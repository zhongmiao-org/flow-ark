# 可选内置浏览器

2026-09-18：0.1.6 的独立网页窗口已通过复杂表单与安装验证，但实际显示入口仍有会话退出问题。用户进一步明确：所有测试使用内置浏览器，先不测试 BOSS；网页必须通过右上角按钮显示在主窗口右侧面板。0.1.7 已实现以下面板方案，验收证据见 [开发预览验收](acceptance.md)。

## 模式与隔离

本机 Chrome/Firefox/Safari 保持原驱动和绑定，当前不执行兼容测试。内置模式仍使用固定 ID `embedded`，但由主窗口持有独立 `WebContentsView`，网站运行在隔离 Renderer 中。宿主经受控系统能力接口管理租约；通用流程和 Worker 不接触 Electron 对象。原实验性 Playwright Electron 子应用移除，避免另开网页窗口和单独应用的生命周期问题。

自动化使用该网页 WebContents 的 `debugger` 传输和固定 BrowserDriver 命令，不开放网络调试端口、不控制工作台页面。定位与表单逻辑放在浏览器适配器，不进入 Main 的业务编排。后台禁用页面节流；窗口隐藏与恢复不销毁页面。新页面留在受控面板中，不能弹出外部浏览器。

远程页启用 sandbox、contextIsolation、webSecurity，禁用 Node、webview，且无 preload；不给网站提供工作台 IPC。专用 Profile 保存登录态，不复制用户日常浏览器资料。网页导航只允许 HTTP(S)，阻止本地文件、应用协议及外部程序唤起；新窗口仍用同一受控安全配置。自动下载必须有当前下载命令，下载文件归对应 Run。

## PC 网页宽度

2026-09-20 用户要求内置浏览器按 1080p 标准宽度显示。网页布局以 1920 CSS 像素为目标宽度，与工作台右侧面板的物理宽度分离；使用 Electron 原生页面缩放，缩放因子为面板宽度 / 1920，由 Chromium 统一处理排版、绘制和输入，不伪装移动设备、不修改网站 CSS。允许 Chromium 整数像素换算的 1 像素误差。面板变窄只改变显示比例，页面高度随面板可视区域换算，以利用纵向空间。原生页面缩放下限为 25%，网页面板内容区至少保留 480 物理逻辑像素，小窗口相应收紧参数栏。该设置降低响应式窄屏布局的影响，不代表所有 PC 网站均已验证兼容。

原型实测发现设备模拟在跨进程 iframe 中产生输入坐标差异，且在新文档导航后恢复原生宽度；最终采用原生页面缩放，复用已验证的拾取坐标转换。页面缩放按来源保存，因此新文档加载后重设；尺寸不变时不重复更新。

网页初建、导航、收起/恢复和后台新建都应采用同一桌面宽度。缩放、面板位置及原生点击坐标必须正确换算，覆盖普通控件、嵌套跨源 iframe 和拾取拦截；显示变化不刷新网页、不改变租约、已填内容或执行状态。截图继续记录实际网页视口，不承诺页面总高度或物理 1920×1080 PNG。界面标明“桌面宽度 1920”，不要把面板物理宽度显示成网站布局宽度。

验证以实际 `innerWidth`、媒体查询和布局结果为准：不同窗口尺寸均保持桌面布局，恢复后会话和表单内容保留，真实原生点击、拾取、自动化、后台截图分别通过。仅本地复杂表单及隔离测试页面；BOSS/智联继续暂停。

## 生命周期

关闭与取消必须核对具体原生网页的销毁，失败/超时不能冒充已回收；未确认时中断运行并阻断新执行，完整重启后核对结果。正常成功保留健康会话，具体身份、回执与恢复规则见[内置网页关闭确认](embedded-cleanup.md)。

窗口最小化或收起时关闭页面后台节流，并隐藏原生网页视图；显示面板由用户主动操作，不因下一步运行抢焦点。页面等待登录或验证码用原有等待人工节点与待办，用户完成后继续。一个会话同一时刻只租给一个 Run；显示/收起不改变租约、重开页面或重放动作。

取消、超时、会话丢失、显式退出销毁对应网页 WebContents 并拒绝未完成命令；外部浏览器仍回收受控进程树。网页失效必须通知宿主并建立待办，不能保留看似可继续的人工等待。应用正常驻留可继续执行，显式退出后不能运行。系统休眠会中断执行条件，不能承诺合盖或休眠仍工作；收到 suspend 事件应停止当前 Run，恢复后核对结果并由用户发起新 Run，不自动重放。不自动启用阻止休眠或开机启动。

macOS 在窗口已最小化时创建新 WebContentsView，可能没有可截图的绘制表面。0.1.7 在后台截图期间将同一网页短暂移入始终隐藏、无 preload 的绘制宿主，完成后移回右侧面板并销毁绘制宿主；不打开另一网站、不改变 URL、租约或执行内容，不显示窗口或抢焦点。原生截图记录当前网页视口，不承诺整页长截图。取消仍销毁网页，不为截图复用已失效的会话。

2026-09-20：截图绘制宿主必须绑定到具体网页视图。取消可以先结束 Run、销毁网页，底层截图 Promise 随后才返回；这段清理时间不能阻止新网页布局或显示。旧截图完成只释放自己的宿主，不移动新截图中的网页；关闭当前网页须从它实际所属的主窗口或截图宿主移除。此项只调整 Main 内部资源归属，不改变截图动作、页面租约或流程协议。

## 本地 IPC 与兼容

公共流程仍用契约 0.7.0 和 browser v1/v2/v3，无节点语义变化。只新增本地 IPC `browser.embedded.enable`（无参）、`browser.embedded.visibility`（visible 布尔）、`browser.embedded.status`（无参）；系统窗口事件使用宿主内部接口。启用只创建本地绑定；打开面板可创建空白网页，不自动运行流程。新增 `browser.embedded.viewport` 仅接收主窗口内的整数矩形，Main 限定边界；`browser.embedded.navigate` 仅接收 HTTP(S) URL，活动执行期间禁止工具栏导航（暂停/等待人工可手动接管）。内部创建、执行、关闭和会话丢失方法不进入 Renderer 白名单。状态只返回已启动、显示状态、当前页面 URL 与标题；不返回 Profile 路径、Cookie、凭据。绑定使用现有浏览器存储，无表结构迁移；0.1.6 专用 Profile 与新面板 Session 分开保留，不在未经验证时拷贝 Cookie 或声明登录继承；旧客户端不认识 embedded 时拒绝执行，不转换成本机浏览器。

## 2026-09-21 设计增量：紧凑窗口的清晰观察

[AI 任务主线](design-ai-task.md) 增加总览、全宽观察和 100% 目标聚焦。总览仅用于找位置；不能以 1920px 页面缩至几百像素后的微小文字作为精确操作验收。全宽/聚焦只改变观察范围、裁剪或平移，不重排执行网页；保持同一会话、1920 CSS px 布局及原始元素坐标。页面滚动、浏览器后退和任务返回分别提供入口，返回任务保留草稿、选择和会话。

这是新增设计要求，当前 `WebContentsView` 缩放实现不因此视为已支持。实现前须验证原生视图裁剪/平移和输入坐标转换；不能直接设为 100% 而悄悄改变页面布局。验收 1040×700 和 1920×1080：真实 14–16px 文字、表格、输入、滚动条、不同位置元素，缩放前后同一目标唯一匹配及真实点击/输入一致。若原生视图无法满足，应先记录技术验证结果并修订方案，不能用静态截图或大标题示例代替验收。

2026-09-21 输入修复候选：自动点击前即时滚动至元素、重新测量目标及每层祖先框架，并检查覆盖物。布局坐标已更新不代表跨进程框架的输入区域已经更新；适配器等待 Chromium 的可信鼠标移动实际命中该元素，再核对位置，最后只发出一次按下/释放。移动和测量仅在按下前、同一命令期限内进行；点击不自动重试。目标在按下时变化、伪造事件、超时和关闭按各自结果停止，业务成功仍须后续回读。此机制不依赖隐藏页面的动画帧，不改变流程协议。代码、原生验证与未完成的裁剪关口见 [Figma 实施记录](design-implementation.md#紧凑观察预研与跨框架输入修复)。

### 2026-09-22 原生观察方案验证结论

解锁环境下的系统截图否定了“父 `View` + 负偏移 `WebContentsView` 即能裁剪”的假设：父边界为 x=80、y=160、880×460，网页仍画到窗口左缘和底部；给父 View 设置 12px 圆角也没有约束该原生网页。不能将前一轮几何/会话数据通过升级为裁剪通过。

`Emulation.setDeviceMetricsOverride` 固定 1920×1080 布局，并以实际 880×460 的 WebContentsView 配合独立 viewport 时，已观察到正确绘制边界、100% 文本及总览切换，页面时间来源和输入保留。但 viewport 的平移没有同步普通画面坐标输入：可见字段对应原始 x=1710，直接点击却产生 x=670 的页面事件。无障碍元素定位后的成功输入及按钮回执不能替代实际画面坐标命中。跨源框架拾取仍停留在 picking，不能确认目标。

因此该候选也尚不进入生产实现。输入转换必须在同一观察状态下覆盖普通鼠标、按下/释放、滚轮、拾取与自动化，核对 Retina 缩放、网页滚动和导航后的坐标；不得修改页面 DOM、重新加载或新增页面副本来绕开同一会话要求。实验性 `before-mouse-event` 转发 CDP 后出现高 CPU 和不响应，未取得事件回流诊断，不作为可用方案。后续原型应先对事件跟踪和转发次数设限、为每个原生调用设超时，并能撤销实验监听器，避免失控后阻塞退出。生产接入仍须通过 1040×700、1920×1080、真实鼠标/键盘、跨源框架、边界外不命中网页、单次副作用和正常关闭的验收。证据与失败清理见 [Figma 实施记录](design-implementation.md#2026-09-22-清晰观察原生裁剪验证未接入产品)。

### 2026-09-22 原生视觉缩放候选与输入边界

后续有界诊断已捕获上述转发的事件回流：原始 x=670 经平移转发为 1710，合成事件再次进入监听器，继续变为 2750、3790，直到第 41 次触发上限并撤销转发。粗粒度的“正在转发则跳过”又会跳过真实释放事件，普通按钮和跨源输入失败；不能采用这两种全局鼠标转发方案。

另一候选固定 1920×1080 布局，以 880/1920 的设备绘制比例配合 Chromium 原生视觉缩放。显式开启 `setVisualZoomLevelLimits(1,5)` 后设置 `pageScaleFactor=1920/880`，在 1040×700 原型中观察到正常边界、原尺寸正文及表格；根页面与跨源框架的实际画面坐标输入成功，两个按钮各有一次服务端回执。普通人工输入由浏览器自身路由，不再全局截获和转发。Electron 默认关闭视觉缩放，参见 [官方 API](https://www.electronjs.org/docs/latest/api/web-contents#contentssetvisualzoomlevellimitsminimumlevel-maximumlevel)。本轮同时改变启用条件与调用时机，尚未单独验证初始化时序要求。

该候选仍未通过拾取和自动化关口：原拾取的 CDP mouseMoved 被额外放大；原型将输入除以视觉缩放因子后，根字段能返回唯一目标，跨源框架仍无法取得高亮目标。真实画面坐标输入成功不代表 CDP 输入正确。后续须统一核对视觉视口偏移、页面滚动、框架坐标及原生覆盖层；不得以根字段通过替代跨源目标身份验证。横向平移仅有 CDP 触摸滚动原型证据，尚无产品观察控件。两尺寸、导航、边界外点击、自动化和完整同会话切换仍须完成，暂不修改生产实现。

### 2026-09-22 文档坐标逐层拾取候选

后续原型以 `DOM.getNodeForLocation` 直接读实际命中节点，不再依赖一次合成移动触发高亮事件。该命令的根输入为文档坐标：包含视觉视口偏移和布局滚动，不能只加 `visualViewport.offsetLeft/offsetTop`。命中跨进程框架边界后，使用该框架所属 CDP session，把父文档点转换为框架内文档点，再查询实际子节点；目标描述、唯一匹配和 framePath 仍由已有拾取校验完成。普通鼠标按下/释放继续由现有拾取拦截消费，不重放给网站。

1040×700 的单层、无 CSS 变换跨源框架已在 100% 和总览两种状态返回同一 `#remote → #frame-input`；真实填写后切换的内容与页面时间来源保持，HTTP 点击回执为零。此为候选成功范围，不代表通用框架支持或生产接入完成。原型不支持变换框架；祖先变换、同进程/嵌套框架、框架内滚动、页面在查询间变化、取消/导航、边界外点击、自动化和 1920×1080 窗口均须继续验证。查询期间不得把已失效的 session 或错误转换得到的背景元素当作原目标。依据和失败对照见 [实施记录](design-implementation.md#2026-09-22-跨源文档坐标拾取原型未接入产品)。

2026-09-22 后续验证：可在现有原生页面 zoomFactor 上叠加视觉缩放，无须设备模拟来取得原尺寸文字。保持原生 zoomFactor=面板宽度/1920，清晰观察的视觉因子为其倒数；同一窗口内启用视觉缩放前后 innerWidth/innerHeight 不变。拾取原始面板点先除原生页面缩放，再除当前 visualViewport.scale，最后加 pageLeft/pageTop 得到根文档点。该组合的两层跨源框架及内层滚动已在 1040×700、1920×1080 取得同一目标；原有合成高亮方式仍失败，直接文档命中仍是候选。不同窗口尺寸下布局高度发生变化，不能据此宣称任意观察区域调整都无重排；生产的观察模式切换仍须满足既定布局保持要求。具体证据见[两尺寸验证](design-implementation.md#2026-09-22-原生缩放叠加与两尺寸嵌套拾取原型)。

### 2026-09-22 拾取直接命中与稳定性实现约定

基于两尺寸和后续变换框架原型，正式拾取采用只读文档命中，停止依赖合成鼠标移动产生高亮回执。保留原有原生按下/释放拦截，不向网站重放拾取点击。悬停预览与结果描述继续使用现有能力，不改变本地 IPC、公开流程或持久化格式。

- 原始面板点按页面 zoomFactor、视觉比例及 pageLeft/pageTop 转为根文档点；拒绝非有限值及可视内容范围外坐标。
- 浏览器在同进程框架内直接命中真实节点。遇跨进程框架时，以 DOM.getBoxModel 的内容四边形和所属 session 的视口信息计算子文档点，保留边框、页面/框架滚动及 CSS 变换；使用可逆投影，退化或无法确定的边界明确失败，不能用外接矩形代替。限制至现有最大 8 层框架路径。
- 查询绑定当前拾取状态、文档 frame/loader 身份、session 映射和观察几何。结果返回前再次核对节点和经过的框架边界；页面、滚动、缩放、框架或目标在查询间改变时要求重新选择，不将新背景节点当作原目标。有限命中期限内完成只读核对，失败不重放点击。
- 选择器唯一校验须对应原 backendNodeId 和所属 session；同选择器的新节点不能替代原点击节点。拾取结果校验不主动滚动网页，执行命令和显式定位仍保留各自滚动行为。
- 取消、导航和新拾取废弃旧查询；未完成的只读 CDP 返回不得修改新状态或关闭新预览。取消不等待无限期传输，旧异步拒绝应被消费。真实释放仍由原按下拦截配对，后续普通点击不能被误吞。

实现验收须包括旋转/缩放及同进程框架、两层跨源和内层滚动、两尺寸、遮挡和边界、目标/框架变化、取消后的迟到结果、普通点击恢复及原有拾取回归。透视变换与退化几何须分别取证，不能从数学函数通过直接推断浏览器已通过。此约定允许开始代码实施，尚不构成产品观察模式或 U11 完成。

### 2026-10-04 原字号观察的键盘平移约定

实际客户端确认原字号切换、输入及纵向滚动可用，但横向滚轮没有移动视觉视口；放宽视觉缩放范围也未解决。本条为画板115/117已有“可平移”要求接通明确的键盘入口，不把横向滚轮或目标聚焦算作已完成。

- macOS 原字号网页获得焦点时，Option + Command + 方向键向对应方向查看一段。只消费该组合，保留普通方向键及文字编辑；按住键不积压平移。界面说明实际入口，不再声称横向滚轮已可用。
- Main 根据原生键盘事件发送内部 `browser.embedded.pan`，参数为严格对象 `{ resourceId, documentRevision, direction }`，方向只允许 `left/right/up/down`。不在 Renderer preload 开放此方法，不允许网页脚本请求。资源及文档代次取自按键发生时；宿主沿用观察模式人工准入，Main 再检查身份、显示、加载、原字号和操作占用。准入期间换页、关闭或调整模式则废弃旧请求。
- 平移复用同一网页，以一次有界原生触摸滚动移动观察区域，不合成点击、不导航、不改写 DOM、不改变缩放比例、不重试。开始前取消旧拾取，清除已确认目标；执行器与新的拾取等待这次观察变化完成。完成后重新读取原生比例，失败通过既有观察错误反馈，显式重选模式恢复。尺寸和模式变化仍按观察代次处理，旧回执不能确认新状态。
- 该入口先提供可人工核对的局部移动；不承诺自定义网页手势、嵌套滚动容器和所有网站已兼容。验收须记录方向、输入保留、页面身份、点击回执和正常退出；在原生证据具备前保持部分实现。

客户端本地提交 `be010ab` 已采用本约定。1440×960 的四向移动和1040×700的向右/下移动已在实际客户端人工核对，输入、同页身份及单次点击回执保留。准入拒绝通过既有观察错误字段反馈，但不污染内部比例故障状态或中断当前执行；实际手势失败仍要求显式恢复查看模式。证据及未覆盖范围见[实施记录](design-implementation.md#2026-10-04-原字号键盘平移与实际客户端核对)，完整目标聚焦和横向滚轮仍未验收。

### 2026-10-04 真实候选的聚焦与确认约定

画板117的聚焦必须接收一次实际拾取的候选，不能从网页标题推导元素。首先接通已有元素拾取入口；任务初次选择对象当前仍仅保存整页身份，其元素上下文须后续独立接入，不能因此宣布117整板完成。

- 本地白名单 `browser.embedded.pick.focus` 使用严格参数 `{ requestId, action: "capture" | "show" | "confirm" }`，沿用人工拾取准入。返回 `{ requestId, target, page: { title, url }, percentage? }`；target沿用现有ElementTarget，不包含网页表单值、DOM内容、Cookie或凭据。
- `capture` 在扩大观察区域前复核真实候选，Main只在内存保存当前资源、文档、选择器、框架路径及原生节点身份。节点身份不返回Renderer、不持久化。相同选择器和文字的新节点不能代替原节点。
- `show` 在扩大后的原生查看区域中使用同一WebContents、1920 CSS布局和100%视觉比例，将已保存的真实目标滚动到可见区域，再复核身份和唯一性；不导航、复制页面、改写DOM或触发目标点击。观察尺寸改变可重新定位此候选，所有迟到回执仍须对应当前候选与页面代次。
- `confirm` 重新核对同一原生节点、页面和目标描述，成功后由原拾取入口应用到当前步骤；失败不得应用。聚焦不提前修改草稿、执行动作或增加授权。原拾取组件卸载、换步骤、取消或开始新拾取时清除聚焦引用，仍使用现有按requestId取消接口。普通缩放取消一般拾取的规则保留；已捕获的聚焦引用独立存活，确认仍重新复核。
- UI使用117的返回总览、确认这个目标、返回目标选择和真实目标摘要。总览与聚焦复用同一网页；返回保留原步骤的未保存编辑及网页输入，并恢复来源焦点。请求中、页面变化、目标不唯一、加载失败均明确反馈；没有真实候选时不展示可确认的聚焦页。
- 本阶段不新增或运行单元测试；按实际原生入口、真实目标、页面替换、往返和单次点击取证，独立记录设计差异与尚未覆盖范围。
