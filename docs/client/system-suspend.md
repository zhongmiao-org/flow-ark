# 系统挂起时撤销旧请求与停止资源

2026-09-20。0.1.33 已实现以下挂起语义，修复挂起前异步准入在恢复后继续创建 Run，以及写入休眠事件失败导致实际取消被跳过的路径；客户端 PR #31 已经 CI 自动合并。175 项单元、71 项宿主测试及 DMG 候选的 system-suspend、run-rerun、embedded、install 四组验证通过，实际结果归[验收记录](acceptance.md)。候选挂起使用 `powerMonitor.emit` 事件夹具，不等于真实硬件睡眠/唤醒验收。日常安装仍为 0.1.28，Mac 仍锁定，等待此前解锁确认；P1 未完成。

## 准入撤销

宿主用内存生命周期代次标记开始接收一次执行请求时的状态。收到 system.suspend 时先设置挂起并改变代次；恢复只开放新的请求，不能让旧代次恢复有效。代次不写入公共流程、计划或数据库。

手动运行、调试、计划触发和关联重跑的确认均须在请求开始时捕获代次，排队等待准入、异步预检或依赖准备之后再次核对。若中间发生挂起，即使恢复已经完成，也应拒绝该请求，不创建 Run、不可变版本、快照或外发副作用。不能在离开等待队列后才捕获代次。已开始的静态准备允许安全收尾，其临时资源沿既有 finally 回收；不执行用户脚本。

已经持久化的重跑确认继续按既有 requestId 返回原记录，不产生新准入；撤销规则不能把重复确认变成第二次执行。

计划的既有触发去重、revision 复验和未来 nextAt 计算保留。被挂起撤销的触发记录明确跳过原因，不重新使用旧触发时刻；恢复后的下一次正常未来触发可运行。新的人工作业可按当前条件重新请求，不自动重发被拒绝的确认。

一次 tick 在异步准入后也要核对其起始代次，不继续处理挂起前捕获的其余到期计划列表。恢复已计算的新 nextAt 不能被旧列表覆盖或补跑。

## 停止与持久化

挂起先关闭准入，并根据实际活动资源所有者发起停止，不依赖能否读出 Run 或成功写入 system-suspend/CANCELLING。事件、队列状态和待办写入各自收集错误；一条失败不能跳过其他资源的停止。

停止继续使用既有协作取消、Worker 超时回收、脚本监护和内置网页确认关闭，不增加另一套回收逻辑。系统通知失败不影响宿主已完成的停止。写入失败时保留 Store.fault 与最后成功保存的历史，绝不把未保存的 CANCELLED 当作实际记录；已有运行观察只表示宿主持有情况。恢复不能清除存储故障、回收未知阻断或旧准入撤销。

健康存储下保留 system-suspend 事件和人工核对提醒。写入失败后仍需确认实际 Worker/脚本/网页停止；未知按现有阻断规则保留。正常重开仅按原恢复规则中断未完成历史，不重放。Main 仍串行转交系统事件，不开放 Renderer 调用 system.suspend/system.resume。

## 兼容和验收

仅调整宿主生命周期；公共契约 0.7.0、SQLite v2、流程、计划与 Run 字段不变，无数据迁移。旧快照和计划固定内容继续可读。

- 真实宿主延迟手动/调试与计划准入，挂起后恢复再释放预检，核对旧请求拒绝、无 Run/快照/业务回执；同一准入队列中尚未开始的旧请求同样拒绝。
- 关联重跑确认在异步准备期间挂起，恢复后拒绝旧确认且不创建派生 Run；新请求的明确确认可正常执行，原记录不变。
- 真实 Worker 与隔离 SQLite 写失败下挂起，核对实际资源退出、后续队列零副作用、存储故障可见、旧历史保留与重开不重放。仅注入 SQLite 连接写限制，不锁定用户 Keychain 或填满磁盘。
- 内置复杂表单保持 1920 CSS 像素；健康挂起/恢复、最小化/托盘正常运行、候选包与日常安装分别留证。调用系统事件处理接口属于事件夹具，不宣称已完成合盖、睡眠或唤醒实机测试。
