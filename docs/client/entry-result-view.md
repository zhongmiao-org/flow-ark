## 现状与目标

已安装候选版将通用步骤结果与上下文按字段展示，并默认折叠原始结构。它尚未提供独立的模板入口整体结果读取。步骤成功、Run 终态、入口保存的值及真实业务结果须分别核对，不能用最后一个步骤或原始 JSON 要求普通用户自行推断结论。

源码核对基于客户端 `c09a0569c48690c08b723df43c886b56b76da8f3` 主线相关路径及现有候选改动：`src/templates/service.ts` 把 SDK 结果存入 template-result，`src/host/author-sdk.ts` 保存 author-sdk-result，而 run.detail 尚无该结果投影。正式完成路径的 `get(...) ?? output` 会把已保存 null 当作缺失；当时仅记录；当前#320已改为undefined判定并修正，本批不重复修改。历史读取不能直接套用依赖当前实例/草稿的执行上下文，也不能降低实际执行准入。

UI 目标是在运行详情显示只读入口结论、固定来源和状态；步骤结果继续独立保留。重新读取只刷新视图，不创建 Run、调用模型、重试业务或授予权限。失败运行即使保存结果也只能表示“已保存”，不可显示为业务成功。普通入口及制作副本分别标识，不混用来源。
