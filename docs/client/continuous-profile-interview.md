## 持续使用

- 个人蒸馏是可持续维护的独立流程，没有终身访谈轮数上限。可以先少量访谈、暂停、稍后补充或重新导入更新资料，不要求一次答完，也不反复询问已有明确答案。
- 对话中可以提问、探索、纠正或提供示例；聊天内容不自动成为本人事实。用户可随时要求整理当前结果，不需达到预设题数。确认当前结果后仍有“继续补充”入口，旧确认会话、证据和 Skill 版本保持可核对。
- 不把20改成999替代长历史设计。采用持久历史与有界读取/发送，原会话ID、消息ID、请求身份、顺序和已确认来源保留；需要新段落或修订时明确关联同一持续档案，不伪装改写旧确认内容。分页、分段及恢复格式须先定义通用契约，再实施。
- 所有历史仍可查看。每轮准确展示实际发送的材料、固定 Skill/事实、对话区间及排除内容；不能一面只发送近期消息，一面宣称“完整历史已发送”。超出上下文时明确选择范围或停下，不静默删史、忘掉规则或另收费总结。摘要必须有来源和待核对状态。
- 保留单请求超时、输出/字节、并发和资源保护，用户可选择预算；这些与终身轮数上限分别说明。请求、重试、整理和试聊均使用本人绑定的 Key；打开历史、切换版本和本地保存不调用模型，不自动循环续费，未知用量保留未知。
- onmessage按会话/段落/轮次/尝试身份与序号归并；输入、历史阅读位置、取消/失败部分内容和最后连续位置持久保留。重启只恢复展示，未完成请求显式重试；迟到事件不得覆盖新输入、确认或版本。

## 确认、写出与告知

1. 补充先保存为本机对话。用户明确整理时才生成待确认差异，显示采用的会话/资料/旧版、逐项新增/修改/删除、冲突/待确认项和影响；可继续补充或放弃本次建议。
2. 保存草稿、试聊与发布分别操作。确认本轮会话不等于确认本人事实或发布 Skill；对话中“暂时这样”“先停”不能自行当作最终确认。本人可跳过未确定项，生成结果须保留这些缺口。
3. 最终确认绑定当前草稿修订、来源、父版本、目录及差异。继续编辑、来新消息、源资料变化、并发发布或外部手改后重新核对；过期回执不发布新内容。无实际差异时说明无需新版本，不能虚报更新或无故调用模型。
4. 使用现有 Skill 并存文件和登记机制生成新版本，旧版与手工内容保留。先记录操作身份，写出和读回核对后登记；文件系统与数据库不是同一笔事务。失败保留草稿，结果未知只核对原操作，不自动重写/重试。工作区默认仍为用户所选资料仓库，可显式另选，不夹带私人路径至公开包。
5. 只有实际写出并登记成功才显示“Skill 已更新”，列出版本、保存位置、主要变化和仍待确认项。保留可重开的应用内结果/待办；系统通知失败不丢结果。通知需去重，不把“草稿生成”“确认请求已接收”报成更新成功。
6. BOSS模板继续引用原确认版本。展示哪些已知本机流程/实例仍使用旧版；用户显式选择采用新版，核对其所需资源/规则后只影响后续Run。已运行快照不变，未发送旧草稿/确认需按实际版本变化失效和重做。不得声称能枚举外部副本或已导出的引用。
7. 可查看旧版或以旧版为内容创建新的恢复版本，保留版本链；不原地改写历史、不删除活动/历史引用。重新绑定/重新确认与撤销已发生的外发分别说明，切换Skill不能撤销已发送消息。
