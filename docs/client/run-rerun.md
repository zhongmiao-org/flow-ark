# 人工核对后重新运行

2026-09-20：补齐架构 5.2 的原运行关联。此功能属于 P1 本地历史与运行控制，具体完成状态见[验收](acceptance.md)。它创建新的手动 Run，从首个节点开始；不恢复原 Worker、步骤中间状态或原输出，不修改原 Run、事件、产物或外发去重记录。

## 选择与核对

运行详情仅对 SUCCEEDED、FAILED、CANCELLED、INTERRUPTED 且资源已回收的 Run 提供入口；正在退出、休眠、存储故障或仍有相关能力调用时不能确认。用户先选择以下之一，再预览并确认：

- 原执行快照（默认）：使用原 Run 保存的流程、参数、本地绑定和已固定脚本。明确显示原版本，不把当前草稿或重编译的第三方依赖冒充原内容。
- 当前已保存流程：显式使用原 flowId 对应的当前保存内容、参数和绑定，重新预检并固定新版本。编辑器尚未保存的文本不在此范围内。

两种模式都可显式选择逐步调试（默认关闭）。预览显示原 Run、来源模式、采用的流程名称/版本、步骤数量、参数名、目录绑定名、凭据引用名和浏览器标识；不返回密钥或本地绑定路径。提示从头运行可能再次产生文件覆盖、网页提交等副作用，用户勾选“已核对原运行的输出与外部结果，确认从头执行”后才可提交。已有结果未知的招聘动作仍由原去重与动作权限规则阻止重放，确认重跑不等于确认这些动作成功或允许再次外发。

缺原快照、固定脚本丢失/摘要不符或已保存流程不存在时明确报错，不静默改用另一来源。原快照模式必须把原 Run.versionId 传入预检：旧快照没有固定第三方依赖清单时拒绝重跑，提示核对当前已保存流程；没有第三方依赖的旧固定脚本文本可按既有兼容方式准备。预览可以生成内部编译缓存，但不生成版本记录、Run、事件、计划或外部业务动作。

## 当前授权和冲突

原快照不是永久授权。原浏览器、目录、凭据和脚本包绑定必须仍受当前保存流程授权且没有被替换；原招聘策略及模板配置必须与当前规范化配置一致。通用 `flow-parameters-v1` 的 values 属于运行参数，比较授权时不要求与当前值一致，原快照继续使用原参数；其 adapter/schema 仍须一致。检查使用当前保存内容和系统资源，不能从历史快照恢复已移除的凭据授权或更宽的招聘权限。允许当前流程新增无关绑定，但不能用它们扩大原执行内容；绑定不一致时提示重新核对并显式选择当前已保存流程。凭据引用仍读取受保护存储中的当前值，绝不把旧凭据值放入快照或响应。

预览摘要固定原 Run/快照、当前保存流程及授权、本机浏览器绑定、选择的内容、调试开关和已准备脚本摘要。确认在异步预检前后重验这些内容；期间保存流程、改授权、更换浏览器或变更脚本均使旧预览失效。进入执行槽时再次检查重跑的当前授权和固定资源；运行开始后仍执行不可变快照，招聘继续使用既有逐动作当前策略检查。原来源 Run 的相关资源未完全释放时不能启动重跑。

## 本地接口与持久化

新增 Renderer/Main 白名单（沿用现有来源帧和 2 MiB 输入限制，全部对象拒绝未知字段）：

- `run.rerun.preview`：`{id, mode, debug?}`。id 为原 Run ID（1～100 字符），mode 为 `snapshot` 或 `saved`，debug 默认 false。返回内容摘要 token（64 位小写十六进制）、原 Run 概览、选择后的流程概览和提示；只有完成预检才生成可确认预览。
- `run.rerun.confirm`：`{id, mode, debug?, token, requestId, reviewed:true}`。requestId 为 UI 为本次明确确认生成的 UUID；返回新 Run。确认期间禁止重复界面点击，丢失回复时可用相同参数及 requestId 重试。
- `run.detail` 增加重跑可用状态、不可用原因、直接来源及直接派生 Run 概览。关系从完整本地持久化历史获得，不依赖 bootstrap 最近 200 条或当前历史页。

新 Run.source 仍为 manual，增加可选本地关联 `rerun:{runId,mode,reviewedAt}`，用于显示“手动 · 重新运行”、来源链接和直接派生记录。旧记录缺此字段仍可读取。`requestId` 与确认内容摘要、产生的 Run ID 一同保存；相同 requestId 和载荷再次确认返回同一 Run，不产生第二次执行，改变载荷则拒绝。幂等记录、必要的新版本、不可变快照、新 Run、关联和初始 QUEUED 事件在同一同步事务内提交。异步准入沿用 FIFO 串行队列，预检失败不留半个 Run；重启后幂等信息仍在。

关联与确认记录只存入现有加密本地 documents，不增加 SQLite 表结构，不更改公共 RunRequest/事件 wire 契约 0.7.0。它们不属于流程或模板格式，不写入导出包、配置、计划或平台上报。Renderer、Preload 与 Host 随完整客户端同步升级；应用固定实际合并的治理基线，不读取父目录。

预览取消、切换来源/调试方式和退出详情都清除旧预览和勾选，迟到回复不能恢复过期 UI。确认已提交后离开详情不撤销已经创建的新 Run；迟到结果不得强行重新打开详情。来源和派生链接也使用组件生命周期及请求序号防护，保持运行历史页筛选及页位置。

## 验证

- 实际 Worker 分别运行原快照与修改后已保存流程，核对不同参数/步骤结果、新旧 Run 关联、原记录不变、逐步调试和重开。
- 预览/取消零 Run 与零业务副作用；无效载荷/未核对、活动或未清理来源、缺快照、旧依赖、固定脚本损坏和撤销授权拒绝。确认前、异步预检期间、排队等待期间的授权或内容变化按上述规则处理。
- 同一请求串行/并发/丢失回复/重启后重试只创建一次；不同载荷复用请求拒绝，失败事务无半成品。
- 真实界面来源切换、取消、明确核对、双击、迟到预览/确认/关联导航不覆盖新页面；旧历史、跨页关系、无关 Run 和导出包边界。
- 隔离内置浏览器与本地复杂表单使用 1920 CSS 像素宽度，核对实际字段、调试和回执/提交次数。源码、本地检查、CI、DMG、安装路径与升级保留分别留证；不测试招聘、真实 AI 或外部浏览器。
