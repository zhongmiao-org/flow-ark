## 问题与交付路径

真实20项Run在第16项保存最新状态结果时触发1000项/8MiB限制；已发送消息保持。较小的5项批次可以接续现场，但不能保证所有账本规模可运行，更不是“循环直到网站上限”的产品闭环。结果页分页只减少渲染，宿主扫描/整列表负载及执行预算仍须另行解决。

选择在本地宿主监督多个有限Run的通用连续会话，不让Worker常驻等待，也不增加BOSS专属节点。每批仍运行固定入口完整流程和现有准入、动作去重、发送后核对及取消边界。流程、提示词和网站终点由模板作者可视化维护；使用者导入公开标准ZIP，配置自己的资料、Key及资源后，在启动前明确选择“连续运行有限批次”。默认仍单次运行。个人资料整理也可复用相同机制；已有访谈对话记录与Skill确认边界不改变。

## 作者的普通UI

在既有入口的结果结构与结果绑定区域增加“连续批次”设置，默认关闭。通过字段选择器选择此入口固定结果Schema中的批次决策、进度标记和状态说明，均显示字段中文标题/路径，不要求JSON。决策是有限枚举：继续下一批、目标已完成、需要查看；进度是有界普通文本，状态说明是有界普通文本。作者从现有可视化条件/脚本结果生成这些值，不把不同含义的布尔值自动猜成终点。

字段路径、Schema类型/枚举、入口来源及结果绑定一并校验、CAS保存、带回/导出并普通独立复导。删除/改型引用字段时明确显示受影响设置，不能保留悬空路径。公开包只携带逻辑定义与普通默认限制，不携带会话、运行列表、个人输入、Key、本机路径内容或授权。制作副本试运行与正式实例须分别固定准确来源、状态隔离和只读结果，不能拿另一实例代验。

BOSS入口仅在确定实际网站日限额提示后输出目标已完成；本机已用150、当前批检查数、队列为空、所有岗位不符、无新增或普通Run成功均不能生成该决策。未知新动作、无进展或需要本人判断时保留原因及待办；旧已隔离未知岗位继续按模板规则排除，不能因自动续批重放。

## 启动、查看和停止

使用者在既有运行前检查页切换单次/连续模式，选择最多批数、最长时长和批间等待，均为有限正值并显式预览实际边界、费用继续由自有Key承担、固定流程/参数/配置版本及资源/动作范围。逐步调试、已有定时计划、另一个连续会话不能静默转为连续模式。未声明或无效结果映射时连续入口不可开始，保留单次检查路径。

核对开始只创建一个本地会话和第一批Run；同一requestId幂等，回包丢失只读取原请求。前一批SUCCEEDED、所有收尾确认、完整结果和来源校验通过、无该批未决副作用，且决策明确继续/进度确有变化、限制未到，才安排下一批。每批结束释放既有单运行槽，等待期间不占Worker和浏览器租约，遵守其他队列任务。不能把创建Run当其执行/网站提交成功。

运行详情显示人可读会话名称、第几批、当前Run、已结束/失败/中断批次、下一次开始时间、目标完成依据、停止原因和历史来源；技术ID收在高级诊断。主操作“本批结束后停止”先持久取消下一批安排，本批仍按既有边界完成；“立即取消当前运行”调用原取消并明确已提交不撤销。不用一个含混“暂停”混淆这两种动作。

失败、取消、收尾未知、结果缺失/类型错误/来源不符、进度重复、配置或资源/授权变化、到达批数/时长限制、休眠/退出均停止安排后续，完整保留当前原Run及已提交结果。重开显示中断及原会话记录，不自动恢复/重复创建批次；用户经现有核对明确开始新的会话。批数/时长到达只表示本地停止，不能标目标完成。关闭结果阅读或切页只停止界面采纳，不代替停止会话。

## 宿主和契约必须落实的边界

- 先正式定义语言无关的入口声明、启动预览/确认/幂等读取、会话记录/游标、停止请求/回执和批次结果关联，再由客户端独立固定版本；当前没有这些新IPC或字段。
- 会话固定完整编译版本/包摘要、入口、输入、配置修订、Skill/资料/Key引用和原授权范围。状态账本修订允许随实际事务推进。草稿变更不改变已运行批次；是否允许新批必须对当前源/配置/绑定/授权作明确复核，变更时停止并重新核对。
- 现有RunReview授权同时包含网页文档/资源的瞬时观察，不能直接沿用到下一批，也不能删除该检查假装已授权。连续会话须明确区分稳定授权范围和每批重新捕获的临时网页观察，使用单独的会话授权证据；普通单次/选区/工具确认规则保持，不能借连续模式扩权或关闭审批。
- 新Run与上批、会话及唯一序号在同一事务登记，事务提交前不dispatch；同一会话序号至多一个Run。未知启动结果读取原记录，不自动用新ID重试。tick/admission、取消、退出/休眠和异步预检竞争必须以同一会话代次/停止标记复核，不允许停止后迟到新建。
- 结果只取本批完整、按固定Schema校验且来源证明一致的入口原值；脱敏显示投影、历史末步或模型文本不能替代控制值。控制证明仅保存所需有限字段和摘要，原结果及全部历史不裁剪、不覆盖。前一批最终秘密集合处理完成后才发布可读会话状态。
- 任何新批都使用原准入、单槽、不可变快照、当前权限和幂等账本；不直接启动Worker、绕过Main/Host或由脚本任意创建Run。制作副本、正式实例、其他会话和独立工作区明确隔离。

## 容量必须独立闭环

连续会话不自动解决单批容量。实施前按真实结构化结果的元数据核对是条数还是序列化字节触发，并找出重复值/完整账本占用；不打印或修改个人库正文。保留完整原值、校验和可追溯摘要，不能截断、抬高上限或丢弃旧值假装修好。

需要提供通用预算计量与可读停止原因，并在可能发生新外部动作前保证后续回执/完整结果有可持久化空间；不能在网页已经提交后才因可预知的结果预算失败。若采用内容寻址复用/分块或新的限额，先定义字节/引用语义、完整性校验、存储失败与恢复、删除引用保护及普通阅读/导出边界，再采用。无法安全开始下一项时在新动作前结束当前批、保留进度并由会话核对是否可续；当前尚无此能力。
