# 可视化空值结构编辑

2026-10-17，先行设计与通用字段编辑修复。沿既有完整业务 Schema 能力，不新增契约版本，不采用未发布的入口结果读取草案。普通作者在类型菜单选择空值，不再为合法 null-only 结果必经高级 JSON。

## 现状与范围

实际原生调试发现：入口结果允许 `{"type":"null"}`，但 AuthorSchemaEditor 的类型菜单仅包含对象、数组、文本、数值、整数、布尔和任意 JSON。已有 null 结构显示原标识，开启公开默认值又通过表单默认算法生成空文本；使用者表单预览还对完整结果/状态 Schema 强制套用配置子集，导致点击后才报不支持。

共享配置和入口输入仍沿现行 configuration-schema 子集，不增加 null 类型。入口输入根对象要求保持。空值选项仅在入口结果和共享状态的完整 Schema 编辑范围提供，包括嵌套字段；宿主保存校验、包校验及固定 Run 不变。

选择空值沿现有类型切换规则清理不适用的子项/约束/默认值。类型名称为“空值（null）”，说明其与空文本、0、false、缺少字段不同。明确勾选公开默认值后写入真正 null，以只读文案显示，不提供会产生字符串的文本输入；既有不匹配默认值保留并提示，用户可取消默认值或明确“设为空值”。不在打开页面时静默修正数据。

使用者表单预览仅用于共享配置和入口输入；结果/状态的该按钮禁用并说明范围，避免向配置表单校验提交完整业务 Schema。高级 Schema 保持可选、默认收起，不删除调试入口。
