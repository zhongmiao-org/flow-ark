# 运行历史分页与完整状态

## 查询和显示

新增 Renderer 白名单 `run.list`，请求可包含 limit（整数 1～100，默认 50）、cursor（最长 1024 字符）、query（最长 200 字符）、state（现有 RunState）和 source（manual 或 schedule），拒绝未知字段。query 去首尾空白后，对运行名称、运行 ID 和流程 ID 做不区分大小写的字面量包含匹配；其他筛选与它取交集，不接收 SQL 或正则表达式。

响应为 runs、nextCursor（字符串或 null）、totalCount（当前全部运行数）和 newerCount（游标边界之后新增的运行数）。totalCount 不是筛选后的数量。按写入顺序倒序，与相同时间戳和系统时钟变化无关。首次查询固定当前记录边界，后续页不插入新增 Run；“查看最新”重新开始查询。状态以每次请求的当前值为准，游标不是冻结的状态快照，状态变化可能改变筛选结果。

游标携带版本、记录边界、上一页最后记录位置和筛选/页大小摘要；宿主校验结构、整数范围和查询一致性。它只是本地分页位置，不授予额外权限。错误或不匹配须明确提示重新查询，不能静默回到首屏。底层按至多 200 条的块解密扫描，匹配至 limit+1 条后停止，并在块间让出事件循环。筛选最坏仍需扫描全部历史，不宣称建立了大数据全文索引。

历史页面提供名称/ID 搜索、状态和来源筛选、上一页/下一页及查看最新；进入详情再返回保留当前筛选和页位置。详情关闭或切换时，迟到的查询不得重新打开旧详情。清理仍从具体 Run 的详情显式预览确认，分页不触发删除或运行。

## 概览与兼容

bootstrap 保留最近 200 条 runs 供既有调用使用，另返回 runOverview：total、queued、active（运行中/暂停/等待人工/取消中，或 null）与 latest（每个流程最近一条 Run）。概览从完整持久化记录计算；界面顶部活动状态和流程卡片不依赖历史页或最近 200 条窗口。

继续使用加密 documents 存储和 SQLite 既有行位置；UPSERT 更新 Run 不改变顺序。本轮无表结构迁移、明文索引、旧记录重写、运行语义或公共契约 0.7.0 变化。客户端升级须同时包含 Renderer、Preload 与 Host；应用不读取治理目录。先合并本说明，再由客户端固定采用实际治理提交。

- 真实 Worker 等待人工与 205 条队列下，活动状态、队列总数和较早流程最近结果正确。
- 真实 Electron 界面分页、详情返回、筛选切换、迟到请求、较早运行产物查看及清理；最小窗口同时打开 1920 CSS 像素内置表单。
- 只使用隔离数据与本地复杂表单，BOSS/智联和真实 AI 继续后置。构建、真实进程测试、打包依次执行。
