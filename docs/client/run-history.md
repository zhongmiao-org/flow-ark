# 运行历史分页与完整状态

2026-09-20：0.1.22 的界面从 bootstrap 的最近 200 条记录计算历史、活动状态和流程最近结果。真实 Worker 等待人工后再排队 205 次，可复现活动 Run 从该窗口中消失。0.1.23 已实现以下本地增量；具体交付层次与证据见[验收](acceptance.md)。

## 查询和显示

新增 Renderer 白名单 `run.list`，请求可包含 limit（整数 1～100，默认 50）、cursor（最长 1024 字符）、query（最长 200 字符）、state（现有 RunState）和 source（manual 或 schedule），拒绝未知字段。query 去首尾空白后，对运行名称、运行 ID 和流程 ID 做不区分大小写的字面量包含匹配；其他筛选与它取交集，不接收 SQL 或正则表达式。

响应为 runs、nextCursor（字符串或 null）、totalCount（当前全部运行数）和 newerCount（游标边界之后新增的运行数）。totalCount 不是筛选后的数量。按写入顺序倒序，与相同时间戳和系统时钟变化无关。首次查询固定当前记录边界，后续页不插入新增 Run；“查看最新”重新开始查询。状态以每次请求的当前值为准，游标不是冻结的状态快照，状态变化可能改变筛选结果。

游标携带版本、记录边界、上一页最后记录位置和筛选/页大小摘要；宿主校验结构、整数范围和查询一致性。它只是本地分页位置，不授予额外权限。错误或不匹配须明确提示重新查询，不能静默回到首屏。底层按至多 200 条的块解密扫描，匹配至 limit+1 条后停止，并在块间让出事件循环。筛选最坏仍需扫描全部历史，不宣称建立了大数据全文索引。

历史页面提供名称/ID 搜索、状态和来源筛选、上一页/下一页及查看最新；进入详情再返回保留当前筛选和页位置。详情关闭或切换时，迟到的查询不得重新打开旧详情。清理仍从具体 Run 的详情显式预览确认，分页不触发删除或运行。

## 2026-09-21 Figma 筛选与耗时增量

为实现 [运行记录与导航设计](design-navigation.md)，`run.list` 增加可选 `createdFrom`、`createdBefore`（含时区的 ISO 时间，分别含下界、不含上界；两者同时存在时下界必须早于上界），以及精确匹配的 `flowId`（1～200 字符）。时间依据 Run.createdAt；无效历史时间不匹配时间条件。界面的今天、最近 7/30 个日历日按本机日期换算并固定边界，翻页不重新移动范围。

source 扩展为 manual、schedule、debug、rerun：关联重跑优先归 rerun，其次带 debug 标记的运行归 debug，其余按实际 source。这是显示筛选分类，不改变 Run.source 或重跑/调试语义。所有筛选交集与页大小均进入游标摘要，修改任一条件后旧游标不可复用。

响应增加 `matchedCount`（当前游标记录上界以内、按当前状态匹配的总数），原 totalCount 仍表示全部历史，newerCount 仍表示上界之后新增数。界面据 matchedCount 显示实际筛选结果范围，不将全部历史数写成筛选命中数。为统计匹配总数，宿主分块扫描到上界内记录末尾，块间让出事件循环；仅保留当前页和下一条，不缓存全部解密记录。

响应增加 `elapsed`，键为本页 Run ID，值为 `{kind: "live"|"final"|"recorded"|"unknown", milliseconds: number|null}`。沿用[运行观察](run-observation.md)的事件、宿主归属、收尾与故障判定，不用 createdAt/updatedAt 差值冒充执行耗时。只读取本页运行事件；实时数随已有轮询更新，未知时长显示待核对。

此增量仅改变本机 Renderer/Host 请求与响应，不改变公共契约 0.8.0、SQLite、执行快照或计划。先合并此说明，客户端采用实际治理提交。验证时间边界、非法/倒序范围、筛选类别交集、匹配总数、翻页期间新增以及每种筛选改变后的旧游标拒绝。界面须验证筛选页应用/取消/清空与详情/输出返回时的分页、焦点和滚动恢复。

## 概览与兼容

bootstrap 保留最近 200 条 runs 供既有调用使用，另返回 runOverview：total、queued、active（运行中/暂停/等待人工/取消中，或 null）与 latest（每个流程最近一条 Run）。概览从完整持久化记录计算；界面顶部活动状态和流程卡片不依赖历史页或最近 200 条窗口。

继续使用加密 documents 存储和 SQLite 既有行位置；UPSERT 更新 Run 不改变顺序。本轮无表结构迁移、明文索引、旧记录重写、运行语义或公共契约 0.7.0 变化。客户端升级须同时包含 Renderer、Preload 与 Host；应用不读取治理目录。先合并本说明，再由客户端固定采用实际治理提交。
