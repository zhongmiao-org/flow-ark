# 系统凭据存储故障处理

2026-09-16，0.1.5 开发版修复数据密钥读取的错误分类。应用的数据密钥只在读取 `data-key.enc` 本身得到文件不存在错误时创建；系统保护能力检查或解密失败均向上报错并保留原文件。密文损坏不得自动生成新密钥，否则历史数据库仍使用旧密钥，无法正常读取。

修复前 `key()` 捕获整个读取及解密调用的 `ENOENT`，无法区分文件缺失与保护后端错误。进程内注入解密后端 `ENOENT` 后，原实现没有拒绝请求，回归失败；修复将捕获范围限定为文件读取，原测试通过。此证据是明确的故障注入，不声称本机 Keychain 实际产生过该错误。

保留既有系统保护格式、凭据 ID 和数据库密钥；无契约变更或数据迁移。系统保护不可用时没有明文回退。加密失败不覆盖既有密文，解密失败不替换数据密钥；修复后不需要用户重新录入凭据。

## 验证

在客户端执行 `pnpm test:vault`。测试临时构建真实 Vault 源码，使用独立 Electron 进程、临时目录和虚构数据，不修改系统 Keychain 设置，不读取已有用户凭据。启动上限 15 秒、用例和退出总上限 30 秒，超时只回收所属进程树并记录失败。

已经通过：

- 真实系统加密/解密回环，文件不含虚构明文，权限为 0600。
- 系统保护不可用时拒绝读取、替换及首次创建，原密文不变。
- 可用性检查抛错、加密拒绝时不覆盖已有文件。
- 解密后端返回 `ENOENT` 时拒绝请求，已有数据密钥逐字节不变。
- 损坏密文不被重建；还原原密文后仍可读取原密钥。

结果为客户端忽略目录 `test-results/vault.json`。系统不可用及异常路径通过进程内替换 API 响应注入；没有锁定用户 Keychain，也不能将此记录称为实际系统权限拒绝验收。完整应用启动/IPC 另由桌面回归验证。0.1.5 仍受 Chrome 恢复缺口限制，尚未打包安装。
