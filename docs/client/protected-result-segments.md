## 准入、生产与恢复必须一起实现

1. 边界来自固定方案及真实来源：已知完整值准确计量；未知值由封闭输出结构或能力固有上限推导。脚本输出结构须通过普通字段表单维护并在生产返回时完整验证。状态写入优先绑定段前已准备的准确值及预期修订；段内未来变量不能冒充已知值。未知/无界/不支持的结构在外发前拒绝，不裁剪输出或扩大上限。
2. 编译必须覆盖必要的全部分支、有限循环、取消/失败/unknown回执及收尾步骤，拒绝只保护点击节点。语言无关的节点格式、可支持的能力家族、SDK动作守卫、引用/变量作用域和完整输出结构关系尚须在正式G1中固定；可信脚本环境不因此成为安全沙箱。
3. 同一Run的原目录、所有未消费预留及未来保存联合核对。结果数量、唯一单元、图/值深度、遍历工作、每个原值副本、全部索引与最终Run输出均计入。有限Schema的规范JSON字节上界不是完整目录/副本上界，不能直接拿它扣减余额后宣称取得许可。
4. 当前执行器仅逐节点提交完整结果，正常模式的node-end不附整个返回值，最终聚合输出还会包含条件和循环结构。G1/G2必须增加准确、受限的内部完成观察/聚合证明或等价机制，核对已完成前缀和未来有界形状，并独立匹配最终输出；不能采用Worker自报较小尺寸、公开日志预览或仅合计叶结果。脱敏键替换和后到秘密引起的投影变化也须纳入上界或阻止来源变化。
5. 进入前由本地宿主固定Run/节点实例/快照、来源与权限修订，并核对真实剩余空间；登记/持有/消费与原保存事务保持一致。预留不是外发许可。配额不足时不产生新的提交中/unknown操作记录，走有限的“尚未执行”出口并保留真实进度；这条出口及整体输出本身也必须预留，不能因为只差失败说明而落不下记录。
6. 必要的Run整体输出预留不能在段结束后过早释放；它继续保护已发生动作的收尾，后续普通结果不能抢占。只有实际保存、原进程/能力/事务确认回收后，才能释放未消费部分；已保存目录和独立回执不删除。
7. 退出、休眠、取消和重开均不把旧预留恢复成新许可。原操作未知时保留原对象和独立回执，不重试外发。磁盘故障仍按原存储阻断，配额预留不承诺磁盘可用性。
8. 连续批次按明确结果和实际进度接续；空间不足本身不是目标完成。无进展或不能容纳一项时转待办并停止，禁止新Run空转。BOSS仅网站实际150次打招呼提示可输出全天完成；对方回复后的附件、聊天/JD筛选仍分别验收。

## 独立边界核心与后续门槛

先建立[有限规范JSON边界核心](../../contracts/drafts/protected-result-segments/README.md)，以封闭有限Schema推导规范字节、值访问次数和深度，固定证书与原Schema摘要。此核心只回答单个完整值的上界，不是预留、数据Schema验证器、已存原值证明或执行许可；不能由客户端提前采用。

接续增加同目录`completion-bounds.mjs`，按现行执行器的块对象/条件分支/循环数组形状编译完整流程汇总，包含容器键及每层序列化工作、全部分支和有限重复；不以叶结果相加代替根输出。固定整个流程与生产者Schema摘要、拒绝未知/缺失/多余结构和超过10000次的路径；动态循环采用执行器1000项上限，字面数组使用真实长度，不能信任人为小估计。它仍是未发布的静态核心，没有生产完成观察、目录/副本联合预算、原子预留或执行许可；实际返回Schema验证及失败/取消独立回执继续补齐。

完整G1仍须定义受保护节点/编译计划、可信生产者上界、目录/原值/聚合上界、全部消费与释放关系、许可/拒绝线格式、运行事件和普通UI契约；须保留旧快照及公开ZIP的可移植边界。随后准确发布、消费者独立采用、全部来源/故障与取消矩阵、原生可视化制作/标准ZIP独立复导，最后接公共BOSS连续入口和真实网站终点。现阶段不新增或运行单元测试；按需使用格式/语法/声明检查及真实原生运行，分别记录。
