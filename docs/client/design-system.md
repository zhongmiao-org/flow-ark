## 视觉规范

方向为雾白工作区、石墨导航、电光蓝主要操作。禁止逐页新建含义相同的色值。

| 用途 | 值 | CSS 语义名 |
| --- | --- | --- |
| 主要操作 | `#315EF5` | `--fa-action-primary` |
| 悬停主色 | `#244BDC` | `--fa-action-hover` |
| 导航背景 | `#121A2A` | `--fa-bg-nav` |
| 工作区 | `#F6F7FB` | `--fa-bg-canvas` |
| 内容表面 | `#FFFFFF` | `--fa-bg-surface` |
| 正文 | `#172033` | `--fa-text-primary` |
| 辅助文字 | `#637089` | `--fa-text-secondary` |
| 边界 | `#DFE4ED` | `--fa-border-default` |
| 已完成 | `#147D61` | `--fa-status-success` |
| 待处理 | `#946200` | `--fa-status-warning` |
| 失败 | `#B83B48` | `--fa-status-error` |

设计文件包含 55 个变量：18 个原始颜色、19 个语义色、11 个间距和 7 个圆角；原始与语义集合各一个模式。中文为 Noto Sans SC，英文品牌与数字为 Inter。文字样式为 Display、Title、Heading、Body、Label、Caption、Metric、Logo；正文 14/22，标签 13/20，辅助文字 12/18。字体资源的打包、许可和目标机渲染由客户端实施时验证，设计完成不代表应用已经内置字体。

标准操作高度 40 px；控件、卡片、浮层圆角分别为 8、12、16 px。Button、Field、Status 为首批可复用组件，支持主要/次要/危险操作、加载/禁用/焦点、输入错误和运行状态。组件实例中的文案可以覆盖；状态必须保留文字，不能只依赖颜色。键盘焦点采用 2 px 蓝色环、2 px 外偏移；此交互要求须在实际客户端验证。

## 交互与布局约束

- 同一区域只有一个主要操作。画布编辑、流程运行和网页拾取属于不同操作区域。
- 宽窗口打开网页时收起常驻动作库，保留当前步骤和配置；右侧网页沿用 [1920 CSS 像素排版](embedded-browser.md)，不因视觉设计改变执行模式或缩放坐标契约。
- 1040–1439 px 窗口采用压缩导航及互斥的动作库/配置抽屉，避免四列同时挤占；1040×700 的细化画板及真实窗口验收仍需在对应实现前补齐。不得将两张宽窗口稿视为全部尺寸已经验收。
- 流程图仍按 [语义规范](flowchart.md) 展示条件真假分支、汇合、数据与人工节点；普通卡片外观不替代这些语义。
- 模板遵循导入校验、选择入口、绑定资源、创建流程的顺序；导入不运行、不自动安装依赖。业务专属名称、字段、提示词继续来自模板包。
- 活动 Run 与计划绑定固定版本；运行中只展示实际报告的阶段和数量。请求暂停、暂停完成、等待人工与取消完成需按实际状态分别呈现。
- 未确认的外部结果显示“待核对”，不自动重新提交。运行成功、业务成功、产物可用仍分别取证。

## 后续开发方式与证据边界

1. 先采用 Figma 变量、字体和基础组件，再替换导航与内容容器，然后按页面逐项迁移。每个客户端 PR 写明参考节点、状态范围、截图与实际验证。
2. 新页面、新状态或交互调整先补齐对应设计；不要在代码中独立发明第二套配色、间距或同义组件。尚未绘制的设置标签、弹窗、紧凑布局和复杂节点先补稿再实施。
3. Code Connect 尚未配置，Figma 组件与 React 组件之间不是自动同步关系。消费端以本文件节点目录和实际截图核对，完成组件迁移后再建立机器映射。
4. 本次交付是设计文件、页面原型和开发规范。页面中的流程、统计、资源与运行记录均为虚构设计示例，不表示这些模板已发布、服务已连接或业务已通过。
5. 当前客户端代码、安装包与运行逻辑未因这次设计任务而修改；具体实施继续走客户端独立 PR、CI、安装和真实内置浏览器验证。

设计稿支持核心导航和若干主操作的页面跳转；输入、文件选择、拾取及真实运行由后续客户端实现，不把可点击的原型称为完整业务模拟。
