# 工作台流程目录刷新性能

2026-10-30：在正式连续求职会话保持运行时取得 30 秒宿主 V8 CPU profile。约 22.06 秒处于 idle；`bootstrap → Store.list` 累计约 1.82 秒，包含 SQL 全量读取和受保护正文解密。该采样只能定位这条刷新路径，不能把所有 CPU 峰值归给它。只读统计显示当前 262 份流程记录的加密正文合计约 22.14 MB；运行状态刷新仍会重新读取完整流程列表。

拟实施范围是通用工作台的进程内只读流程目录复用，不改变流程、运行或模板契约，不增加磁盘缓存或业务接口，不缓存凭据。已有 UI、Figma 和保存行为保持。

- 只复用完整 `flow` 目录投影；不把旧的运行、待办、权限或资源预检结果作为本次来源。
- Store 按文档种类记录写入/移除失效代数，同时核对 SQLite 外部连接的数据版本；普通运行事件不应令未变化的流程目录反复解密。
- 事务内不读取或填充复用项，避免未提交内容在回滚后泄露到正常读取；失败写入允许保守失效。
- 完整目录 JSON 超过 32 MiB 时不复用；不截断目录。仅保留一份目录，并向调用方返回独立副本，调用方修改不能污染后续读取。
- 流程保存、删除、实例入口输入等实际 `flow` 写入后须看到最新内容；外部数据库提交使旧复用项失效。

先执行类型、构建、格式检查，不新增或运行单元测试。安装后通过普通 UI 核对流程修改/移除后的目录刷新及重开，并在实际业务负载下重新采样。该优化、CPU 峰值收口、长结果保存和连续 20 次招呼分别验收；当前仅为观察与实现约束，尚无消费者及修复后证据。
