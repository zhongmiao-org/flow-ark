## 实际来源与问题

在同一真实独立JD上，经普通字段验证和“查看拒绝位置”复现两个直属SPAN的hidden-descendant，36元素/64节点。通过客户端新建独立只读诊断草稿、编排单脚本、原包导出/复导/正式实例，仅绑定现有浏览器，无AI或写入动作。2秒真实运行读到直属SPAN数2，两者文字长度0、内联style/hidden/aria-hidden为空、类名为站点随机值。未读取或保存正文内容，只记录属性及长度；这仍不能证明节点没有子节点、伪元素或影子内容。

本机诊断包`local-jd-style-diagnostic` 0.1.0/作者修订6，9文件，原始ZIP SHA256为`60dd8c0c3e5ae4b344249589b67bd5ea1b7ac89425e037079365dd6c943760c4`，内容摘要`3dd9b9ec9c665466189a403b817f880511f60d25f0e5cee0107f166ec494ccad`。只作为真实只读开发证据，不公开为招聘业务模板，不计打招呼成功。全部制作和运行由客户端UI完成；没有手改业务JSON、ZIP、数据库或伪造来源。

旧规则将任何隐藏后代都拒绝，有文字长度为0的节点也会挡住整个JD。接续不忽略全部隐藏内容，只新增显式采用、可恢复原规则的严格空叶子分支。站点选择器和求职资格继续归独立模板，客户端不识别BOSS、随机类名、城市、职位或个人事实。

## 同步DOM排除条件

新规则只在原扫描已判定后代隐藏时，逐项验证以下全部条件：

1. 仅目标后代，不能排除采集目标或祖先；标准HTML命名空间、非自定义元素，不属于原检查器的替换/嵌入内容类别。
2. `childNodes.length`严格为0，连空白文字或注释子节点也不忽略；没有可访问影子树。
3. 同次计算样式确认为`display:none`或数值`opacity=0`，保证整个节点不绘制；单纯visibility/content-visibility隐藏、display:contents、未知或读取失败不满足条件。不声称可证明不存在闭合影子树，但上述整节点抑制条件仍必须成立。
4. 同次`::before`和`::after`的content只能为none、normal或空字符串字面量；空格、图片、计数器、attr和其他生成内容均拒绝。不得读取生成内容作为正文或删除页面样式。
5. 没有运行中或pending动画；相关API、样式或伪元素不可核验时继续拒绝。整个判断在原同步扫描内完成，不等待、不跨DOM调用拼接、不从站点类名推断。

只有满足全部条件的叶子不再产生hidden-descendant；计入同一扫描预算及`excludedHiddenEmptyLeaves`，不把排除数量当“已读取隐藏正文”。不符合的隐藏节点、非空正文、伪元素、裁切、不支持布局和外部覆盖边界保持原行为；不会返回剩余正文片段冒充完整读取。
