# 招聘模板岗位筛选

P1 范围依据 [招聘交互](../p1-recruiting.md)，协议见 [0.5.0](../../contracts/v0.5.0/README.md)。本功能扩展平台无关策略和模板数据，不新增生产网页选择器，不代表两站已完成真实验证。

## 模板和兼容

两个内置招聘模板发布 1.2.0 配置定义，并声明 recruiting-job-filter-v1 能力以使旧客户端明确拒绝导入；将城市、公司范围、排除职位词、工作方式及人民币月薪放入包内 jobFilter 表单，Renderer 继续按通用 Schema 渲染独立实例配置。通用右侧面板不增加招聘栏目；非招聘模板无这些字段。默认数组为空、薪资筛选关闭，不扩大允许目标和逐动作授权。

既有实例保留原模板来源和 Schema，计划保留原策略快照；新版模板创建新实例，不覆盖旧流程。导出保留表单定义、清除实例策略值，导入不继承账号、事实、筛选值或自动权限。需要新增筛选的旧实例可从新模板创建并重新配置，不静默迁移授权。

## 证据和动作

站点适配的 read(target) 返回可选 jobSnapshot，字段属于指定目标的当前页面详情。列表里的 job/company 与详情不一致会停止该动作。只要启用了新增筛选，快照缺失便不能通过。数据未知时由适配器返回 null；不得将经验推断或模型猜测包装成页面证据。

协调器先核对账号、目标和简历，再检查岗位条件，之后才允许调用 AI。提交前重新读取当前页面；条件不符、必要字段丢失、岗位证据变化、会话变化或用户已回复时均不发送旧内容。持久化动作记录保留岗位证据，确认摘要包含证据内容及来源，排除不断变化的 observedAt。动作策略提交入口仍独立校验，不能绕过协调器直接提交不符合范围的动作。

筛选不改变投递/简历/会话的去重键：规则改动或页面信息更新不会重放已提交、未知或明确失败的动作。筛选失败写入包含公司、职位和原因的持久化待办；不等待人工占住执行槽。观察时间变化不会重复产生同内容待办。

## 本地验证要求

两站虚构适配器分别覆盖允许/不允许城市、公司、职位词、三种工作方式、完整薪资区间、缺失信息、币种/周期不支持、倒置数据、详情与列表冲突。核对不匹配时 AI 调用数和提交数均为零；确认后仅时间变化仍可提交，岗位信息/来源变化使确认失效；提交前变化及政策撤销不产生副作用。桌面验证字段在模板弹窗中保存、无自动运行、通用右侧无业务字段，并验证原实例与新模板隔离。真实站点 J-02 仍需实际账号、页面和授权业务回执。
