# 运行详情与实时观察

2026-09-20。补齐 P1 当前步骤、耗时、主动进度和输出展示，修正持久化失败后把最后保存的 RUNNING 当作当前执行的误导。0.1.32 已采用此设计，源码、候选包和日常安装的实际交付分别见[验收记录](acceptance.md)。范围仅本机单任务与现有运行详情，不增加重试、续跑、业务百分比或招聘能力。

## 事实来源

Run 和事件仍是最后成功保存的历史，不能因界面推断改写终态。宿主新增只读执行观察：`{observedAt: ISO时间, active: null | {runId: string, phase: "executing" | "closing"}}`，由当前 Active 资源所有者生成；取消、Worker 收尾或中断后的收尾归 closing。active 为 null 仅说明采样时宿主没有活动 Run，不保证历史未知外部资源已消失，既有 runtimeBlock 和脚本租约规则继续生效。

`bootstrap` 与 `run.detail` 增加可选 `execution` 观察；`run.detail` 同时返回可选 `fault`，沿用 Store.fault。新旧消费者可忽略新增字段，不改变请求和公共契约 0.7.0，不迁移 SQLite v2。组件随完整应用更新。凭据列表、产物可用性等异步读取先结束，再同步采样 Run、事件、输出与 execution，避免把较早历史与较晚活动身份混为同一观察。Renderer 只使用宿主回执，不直接查进程。

界面按观察中的 active.runId 匹配当前活动，不把旧 RUNNING 记录直接用作实时控制事实。采样时宿主未持有此运行、仍为非终态的记录显示“最后保存状态”，执行结果待核对。没有新观察字段的旧记录/响应保持可读，明确实时状态未知。宿主原有状态、归属和 controlPending 校验仍是控制许可的最终来源；界面不添加第二套执行状态机。

存储故障持久显示“已停止接收新任务；状态为最后成功保存的记录，当前执行和最终结果请核对”。不可无条件宣称所有进程已停止。实际仍持有的活动 Run 保留取消入口；已无活动资源的旧 RUNNING 不继续提供暂停、继续或单步。取消失败不假报保存成功。恢复沿用显式退出、重开和人工核对，不自动重放。

## 展示

- 当前步骤由不可变快照与有序 node-start/node-end 事件定位；嵌套条件和循环优先显示最内层尚未结束的确切 nodeInstance，并展示循环实例路径，不能把容器数或循环数当总完成率。仅当宿主 phase=closing 时显示正在收尾；执行中两步骤事件的间隙显示等待下一条步骤记录；失败/中断记录只展示最后记录步骤，不称正在执行。
- 暂停时显示下一步的 debug-pause 位置；人工等待显示实际等待步骤。名称来自运行快照，不读取后来编辑的草稿，旧事件缺失则明确不可确定。存储故障时即使宿主仍持有 Run，也只显示最后记录步骤，不把旧 PAUSED 位置或旧进度数量当作当前报告；保留活动归属供取消。
- 耗时从最早成功保存的 RUNNING 时间开始，排队不计入执行耗时；暂停/人工等待计入并明确为运行总耗时。活动任务按当前时间刷新，已保存终态按终态时间固定。中断恢复时间不能冒充实际执行结束时间；没有可确认结束时间时展示已记录时长或待核对，不继续累计停止后的旧 RUNNING。时间缺失/倒退不猜测、不显示负数。
- 主动进度仅使用当前节点实例最近一次有效 progress 事件的 completed/total。无 total 显示已处理数量；没有报告显示未报告数量。有限非负数及总数有效时才显示，越界/无效报告保留原始事件但不计算百分比，不跨循环实例沿用。不得由步骤数推算业务完成率。
- 运行输出显示宿主已持久化且脱敏的 output，普通运行无需重跑便能查看。保留 null、false、0、空字符串和空对象；没有保存输出时明确说明。长输出先展示有界预览，用户可展开完整的已保存脱敏内容，截断必须标识；展开只读，不能再次执行。调试步骤预览及原始日志/事件继续可查。

## 验证

- 纯展示模型覆盖无报告脚本、有效/无效进度、嵌套分支与循环实例、暂停位置、缺失/倒退时间、保存终态、重启中断、故障遗留 RUNNING 以及各种空值输出。
- 真实宿主与 Worker 以本地 HTTP 返回较大虚构结果，在独立 SQLite 主连接设置 max_page_count 触发实际 SQLITE_FULL（错误码13），核对失败位于 output、无 SUCCEEDED/输出记录、后续队列无副作用、实际 Worker 退出、新准入拒绝、旧数据完整和重开不重放。该页数上限按 [SQLite 官方 PRAGMA](https://www.sqlite.org/pragma.html#pragma_max_page_count)设置，不填满用户磁盘；此证据不能称为真实磁盘耗尽。
- 真实 Electron 界面验证命名脚本无报告时当前步骤/递增耗时、报告数量、普通运行最终输出、暂停/等待/取消与结束时长、重开保留。内置本地复杂表单保持 1920 CSS 像素，源码和候选/安装路径分别记录。故障提示须使用明确故障夹具，区分注入界面验证与真实 SQLITE_FULL 执行证据。
