# 每次登记的运行产物副本

2026-09-20。0.1.20 真实 Worker 复现：连续两次向同一 result.txt 写入不同内容后，第一次 Run 仍为 SUCCEEDED，历史产物 available 为 true，但定位读取到第二次内容。架构要求产物按 Run 隔离，当前只登记外部可变路径未满足这一点。

## 存储与兼容

- 文件、Excel、脚本产物、截图和下载统一由宿主登记。每次登记向数据目录 `artifacts/<runId>/<artifactId>/<原文件名>` 保存独立副本；同一 Run 的重复文件名也不共享副本路径。业务输出原路径保留供后续步骤使用，不改写流程、绑定和 ArtifactRef 的 artifactId/runId。
- 流式复制并计算 SHA-256，校验来源为普通文件且复制期间未变；复制完成、取消复查后才在一次 SQLite 事务中登记产物索引及事件。复制/发布失败不登记成功记录，清理未发布副本但保留业务输出。取消后的迟到复制结果不得登记；不重放已经发生的文件操作。
- 产物元数据增加 `storage: snapshot-v1` 和 `sha256`，路径指向副本。SQLite 仍为既有对象存储，无表结构迁移，公共契约 0.7.0 与 ArtifactRef 不变；旧客户端忽略新增字段并仍能读取副本路径。
- 旧记录没有历史副本和摘要，不能从当前文件伪造当时内容。旧记录保留原路径和可访问性，只标记“旧记录，未保存副本”；不批量读取或迁移日常数据。
- 默认不自动删除运行副本。按 Run 清理作为后续增量由[产物清理](artifact-cleanup.md)定义，具体交付只以验收证据为准。磁盘不足、读取或数据库失败仍明确失败，不以副本缺失冒充记录成功。

## 查询与界面

`run.detail.artifacts` 保留已有字段，增加 `integrity`：verified（副本摘要一致）、changed（副本内容变化）、missing（删除、移动、不可读或符号链接替换）、unverified（旧记录当前可访问，但无法核对当时内容）。available 对新副本仅在 verified 时为 true；旧记录沿用可访问性并显示 unverified。查询不改写 Run 终态或历史事件。

摘要校验使用流式读取；界面轮询可按设备/文件标识、大小、mtime、ctime 缓存核对结果，文件元数据变化时重新核对；定位请求必须重新计算摘要。校验过程中发生变化按不可核对处理，不将校验称为对恶意本机程序或文件系统竞争的安全保证。

新副本显示“已保存副本”，修改/丢失时明确显示原因并禁用定位。旧记录显示“旧记录，未保存副本”，可定位当前文件；不能把它显示为已核对的历史副本。artifact.resolve 内部方法仍只接收已登记 ID，新副本损坏时拒绝返回路径，Renderer 不获得任意文件接口。

## 验收

真实 Worker 验证跨 Run 和同 Run 同名产物、来源覆盖/删除后的旧副本、宿主重开、同长度篡改、缺失/符号链接替换、旧记录兼容。验证登记事件失败回滚索引，复制取消/迟到结果不发布，已有源文件不重放或删除。真实 Electron 界面核对新旧状态和定位按钮，内置复杂表单的上传、下载与截图内容继续通过。仅使用隔离虚构数据；源码、DMG 候选、最终安装与日常桌面分别记录。
