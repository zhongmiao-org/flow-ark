## 展示约定

1. 自定义名称优先；步骤未命名时使用已有中文操作名和序号。实际循环项次、条件分支仍按固定快照解释，不能猜测未知步骤。
2. 运行展示名称、触发方式、实际时间和状态。列表同名项可用实际时间和列表位置区分；不生成虚假的业务编号。
3. 固定快照显示“按启动时保存的方案执行”；摘要仅供诊断。模板保留实际语义版本，Skill 使用名称及实际确认时间，不把内部版本 UUID 编造成版本号。
4. 模板实例、流程选择、结果来源、会话及资源入口使用已有名称、文件名或来源描述。无法取得名称时明确说明待核对；必要的机器配置键放在高级配置，不冒充名称。
5. 排障确需完整 ID、摘要和实例路径时，通过明确命名、默认折叠的“技术标识（高级诊断）”查看、复制。普通标题、选项、提示和无障碍名称同样执行可读规则。
6. 不修改持久化标识、API 参数、去重键、引用、路由、授权或导出语义；不做数据迁移，不重写旧运行，不增加 AI 请求或外部动作。
7. 用户资料、脚本输出与完整高级 JSON 不做猜测性替换，避免改动业务原文。诊断与原始记录仍可精确核对。

## 模板动作确认的名称与范围

2026-10-19 在原始 BOSS 0.2.14 正式安装实例复导中，首次网页点击的模板权限确认显示 `确认：workflow-write`，说明为空。默认区和高级详情都没有可读动作范围，已在任何点击前取消该 Run 并确认终态。该缺陷属于通用模板动作确认，不通过手改包、改成自动授权或直接回答布尔值绕过。

先更新既有可读规范 Light `972:10198` / Dark `972:10411` 的动作名称/来源/范围规则，以及人工确认 Light `2:2911` 和历史 Dark `164:9516` 的副标题/范围说明，移除示例运行编号。两张可见规范与 Light 人工页已整图核对；历史 Dark 原本隐藏、截图为 1×1，不计其整图通过，不擅自展开历史画板。现有字段、主题变量、组件与布局保持。

确认标题使用准确固定包中动作的声明名称，完整范围说明与入口名在默认请求内容区展示；不以内部动作键替代名称，不把运行级许可说成只确认当前点击。既有 `writeGuard` 的确认按本 Run/动作缓存，必须明确覆盖本次运行该动作的后续步骤（含循环），并继续受当前配置、资源和权限复验；不改实例默认权限，不允许其他动作。它是模板声明的动作范围，不声称已核验当前业务对象或每次外发内容。

SDK `effect.prepare` 的确认同样采用声明名称，保留模板本次说明和已有完整 review。核对实现发现它也保存本 Run/动作的写入确认缓存，不能声称只放行单个网页点击；说明须同时指出当前操作记录的准备及本次运行该动作的写入范围。后续每份操作记录仍须独立准备、同键不重放，确认不保证站点已受理；本批不改变这套既有授权与去重行为。旧已保存人工请求保持原样，不用当前模板回填历史；普通无说明的旧请求仍按既有失效状态处理。本批复用已有 title/description/schema 字段，不新增公共协议、数据库或业务权限，旧 `template-approval` 与去重键不变。后续客户端类型/构建/有限集成观察、原生确认/拒绝/取消和打包安装分别验收，不新增或运行应用单元测试。
