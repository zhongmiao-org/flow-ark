# 持续会话的原生 IPC 顺序核对

2026-10-18，接续[主线 S08](guided-skills-boss-plan-20261015.md#34-ai-对话消息与顺序)、[原生 HTTP 断流核对](conversation-connection-failure.md)和[迟到保存回执](conversation-receipt-order.md)。客户端保持已交付 #313、契约 0.38.0；本批核对真实 Main/Preload 的时序缺口，没有新增产品功能、协议、Figma 交互、模板包或安装更新。

## 观察范围与来源

从上批闭合的虚构工作区复制隔离资料，初始 45 文档/5 事件和两份虚构工作区保护凭据逐字节保持，原个人目录不接入。使用临时启动器在正常 Electron Main 阶段加载观察层，再直接加载当前构建的原 `dist/main.cjs`。正常 Main、Preload、Utility Host、白名单 sender/frame/参数检查、SSE 适配器、Store 和 Renderer 均使用原实现；观察层只在 Main 已校验之后暂存/重复/重排原事件，或暂存一次原 `conversation.thread.send` 返回值，不构造新快照、不绕过业务准入或直接写 Store。

模型传输仅到真实 127.0.0.1 HTTP，供应商响应、Key、内容和用量均为虚构，其他 fetch 目的地被拒绝。会话发送、导航、输入保存和第二个通用 conversation v2 流程的创建全部经原生客户端 UI；故障控制也由临时可见页面显式操作，不手改流程 JSON 或导出包。临时队列最多 16 条是夹具保护，不能计为客户端新增缓存能力。

初次夹具启动分别遇到 Electron 模块过早加载、拆分局部变量缺失与应用身份不同导致解密拒绝；修正正常 Main 加载时机和相同应用元数据后，确认原虚构记录完整保持，再开始下表观察。失败启动未产生模型请求，不计产品缺陷或通过项；没有放宽系统凭据保护或明文降级。

## 六项原生时序证据

| 场景 | 实际来源及结果 |
| --- | --- |
| 发送回执迟到 | A 第 11 次请求的回执 sequence46 暂存，流式事件已到 sequence49/ready 后才释放旧 generating 回执；UI 保持完整甲乙与完成状态，没有回退或另建请求 |
| 真实事件倒序 | A 第 12 次的实际事件 50–54 全部暂存，UI 仍在生成；按 54→53→52→51→50 投递后触发原 detail IPC，按宿主完整快照恢复 ready/甲乙，旧事件未覆盖终态 |
| 重复事件 | A 第 13 次的五个真实事件 55–59 各投递两遍；只增加一次请求、一份有序甲乙正文，无重复追加 |
| 正文事件缺号 | A 第 14 次明确丢弃 sequence62，63 到达后 detail 恢复甲乙，但 UI 仍为 generating；只有真实 sequence64 成功终态后才成为完整问答 |
| 切换会话后旧事件到达 | A 第 15 次仍在生成时切换至独立 B，B 中输入本地未发送补充；倒序释放 A 的 69–65 后，B 仍 0 次请求、原输入保持；返回 A 可见独立完整结果 |
| 保存事件迟到与手动重读 | B 的保存调用已采纳 sequence2 后暂存其真实事件；用户继续编辑新输入，再释放旧保存事件并手动读取，均未覆盖未提交输入；最后由用户操作保存最新输入 |

本批共五次明确的虚构模型尝试、五条本机 HTTP 连接；B 不调用模型。捕获 28 条原宿主事件，故障层额外重复投递五次、明确丢弃一次；结束时暂存事件和回执均为 0。源快照身份和连续序号由原宿主产生，未将修改 JSON 中的 sequence 当作真实乱序证据。
