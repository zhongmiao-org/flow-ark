# 节点超时与高级输入一致性

2026-09-20 修复约定，交付状态见 [验收](acceptance.md)。沿用公共契约 0.7.0 已有的 timeoutMs（100～3600000 毫秒），不增加节点版本、IPC 或数据库迁移。

## 超时语义

- 每个节点显式配置的 timeoutMs 必须生效，包括条件、循环、人工等待、数据和断言。HTTP、脚本、文件、Excel、浏览器和招聘能力节点未配置时，继续采用既有 60000 毫秒默认值；未配置的人工等待、条件、循环、数据和断言不新增默认期限。
- 期限从节点自身的步骤边界放行且 node-start 已记录后起算，使用单调时间。节点启动前的逐步调试暂停不消耗它自己的期限。条件涵盖所选分支，循环涵盖全部实际迭代；显式父容器期限包含内部人工等待、子节点执行和子节点边界暂停，不因等待用户而延长。
- 嵌套节点以最早绝对期限为准，错误指出实际到期的节点实例及预算。同步工作阻塞事件循环后也要核对已经到期的期限，不能仅依赖定时器回调或错误归到较晚的父期限。工作超过预算的节点不记录成功、不启动后续步骤。
- 自身期限在实际工作（容器包括子树）完成且检查通过后释放，再等待自身 node-end 的持久化回复；记录回复较慢不能追溯判定已完成的工作超时。父容器期限仍覆盖子节点的事件等待，因此已完成子节点的成功记录可以与父容器超时并存，父容器不记录成功。
- 任一节点超时停止整个 Run，向正在等待的控制门、HTTP/脚本及其他能力传递中止信号，宿主仍负责回收 Worker 和浏览器会话；正常报告的超时为 FAILED，用户取消仍为 CANCELLED，意外失联仍按 INTERRUPTED。所有定时器和监听在完成或失败后释放。
- 超时不撤销已经发生的外部或文件操作，不自动重试；结果仍需核对。纯同步不可中断工作只有让出执行权后才能检查时间，不能把预算称为硬实时进程调度保证。

兼容：旧流程中此前被忽略的显式超时现在会实际失败；不改写旧草稿、计划、快照和历史终态。显式配置仍来源于节点高级 JSON，界面说明父容器等待计时行为。

验证包含人工等待、条件和多次循环超时；父/子不同期限、同步超时归属、调试暂停边界、未设期限的人工作业、用户取消优先及计时器释放。真实 Worker 验证超时后无后续副作用、资源槽可再使用；内置复杂表单验证页面操作后等待超时的清理与新任务恢复，不访问招聘或外部浏览器。

## 高级 JSON 未完成输入

高级节点 JSON 解析失败或改动不可变 ID/类型时，不得用仍保留在内存里的旧节点静默保存、执行、调试或导出。错误纳入统一输入检查；提交动作自动展开高级区并聚焦错误文本。

有无效高级输入时，切换节点、参数页签、修改结构、撤销重做、离开编辑器或打开另一个流程等会清空该文本的操作应先被阻止。异步运行或实例配置保存的回复到达时也须再次检查，不能卸载等待期间新输入的错误文本；此前已提交的保存/运行仍按原请求完成，不取消或重放。关闭高级折叠区可以保留文本；修正为合法输入，或显式点击“恢复节点配置”返回最后有效配置后才解锁。此规则只保护未完成高级输入，不改变既有有效草稿保存和撤销语义，不新增确认弹窗。

验证由真实界面录入截断 JSON、错误 ID/类型，分别尝试保存、运行、逐步调试、导出及切换操作，确认数据库/Run/外部动作不变、错误文本保留；修正和恢复后能正常保存、导出并执行已更新配置。
