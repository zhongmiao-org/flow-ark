用户在资源页选择准确的父确认版本和个人工作区；入口表单选择要修改的项目，填写更新要求、正文同步更新片段、事实序号及访谈标识。字段标签使用业务名称，不让使用者输入代码、JSON路径或站点选择器。保持同一父版本、要求、配置和标识才继续同一补充访谈，改变范围建立新的上下文。

结构化修改限定一个显式项目：目标岗位、期望地点、工作形式、期望薪资、排除方向；真实表达样例、表达规则、待确认表达推断；允许自动回复、需要本人处理、禁止自动回复；待补问题、矛盾记录；指定事实的内容/来源说明/状态、新增事实或删除指定事实。另可只更新明确正文片段。任意其他手工字段仍可通过已有逐项编辑器修改，本入口不让模型自行扩展目标路径。

正文采用本人输入的准确原片段，只允许唯一匹配的一处替换；原片段为空表示正文没有对应内容，此时不接受模型额外追加正文。原片段不存在、不唯一、目标字段结构不符、事实序号越界、输出类型不符或模型不能判断时，停止本批并保留信息，不回退为整篇重写。

## 编排约定

固定Skill读取 → 确定性准备范围 → 补充引导会话 → confirmed条件 → AI局部提案 → 拿不准时停止 → 确定性应用单处变化 → 创建待确认Skill草稿。AI只产生选定项目的新值、指定正文片段的新内容与理由，不返回整篇Skill或任意路径的补丁；所有模型调用仍使用用户自己的Key。

两个小型模板数据步骤分别核对/准备范围和应用局部提案，资料、访谈、条件、AI、Skill仍独立可视化编排。应用时从父版本深拷贝，保留未知和无关手工内容，只更改选定字段或指定事实；原正文片段外的字节保持。原全部来源保留，再追加真实已确认补充会话来源，不让模型生成摘要、修订或时间。

新草稿的key与base引用实际父版本，title保持；仅创建本机待办，不自动写确认版本或获取外发权限。用户查看完整差异、编辑、内部试聊后显式确认新版本；当前确认头或外部文件已变化时，沿用宿主冲突核对，旧版本和活动Run不变。导入新包不携带个人Skill、原资料、对话、Key或本机资源。
