# 按运行清理产物

2026-09-20。产物副本交付后，P1 仍缺少长期使用时的清理入口。本次提供运行详情中的显式清理：默认保留全部产物，没有后台自动删除或保留天数策略。

## 范围与确认

- 只能清理 SUCCEEDED、FAILED、CANCELLED、INTERRUPTED 的运行；活动宿主、仍在结束的 Worker 或迟到能力调用尚未收尾时拒绝。不同运行的清理相互隔离，同一运行不能并发清理。
- 目标仅为当前应用数据区的 `artifacts/<runId>`，包括登记副本及截图、下载、脚本的中间产物。业务绑定目录、原业务文件、外部旧产物、其他运行、脚本依赖、凭据和 Profile 不在范围内。产物根目录或该 Run 目录为符号链接时拒绝；目录内的链接只删除链接本身，不跟随访问目标。若其他 Run 的未清理索引仍指向本目录，则拒绝清理，避免破坏旧版共享路径记录。
- 先预览实际文件数量、逻辑字节数、相对文件名和保留的外部旧记录数量；展示最多 100 条名称并明确剩余数量。字节数不是文件系统实际释放空间承诺。预览不能删除或修复任何内容。
- 确认界面说明永久删除应用内产物，用户勾选“已核对结果并保存需要保留的文件”后才能清理。保留运行终态、快照、输出预览、事件、产物元数据、动作去重记录及待办；不能用清理抹去未知外发结果或再次执行授权。
- 确认时重新扫描和核对预览摘要，文件、索引或状态变化时拒绝并要求重新预览。只接收运行 ID 和预览摘要，不接收路径或任意文件列表。目录检查防止常见链接越界，不称为抵御恶意本机程序的安全沙箱。

## 持久化与失败

宿主先持久化清理意图，再删除当前 Run 的产物目录。意图写入失败时不删除文件。删除成功后，在同一事务中标记受影响产物的 clearedAt、清理完成记录并追加 artifact 清理事件；Run 终态不变。

文件删除失败可能留下部分已删除文件；记录清理失败并保持未完成状态，界面明确显示“清理未完成”。完成事务失败时不能报告成功，存储故障按既有规则阻止新运行。重开遇到 pending 清理意图只标记 interrupted，不自动继续删除。用户重新预览剩余内容后可再次确认清理；操作按目录缺失幂等，不重放业务步骤。已清理的索引保留 tombstone，不因同路径后来出现文件而恢复定位。

## 本地 IPC 与兼容

- 新增白名单 `run.artifacts.preview`，参数 `{id}`。返回 runId、token、count、bytes、files（name/size/link，最多 100 条）、omitted、externalCount、indexedCount、previousCleanup。token 覆盖 Run 状态、索引元数据和目录项身份、大小、修改时间等签名。
- 新增白名单 `run.artifacts.clear`，参数 `{id,token,reviewed:true}`，token 为 64 位小写十六进制。成功返回已完成的清理记录；活动、收尾、并发、预览过期或存储故障均拒绝。
- `run.detail` 增加 artifactCleanup；产物增加可选 clearedAt，integrity 增加 cleared，available 为 false。界面显示“已清理”，定位被拒绝，其他 integrity 沿用[产物副本](artifact-snapshots.md)。旧外部记录继续显示未保存副本并保留当前路径。
- SQLite 增加既有文档存储中的 artifact-cleanup 类型，无表结构迁移；公共契约 0.7.0、ArtifactRef、流程、版本与计划不变。旧客户端忽略清理记录，已不存在的文件仍不可定位。运行事件使用既有 artifact 类型的清理数据，不改写旧事件。

## 验收

使用隔离虚构数据和内置复杂表单。真实宿主验证预览无副作用、确认摘要过期、活动/收尾/并发拒绝、原文件及其他 Run 保留、内外链接、旧外部记录、同名副本、零文件与重复请求、清理后重开和拒绝定位。注入意图写入、部分删除、完成事务故障及 pending 重开，确认失败可见、无自动业务重放或删除。真实 Electron 通过清理预览、取消、勾选确认、完成状态、刷新与重开验证；源码、DMG 候选和最终安装分别记录。

当前历史入口仍只列最近 200 条运行；更早记录的界面访问需要后续补齐。此项不作为完整历史浏览或 P1 总体验收完成的证据。
