## 可静态阻止的缺陷

旧 authoring_plan 只验证流程节点及入口资源引用列表；配置、状态、输入、结果 Schema 语法和内置节点实际 binding 未在保存计划前逐项检查。后续导出器还会为内置节点推导资源，使错误 ID 到实例配置才暴露。

新增对 plan/code/assemble 写入路径的前置校验（旧草稿 get 保持只读可查）：配置 Schema 使用现有受支持子集；所有声明 Schema 使用本地 Ajv 编译，失败给出准确字段；file/excel/document 的目录绑定及 ai/conversation 的 AI 绑定必须在该入口明确声明，种类与访问方式一致。资源访问组合也按既有包契约检查。旧草稿只读加载规则不追加收紧，旧不合格计划继续生成或组装时必须修正；不为读取历史而修改其内容。脚本动态 SDK 资源仍由正式宿主准入，静态检查不能证明任意 JS 语义。

## Skill 必须约束的事实

- 资源/动作/节点参数使用安装 Schema，配置默认值是待填写种子，不伪造合法坐标、URL或业务状态。无法初始化的必填状态由宿主未初始化槽承载，首次完整 set 仍校验。
- Excel string 保留前导零；数值仅在源类型/格式有证据且符合映射规则时转换，不能因列名为电话直接全部拒绝或擅补零。
- Canvas 表格先只读验证导航、范围形状和保护列；有现场依据才显式选导航准备策略，不能把通用 SDK 的存在当作站点支持。
- 人员、勾选、保存可能伴随通知/提交。写入前核对并关闭不在授权内的外发；无法验证则停止。Command+S 的站点语义不能凭 Excel 经验推断，保存必须业务页面正向证据及 fresh read。
- 窗口身份、标题装饰、输入实际是否生效属于客户端/适配器验收，不能靠不断修改业务代码、放宽守卫或重复安装伪造通过。

## 验证口径

正式 CLI validate/build 只编译，不执行节点、AI或桌面动作。每项命令单独记录退出码；生成 SDK 后重新类型检查。不以最后一个 shell 命令成功替代前序检查通过。安装候选和真实写入、保存、重开防重仍未验收。
