# 日志、结果与错误的脱敏边界

2026-09-20。0.1.34 后确认两项遗漏：对象键没有经过脱敏，执行前校验错误直接穿过 RPC/IPC。修复统一展示与持久化输出边界，不改变公共契约、SQLite v2、运行状态和凭据授权。

## 行为

- 已登记凭据及既有敏感格式在字符串值、对象键、数组和嵌套结构中均须遮盖。敏感字段名沿用原先遮盖对应值的规则；正常字段及安全值保留，不修改原对象。
- 键需要遮盖时使用不含原文的稳定占位名称。预留既有键并跳过冲突，保留每一项，不能以重名覆盖丢弃结果。布尔 false、数值 0、空字符串、null 和数组顺序保持；重复脱敏不再次重命名已有占位键。
- 通用 RPC 错误默认采用同一字符串策略；Host 的公共请求错误使用该执行上下文已登记秘密。Main 的 Renderer 请求出口还覆盖 IPC 校验、文件操作、Vault 与异步 RPC 拒绝，并对本次待保存的凭据值进行局部遮盖。返回拒绝仍是拒绝，不伪造成功或启动 Run。
- 成功的内部凭据读取和执行中的原始值保持不变。`credential(id)` 仍只在流程明确授权后返回原值，凭据不因脱敏增加读取或写入。原始内部错误的分类判断仍在展示边界之前完成，不改变取消、失败、中断、重试、退出和资源回收行为。
- 日志、调试预览和最终输出在保存前脱敏；界面公共错误展示不携带原始 cause、stack 或额外秘密字段。完整错误只保留可公开的诊断文字，原有长度限制继续生效。

## 验证与旧数据

使用独立虚构凭据经真实 SDK、Worker、Host 运行，分别核对嵌套日志、普通输出、调试预览、抛错以及正常退出重开。验证内部读取仍得到原值，已保存输出和界面不包含该值；键冲突不丢项。

执行前分别验证 Host/RPC 校验拒绝与 Main 直接拒绝，使用虚构格式样例以及本次待写入值，核对错误可读、零新 Run/快照/版本和零外部副作用。IPC 错误注入与真实系统保护回环分开记录，不把模拟错误称为实际 Keychain 故障。

不重放流程来清理历史。新策略可继续处理可识别的历史格式，但旧记录中的任意非格式秘密若已轮换或不在当前执行上下文，不能可靠识别；本修复不宣称自动清除全部旧历史或任意编码后的秘密。可信脚本仍不是安全沙箱。

仅使用本地复杂表单、内置浏览器和虚构数据，网页保持 1920 CSS 像素宽度。源码、DMG 候选、日常安装分别验收，结果归[验收记录](acceptance.md)。
