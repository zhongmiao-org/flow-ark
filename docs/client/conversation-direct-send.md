# 普通会话直接发送

2026-10-17，用户指出逐条回复要求“核对、勾选、发送”打断访谈。本次只调整普通会话发送交互；固定确认来源、保存 Skill 和外发动作仍保留各自独立确认。

## 发送约束

输入后一次点击“发送”就是本条请求的明确人工发送与费用意图，不再要求展开预览或逐条勾选。当前服务、模型和使用本人 Key 的提示常驻回复区；发送范围与完整内容可以按需展开。内部试聊使用相同的普通发送交互。

0.32.0 的 Prepared、五分钟一次授权、凭据修订核对、CAS、持久请求身份及 onmessage 顺序保持。Renderer 在同一次人工发送操作中先获取宿主构造的完整 Prepared，再提交同一个身份；预览不是第二次人工审批。`reviewed:true` 表示明确点击本次发送，不表示必须存在一个复选框。不能由定时器、模型、模板、页面恢复或收到消息自动调用此流程。公共 JSON/IPC 结构及已发布快照不变。

来源、指令、模型及历史窗口改变仍先核对提议后采用。持续会话显示当前 Key 配置状态，并在发送前与准备后只读复查配置修订；不一致时本次不调用模型，保留输入，提示用户核对新配置后再次发送。后续配置变化仍由宿主原有授权修订检查阻止。Key 本体不返回 Renderer。

同一操作串行锁覆盖准备与发送，连点不产生两个请求；准备失败不生成待核对的模型请求。提交后结果未知保留原 requestId，仍走核对/撤销原请求；取消、手动重试、来源确认、Skill 发布和对外发送分别处理。普通聊天不自动发布 Skill，不改变绑定或已有 Run。
