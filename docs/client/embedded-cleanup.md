# 内置网页关闭确认与运行中断

2026-09-20：修正内置会话关闭失败仍被当作回收成功的问题。此文定义 0.1.30 已采用的网页关闭语义，实际实现、故障注入与原生页面证据归[验收记录](acceptance.md)。当前仅测试本地复杂表单，招聘、真实 AI 和外部浏览器仍后置。

## 关闭确认

内置页面由 Main 按资源代际持有；宿主用唯一 token 租用。资源代际在创建时确定，token 在异步启动前登记。初始化、执行、截图、关闭及意外丢失的异步结果只能修改其所属代际，旧请求不能销毁、清空或重新启用新页面。

关闭开始后保留 token、原生对象和关闭 Promise，同时拒绝新操作。停止当前命令、取消拾取/下载、移除视图和销毁网页分别尽力完成；移除视图失败不能跳过真正的原生关闭。只有对应 WebContents 的 `destroyed` 事件或 `isDestroyed()` 才是销毁证据。关闭调用返回、字段清空、渲染进程崩溃和 RPC 超时均不等同于已销毁。

内部 start 回执包含 token 与 resourceId；close 回执区分 closed 与 unknown，并带所属 token/resourceId，unknown 带诊断原因。宿主验证回执匹配，拒绝 undefined、布尔值或不匹配身份。重复关闭同一已确认对象幂等；任意未知旧 token 不能被当作已关闭，不能作用于当前对象。所有 Main/Host 组件随完整客户端更新，不兼容混用旧内部回执。

关闭中和未确认关闭时，所有网页创建入口使用同一状态门禁，包括预览导航、面板打开、元素拾取和宿主 start。收起面板和读取状态仍允许。正常成功运行只释放健康页面的独占租约，可保留页面与登录会话；不要求每个成功 Run 都销毁页面。取消、失败或意外失效要求确认停止对应资源。

截图的隐藏绘制宿主属于确切网页代际。关闭时清理正确的父容器，迟到截图只处理自己的宿主，不移动新网页、不登记已取消运行的产物。Cookie/存储刷新不作为销毁证明：失败或超时单独给出警告，不能谎称已保存，也不否认已取得的原生销毁证据。

## 运行状态与恢复

运行宿主统一收尾。发出协作取消后立即启动现有 Worker 强杀宽限计时，与浏览器关闭并发；浏览器挂起不能延迟 Worker 回收。重复取消、执行错误和退出加入同一资源收尾；单项失败不能跳过其他资源。成功路径在最后一次异步清理后重新核对取消/丢失状态，不能把收尾期间的取消覆盖为成功。

终态以实际原因区分：回收未知为 INTERRUPTED；意外 Worker/网页丢失为 INTERRUPTED；明确用户取消且已确认回收为 CANCELLED；节点失败/超时且已确认回收为 FAILED；无中断且完整成功为 SUCCEEDED。原操作错误和回收诊断均经脱敏保留，外部结果未知必须提示核对，不自动重放。

任一所需资源无法确认回收时，先设置独立的执行阻断，再释放宿主控制结构。它与存储故障分开：界面显示回收未确认及完整退出、重开、核对结果的提示。已有队列保持未启动且可手动取消；新手动运行、关联重跑、计划触发和 pump 均不得开始执行，异步预检完成后再次检查门禁。只读历史、流程编辑、待办及退出继续可用。休眠恢复不能清除该阻断；阻断期间不积累计划补跑。

无宿主租约的预览网页也不能遗漏：Main 首次确认回收未知时，以私有 `system.browserCleanupFailed` 通知宿主设置同一执行阻断；普通意外丢失通知不自动等同回收未知。该通知处理不等待会反向调用 Main.close 的收尾，避免循环等待；通知无法送达时停止宿主并提示完整重开，不让后台任务无提示地继续。Main 的故障状态保持到完整重启。

本版采用完整应用重启恢复，不新增“强制解锁”或自动继续队列。迟到销毁证据可补诊断，但不清除已报告的阻断或自动启动队列。正常显式退出有界地停止宿主与应用，即使关闭失败也不能停留在半退出状态。重开后按既有恢复规则把未完成活动/队列记录为 INTERRUPTED；用户核对后通过现有重新运行入口产生新 Run，不重放旧操作。仅重建 Host 不视为整个应用资源已回收。

恢复保证限定于随 Main 退出而销毁的内置 WebContents。2026-09-20 后续审计发现独立 detached 脚本在 Worker 被外部强杀且脚本同步忙循环时可能成为孤儿；父进程退出和应用重开不能证明它已停止。0.1.31 已按[脚本进程监护](script-process-supervision.md) 独立修复该归属缺口，未知脚本租约跨应用重开保留；不把此处重启恢复策略视为全部外部进程的回收证明，证据边界见[验收记录](acceptance.md)。

关闭预算集中定义：原生销毁等待 5 秒，宿主关闭确认总预算 8 秒，Worker 协作宽限仍为 2 秒；会话存储刷新另限 1 秒。Main 退出保留现有宿主 15 秒等待，并保证本地清理失败后仍结束宿主及应用。超时阻止迟到初始化复活，不能只缩短调用方等待而放任远端动作。

## 协议、数据与验证

本地 Bootstrap 新增可选 runtimeBlock 提示，网页状态可报告不可操作原因；内部租约回执只在 Main/Host 传递，不向网站或 Renderer 暴露原生对象、token、Profile、Cookie 或凭据。0.1.30 此项网页变更保持公共契约 0.7.0，流程节点、业务副作用语义、导出包及 SQLite v1 不迁移；旧流程、快照和历史保持不变。后续 0.1.31 的脚本监护单独采用 SQLite v2，迁移与兼容以[脚本进程监护](script-process-supervision.md)为准。

验证分别覆盖：

- Sessions：关闭拒绝/超时、错误身份、重复关闭、启动中取消、迟到旧请求/丢失通知、正常跨 Run 健康复用。未确认时不得发送新 start/perform。
- 真实 Worker：无响应脚本与关闭挂起并发取消，核对进程实际退出；关闭失败后队列无文件/HTTP 副作用，普通/重跑/计划准入阻断；成功收尾取消竞态、意外丢失、原错误与回收错误保留、写库失败和退出收尾。
- 真实内置 WebContents：延迟销毁证据、视图移除失败仍销毁、原生 close 失败后阻断、初始化中关闭、最小化截图中取消和旧回调隔离；显式退出后隔离数据重开，无自动重放。
- 回归：复杂表单实际服务端回执、1920 CSS 像素、拾取与截图生命周期、节点超时、退出确认和候选包升级。注入的是故障边界，真实页面正常关闭证据须单独核对，不能把注入用例当作观察到系统自然故障。

不增加外部浏览器切换、业务动作重试、在线恢复中心、服务端或常驻系统服务。日常安装若仍等待解锁，应继续如实区分源码、候选和最终安装。
