## 制作定义与信任边界

从准确0.1.3包复制制作下一公开检查点，保留原三个入口字节。新增profile-sources手动入口：解析明确选择的简历文件→读取固定确认Skill→整理来源状态→可视化ready条件→保存来源就绪结果/否则登记本人核对提醒并保存。简历通过resume-materials只读目录及入口输入resumeFile安全相对文件名选择；只读profile Skill资源必须选择本机登记的准确确认版本和摘要，不使用草稿或静默最新。文件名采用输入引用，公开默认空值，不把私人目录或正文写入定义。

沿用document v1的UTF-8/PDF/DOCX、8MiB/100页/1000单元/50000字符及缺口规则。只解析所选文件，不扫描目录、自动OCR或执行项目；partial/empty进入needs-review，缺失/损坏文件或Skill在宿主预检/读取处明确失败，不伪造正常输出。Skill缺失、外部变化或未确认时阻止；不自动换版本、改文件或回填内容。

sources-ready仅表示当前解析ready且固定Skill可读取，不能证明身份相同、履历与技能一致、事实已确认、JD匹配、账号有效或动作授权。完整文档/Skill正文由既有宿主受保护结果保留；模板结果和提醒只保存文档来源/摘要/状态/缺口及Skill版本/摘要/确认时间等来源，不复制正文/结构化事实。accountVerified/eligibleForActions始终false，不把旧Run结果当作后续外发准入；后续采用前仍需重新核对绑定、版本和当前账号/会话。

同实例提醒按文档名/摘要、Skill摘要和解析状态去重，重复核对保留首次来源；更换内容或版本产生不同键。引用、目录及Skill绑定留本机，公开包只有逻辑声明。原conditions入口仍无需任何本机资源，原网页两入口仍只需要浏览器，不因新增资料入口要求它们绑定简历/Skill或Key。全部未来模型调用继续只使用用户自有Key。
