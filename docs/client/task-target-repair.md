# AI 任务的网页目标修复

2026-09-21。依据 Figma `23:4425`、`23:4575`、`23:4724`、`23:7691`，补齐失败定位、实际重新拾取、修复差异及明确重跑。属于 [AI 任务体验](design-ai-task.md) U10；完整 186 张画板和 U01–U12 范围不变。本文定义接口，不能当作页面、真实模型或用户验收已完成的证据。

## 修复依据

原 Run 必须已失败、取消或中断并完成资源收尾，任务关联同一个 flowId。宿主从不可变快照及实际 node-start/node-end 事件定位最后开始且未确认完成的网页步骤；不根据模型描述猜测失败节点。只支持现有 browser v2/v3 中带静态 selector 的目标操作；动态目标、导航或已由用户修改的同一步骤返回明确原因，用户仍可走普通任务修改。

重新选择沿用内置网页的原生拾取，不触发网页点击/输入/提交。Renderer 只提供实际 pick requestId，不能提交 selector、匹配数或“已验证”字段作为依据。新增仅 Host/Main 内部方法 `browser.embedded.pick.capture`，从当前已选中的原生状态读取目标，并对同一网页重新检查唯一匹配；不创建会话、导航或读取全部 DOM。异步检查前后核对网页资源 ID、文档 revision、URL/标题、拾取状态和操作归属；刷新、重新选取、取消、隐藏、关闭或不唯一均使旧检查失效。

返回最小选择信息：requestId、网页资源 ID、文档 revision、URL、标题，以及 selector、framePath、label、tag、inputType、structural。不返回输入值、密码、Cookie、账号、选项全表或任意页面文本。label 只是已选元素的简短描述，不能称为完整读取预览。网页 URL/标题及资源身份只用于本机核对，不自动传给模型。

## 本机接口 v1

所有方法沿用来源帧检查、严格 Schema 和 2 MiB IPC 限制。以下为本机扩展，不改变公开规划格式 1.0、流程格式或事件协议：

| 方法 | 输入与行为 |
| --- | --- |
| `task.repair.preview` | `{id,revision,runId,nodeId,pickRequestId}`；核对当前任务、原运行、流程/绑定、实际选择；返回只读预览及 64 位十六进制 token，不调用 AI、不保存草稿、不创建 Run |
| `task.repair.generate` | 上述字段及 `{token,provider,model,reviewed:true}`；重新核对同一预览，明确选择现有 provider/model 后调用一次完整流程规划，立即返回任务状态 |

ID 沿用任务接口的 1–100 字母数字/下划线/连字符规则，revision 为正安全整数；pickRequestId 为 UUID。token 包含本次宿主会话、内容 revision、完整流程/绑定、原运行证据、已选目标及网页身份。未确认 token 不持久化；过期 token 拒绝，不能以再次点击自动换一份上下文发送。

预览展示实际将发送的完整 AIPlanningRequest：任务描述、当前完整流程、宿主生成的有限修复说明，以及本次失败状态、步骤身份和所选目标。未选择的任务附件、答案、历史输出、其他运行、网页 URL/标题、本机路径和凭据值不自动加入。原始异常文本只在本机显示，不自动作为模型上下文。UI 必须在发送前提供完整输入核对和确认；模型输出仍是不可信数据。

模型返回完整流程。宿主构造允许的新流程，仅替换该步骤 selector/framePath，其他字段、节点顺序、条件/循环、参数、能力、模板来源与资源绑定必须保持一致；与允许流程不完全相同即拒绝。未改变目标也拒绝。差异由宿主计算，不采用模型声称的“只改一处”。clarify/unsupported 可显示，但不能采纳为修复。

## 采纳与生命周期

沿用 task.detail/generate 状态轮询、task.cancel/reject/adopt/undo 与加密 ai-task 文档。修复提案增加仅本地 repair 来源信息，用于重新核对原运行、网页及选择。普通生成不能继承旧修复依据。生成前、等待凭据后、结果到达及采纳前均复核；取消、编辑任务、换网页或换目标后的迟到结果不能覆盖当前内容。任务、流程/绑定或原运行证据变化时保留当前草稿并要求重新检查。

采纳前再验证实际目标，异步等待后重新读取任务及完整提案身份和流程/绑定摘要；在单个 Store 事务中保存新草稿及撤销记录。撤销继续遵循当前摘要保护。提案、采纳、拒绝、撤销均不得修改原 Run、快照、事件或已建立计划，也不生成新 Run。

采纳后进入起点与运行前检查，明确显示原运行已经开始的操作及尚未确认的结果。新运行从头执行并关联原 Run，不恢复脚本内部现场、不自动重放未知副作用；必须重新确认当前草稿、资源、页面和原外部结果。仍由运行宿主负责固定快照、准入和请求去重，不能从修复 API 直接启动。页面及关联新运行的接入证据分别记录，不能用宿主单测代替完整 U10。

## 验证要求

宿主验证真实来源选择与伪造选择拒绝、失败实例身份、同一步骤手动修改冲突、模型越界修改/不变目标拒绝、完整差异、零 Run/旧快照不变、取消和迟到结果、凭据等待/生成/采纳期间的文档及草稿变化、存储失败回滚、重开不续发。原生 GUI 另验证实际拾取、DOM 多匹配、同 URL 刷新、隐藏/关闭/重新选取及串行测试清理。完整页面还需三尺寸、返回位置、确认内容失效、真实内置浏览器失败到关联新运行，以及实际模型独立验收。
