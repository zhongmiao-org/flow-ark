# 普通工作区与凭据分离

2026-11-11 当前本人授权：普通流程资料不再因启动客户端而访问钥匙串；API Key、工具登录凭据和原数据密钥仍保留系统保护。此授权调整此前全部业务 JSON 强制加密的默认，不授权凭据明文降级、静默清库或删除旧历史。

已有 `flowark.sqlite` 的 documents/events 全部 AES-256-GCM 加密，不能只延迟供应商 Key 读取就打开旧流程。显式维护操作在当前已解锁会话读取旧密钥，创建独立普通工作区副本，验证每行 JSON 和计数；旧数据库、WAL、密钥及 credentials 目录不改、不删除。副本只在本人核对范围及保留路径后启用；启动不能自行迁移或重建失败密钥。

普通副本仍使用原表结构、引用、Run、unknown、防重与状态身份，payload采用显式 `workspace-json-v1:` 格式，拒绝加密库/普通库混读。数据库和启用清单均使用0600，目录0700。启用清单含准确源与目标摘要、行数、候选身份及版本，不能把任意路径或缺失库解释为新空工作区。迁移中断不改当前工作区，激活前必须关闭旧宿主并重新核对源内容未变；旧加密副本是启用时的恢复基线；普通副本产生新写入后禁止自动切回旧基线，以免丢失新 Run、unknown 或防重。失败回退必须先核对尚无新写入，不能只删启用清单。

凭据仍在 Vault 的 `.enc` 文件中，普通迁移不复制、解密或导出该目录。运行实际需要 Key 时再调用现有受保护凭据路径；零 AI 的工程检查/编译/本地流程不因此解锁凭据。普通流程资料和历史以本机文件权限保护，不再声称全库加密；用户需在正式 UI 明确看到该区别。

本批先实现不执行迁移的底座及格式；UI/Figma、启动选择、人工确认和真实迁移仍须分别验收，未执行不得标记免钥匙串启动通过。

敏感字段扫描仅为阻止明显误迁移的启发检查，不是对自由文本、脚本、日志或任意输出不含秘密的安全认证。本人必须显式选择普通工作区，并看到“普通资料在本机磁盘可读、凭据仍受系统保护、原加密库保留”的准确说明；未确认不启用。若自由文本包含用户自行粘贴的秘密，应先整理对应资料或继续加密模式，不能用扫描通过替代本人范围判断。
