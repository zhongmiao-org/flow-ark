# 来源整理的运行范围核对

2026-10-17。个人蒸馏制作暴露：来源任务从独立检查点继续，而通用重跑页只解释流程从首节点执行，使用者无法准确判断本次会调用几次模型。先行设计为[重试范围核对，849:9062](https://www.figma.com/design/sVciNUZHG9yx81gCpYzjH9?node-id=849-9062)，沿用 Semantic Light/Dark、既有按钮及勾选组件；本批先定义通用契约，不把静态画板当作宿主已经执行了范围限制。

## UI 与范围

普通使用通过原任务的结果页进入核对。宿主提供原 Run、节点实例、任务/来源/配方、任务修订、草稿检查点、下一片段范围、Provider/model、当前 Key 配置修订、历史请求与未知用量，以及本次调用上限。界面不要求复制 JSON，不展示 Key、原始请求体或把模型草稿全文混进预览。高级详情不能成为运行必填项。

三种操作分别显示：ready 为继续有限批次，上限取原节点 maxRequests；attention 为重试当前未提交片段，上限严格为 1；complete 为使用已完整登记的结果，模型调用为 0。上限只约束这个来源节点实例，不是整个流程的调用总数、token 数或费用保证。整个流程仍从首节点执行，其他节点可能产生模型、文件或网页操作，沿用通用重跑核对及原有权限，不能被来源核对替代。存在已保存完整响应时先提供零调用采用入口；重试也必须明确说明这是另发请求。

## G1：宿主生成与当前性

新增契约草案[0.36.0](../../contracts/v0.36.0/README.md)。只在终态原 Run、已登记实际节点实例和任务、当前不忙且来源仍可用时生成只读预览。普通 Renderer 只提交目标身份；所有范围、摘要与计数均从宿主实际记录计算，不能接收 Renderer 自报的来源正文、检查点或上限。

预览只针对原执行快照。固定执行版本、归一化快照摘要、实际任务配方（包含解析后的 seed）、来源、检查点及待处理尝试，绑定本进程随机 epoch 和不透明 reviewId，最多十分钟有效。生成不读 Key、不调用模型、不推进任务、不发放重试许可。摘要只是完整性核对，不是签名或动作授权；宿主必须保存并查找原预览，不能只验证客户端回传摘要便接受。

用户核对后只提交 reviewId、摘要、请求身份及 reviewed。宿主重新读取实际状态、Key 配置修订和授权，核对原预览，并在创建唯一新 Run 的同一事务中保存确认回执及固定预览。相同 requestId 和相同内容返回原 Run；相同身份不同内容、预览重复绑定另一个 Run、过期、进程重开、任务/来源/配方/配置改变均拒绝且不发请求。不自动刷新预览或沿用旧勾选。选择当前已保存流程属于另一项完整核对，不能悄悄丢掉原任务约束。

## 执行前约束

宿主在目标节点解析完动态 seed 后、创建任务及读取 Key/发送请求之前，再核对原任务身份和配方。变化应停止，不能用新的 jobId 静默创建新任务消耗一次重试。nested/loop 的 nodeInstance 必须与宿主原运行索引逐字相同，不能以同名 nodeId 代替。

确认只绑定一个新 Run 的一个来源节点实例。流程从头执行时，其他来源实例只能返回自身已登记完整结果；任何需要新请求的其他来源实例须阻止并重新做明确范围核对，不能借用该许可。不能为到达目标而静默重放未核对的来源请求，也不能注入原中间输出冒充原流程正常执行。普通新任务仍走它自己的入口和核对。

开始首次请求前要求预览未过期、epoch 相同；一旦在有效期内原子登记本批启动，继续操作只按已固定有限批次运行，重试最多登记一次发出。后续同批请求仍复验当前授权、配置及本批实际检查点归属。过期不废弃已经发出的付费响应；有效完整响应仍按既有 CAS 采用，取消/未知/失败不自动补发。重启不自动恢复付费批次，已保存响应可继续走零调用核对。任务检查点与确认回执均属于本机私有记录，不进入公开定义或 ZIP。

## 验证与交付边界
