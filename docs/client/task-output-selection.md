# 理解与补问的输出选择

2026-09-22。对应 Figma [理解与补问 23:2766](https://www.figma.com/design/sVciNUZHG9yx81gCpYzjH9?node-id=23-2766)。页面按原稿 420 / 708 两栏、24 间距、710 最小高度展示需求、输出选项和输入来源 / 操作对象 / 修改内容 / 输出结果四张理解卡。展示真实需求与已选对象；账号未经核对不能写成已登录。模型补问保留短选项及自由回答，不能将任意需求强行解释为教学示例。

## 本机选择与模型边界

- `task.output.choose {id,revision,name,onConflict}`：任务修订校验后由宿主请求 Main 打开系统目录选择器。name 是不含路径分隔符的安全文件名（最多 255 字符），onConflict 为 number 或 overwrite。Main 只把选择器取得的目录交给宿主；Renderer 不能传入路径、选择证明或已授权字段。取消不写任务、不取消既有生成、不创建流程或文件。
- `task.output.configure {id,revision,name,onConflict}`：只更改已经选择的输出文件名 / 策略。
- `task.output.clear {id,revision}`：撤销当前输出选择。

2026-10-10 界面补充：撤销目录保留本次编辑中的文件名、同名规则和未保存回答，避免仅移除目录却清空其他输入。保留偏好不代表目录仍有授权，输出结果仍显示未选择目录、发送预览移除输出元数据；重新选择目录成功后才保存并采用这些偏好。未绑定的偏好仅在当前编辑中保留，不承诺离开任务或重开后的持久化。取消/失败仍保留当前编辑；已保存流程、运行、计划和文件不随当前目录撤销改变。

成功选择、修改或撤销递增任务 revision、取消在途生成并清除提案 / 最近采纳撤销 / 目标修复依据。单步修改期间先退出该范围才可改变整个任务输出。目录选择器等待、目录检查后再次校验原任务、取消代际和活动运行；迟到回复或同时操作不能覆盖新草稿。同一任务已有排队、执行或收尾中的 Run 时拒绝改变输出选择。退出 / 休眠 / 存储失败拒绝写入。

沿用加密 ai-task 文档，保存本地 outputTarget：selectionId、taskId、directory、目录设备及 inode 身份、name、onConflict、selectedAt。目录取系统选择的真实路径并检查为可写目录；生成、采纳、准入和步骤授权时再次核对身份与可用性。目录内容及本机路径不自动读取或发送；模型只收到宿主构造的保留上下文 `_flowark_selected_output`（固定逻辑 binding `task_output`、文件名、同名规则）。普通资料不能冒用系统 ID，二十项 / 单项 50000 / 合计 200000 字符限制包括所有宿主资料。发送核对页展示相同元数据，并明确路径留在本机。

## 方案、采纳与执行

number 使用现有 file v4 create/onConflict:number 和 file-create-numbered-v1；overwrite 使用现有 file v1 write，只作用于该目录内所选文件名，不扩大网页操作权限。模型必须使用固定 `task_output` 绑定、静态所选文件名及对应操作；不可改成另一文件、动态名字、复制、归档或读取该输出目录。选择了输出但方案没有使用时拒绝方案，要求重新核对需求。对网页只读任务，允许此用户独立确认的文本覆盖例外；网页仍只读，其他文件覆盖仍拒绝。固定输出选择暂不用于可自行读写完整资源映射的脚本节点，也不允许通过网页上传读取这个输出绑定；不能借另一种节点绕过输出约束。同名序号创建保持原子不覆盖；覆盖行为在方案与运行前检查明确展示，沿用现有原子替换和目录范围校验，不自动运行或重试。

采纳在同一 Store 事务中合并 `bindings.files.task_output`，仅使用宿主保存的真实路径，保留其他绑定。已有同名手动绑定不同路径时拒绝隐式覆盖，须用户在理解页重新核对，并在既有流程中移除冲突绑定后重新生成。共享同一流程的任务不能选择另一任务已经选择或仍绑定在流程上的输出；原任务撤销选择后，须采纳移除旧绑定的方案，其他任务才可取得该流程的输出归属。FlowRecord.outputTarget 同事务保存并加入版本 / 冲突摘要；flow.save 不能去掉它。撤销恢复原流程、绑定和输出约束，仍保留用户独立选择的当前输出资料；旧约束与当前选择不符时必须重新生成采纳。

撤销选择后再次采纳无输出选择的方案时，移除此前由宿主写入的 task_output 目录绑定；不能保留已撤销目录作为隐式授权。选择变化不改写既有 Run / 计划 / 产物。普通运行、运行检查、排队出队、计划和历史重跑核对快照输出选择仍有效及绑定相同；步骤授权再次核对，不允许借手动编辑绕过所选文件名 / 策略。已发生的文件副作用不回滚、不重放。原子存储失败回滚任务与流程，模型结果、目录选择或一次试运行成功均不等于真实供应商或用户验收完成。

## 验证与交付边界

覆盖严格 IPC / 路径伪造、取消无写入、过期选择器 / 并发 CAS、上下文保留 ID 及合计限制、路径不外发、生成与凭据等待期间变更、恶意方案文件名 / 策略、采纳冲突及事务回滚、撤销 / 重开、真实文件策略、普通运行 / 队列 / 计划 / 重跑和手动编辑绕过。界面核对原稿两栏尺寸、目录取消 / 重选、缺少目录与模型配置返回、理解修改与补问、文件名 / 两种策略、真实运行和产物；GUI 严格单实例串行。

公开规划格式 1.0、契约 0.12.0 和 SQLite 表结构不变，不移动既有 tag。首次教学已移除测试中以 flow.save 准备输出目录的捷径，并取得 UI 到真实文件的闭环证据；其中系统目录返回和模型 HTTP 仍使用夹具，原生选择器人工操作未通过验收。规范、宿主实现、界面、真实 AI 及 U12 用户验收分别记录，见 [Figma 实施记录](design-implementation.md)。


### 2026-10-08 原生文本新建与加序号证据

在既有隔离客户端中，用macOS原生目录选择器选择独立空目录，修改输出名为“文件结果核对.txt”，选择number策略。发送披露只显示逻辑绑定、文件名和规则，不包含真实目录。真实DeepSeek返回固定两行文本及新建文件两步方案，采纳修订5后确认运行，原文件和运行副本均为66字节、内容保持换行。随后经“再次运行前检查”显式确认创建关联运行，产生“文件结果核对 (1).txt”，原文件保留；两份原文件与各自副本SHA-256相同。详情预览、重新读取和新旧运行来源往返已实际查看。此证据替代“原生选择器人工操作未验收”的局部缺口，仅覆盖本机文本新建number策略；覆盖写入、取消/重选、目录身份变化与其他资源边界仍未在本轮实测。完整运行标识与截图见[实施记录](design-implementation.md#2026-10-08-原生文件生成预览与同名保留)。
