# DeepSeek 首版接入与 Key 状态设计

2026-09-21。用户要求首版 DeepSeek 有独立可用的配置设计，并通过脱敏回显让用户明确知道 Key 已配置。本轮为设计增量，不修改客户端或公共 IPC 契约，不删除既有 Codex 架构能力。

## 放置与进入路径

- 主入口：左侧「本地设置」→「AI 服务」，首版优先展示 DeepSeek。
- 本地设置概览显示「DeepSeek · 已配置 / 未配置」和连接验证状态，可进入详情。
- 模板仅在所选入口声明需要 AI 时检查资源；缺失时提供「去配置 DeepSeek」。保留模板实例、入口及未保存输入上下文，返回后重新读取绑定状态，不自动启动运行。
- Key 属于本机供应商配置，模板选择逻辑 AI 资源，不在模板参数中再次填写 Key。只读或不需要 AI 的入口不因此阻塞。

## 配置与回显规则

| 场景 | 展示与行为 |
| --- | --- |
| 未配置 | 空输入、明确「未配置」，不可用一串圆点暗示已有密钥 |
| 已输入未保存 | 输入保持遮蔽，标示未保存；只在保存成功后显示「已配置」 |
| 已保存待验证 | 静态「API Key · 已配置」以及 `•••••••• 7K2M` 示例尾四位；独立显示「待验证」 |
| 重新打开设置或重启应用 | 从宿主重新读取配置状态与安全尾号元数据，恢复同一掩码；不依赖前端上次输入缓存 |
| 测试连接 | 用户主动触发，显示测试中和取消，测试期间禁用模型/Key修改和移除；固定测试文本，不传模板业务内容，提示可能产生少量 API 费用 |
| 验证成功 | 显示「连接已验证」、所用模型与测试时间，只适用于本次配置修订 |
| 测试失败 | 保留「Key 已配置」及掩码；另显示鉴权、额度/限流、网络或模型错误，不把失败显示成未配置 |
| 替换 Key | 新输入为空；不把旧掩码塞进可编辑输入。留空不覆盖，显式保存成功才替换；取消/失败保留旧 Key |
| 修改模型或 Key | 使先前验证结果失效，回到已保存待验证；异步测试结果需校验配置修订，忽略旧请求的迟到结果；不静默切换供应商或模型 |
| 移除 | 二次确认，指出依赖入口的影响和本机删除范围；成功后为未配置，失败保持原配置；资源在用时阻止移除 |

完整 Key 不回显、不可从已保存状态复制；无“眼睛”按钮还原已保存密钥。前端只接收 `已配置/未配置`、安全尾号和测试摘要，不能先收到完整 Key 再自行截取。原始 Key 通过已有受保护写入路径交给宿主后清理输入；不得写入日志、模板、ZIP 或普通本地存储。旧配置没有尾号元数据时显示「已配置 · ••••••••」，不为补尾号向前端下发完整密钥。安全存储失败不明文降级。

`7K2M` 仅为画稿虚构尾号。客户端实施时需确认现有设置接口是否提供安全回显元数据；如需新增字段，应先修订治理契约及验证，不能把设计文档当作已上线接口。

## 模型与服务地址

服务地址按当前 DeepSeek 适配器使用 `https://api.deepseek.com`，实际协议保持 Chat Completions。画稿以 `deepseek-flash` 为模型示例，依据本次核查的 [DeepSeek 官方接入文档](https://api-docs.deepseek.com/)；模型可用性由账号与实际请求确认，不把示例当作该账号已通过实测的承诺。

## 验证边界

Figma 中保存、测试结果和删除均是设计状态跳转，测试动画不发真实 API 请求；图稿未接触真实密钥。客户端需要验证保存/重启回显、替换失败保留、空值不覆盖、移除互斥、错误脱敏和配置修订对应测试结果。本轮不宣称上述行为已经实现。
