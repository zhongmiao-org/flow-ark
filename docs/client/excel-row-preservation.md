# Excel 行列位置保留

2026-09-20 修复约定。沿用契约 0.7.0 的 excel v1 普通读取/写入与 v2 模板填充，不增加节点、IPC、库依赖或数据库迁移。交付结果见[验收](acceptance.md)。

## 普通行数据

- 数组第 0 行对应工作表第 1 行，行内第 0 个值对应 A 列。读取首个工作表时保留第 1 行到工作簿实际记录的最后一行之间的空行，空行表示为 `[]`，不按“有数据的第几行”重新编号。没有工作表或没有已记录行时输出 `[]`；不推造 Excel 未记录的无限尾部空行。
- 每行按最后一个有值单元格决定数据长度，其前面的空单元格显式输出 `null`。不保留 JavaScript 稀疏孔、不将不等长行补成矩形；不额外推造末尾空列。`0`、`false` 和空字符串保持原值。
- 写入按输入数组索引定位行列。空行、显式 `null` 行和稀疏外层数组的缺项占据原行号；输入明确包含的尾部空行也写成实际空白行记录，避免再次读取时丢失。行内稀疏孔按空单元格处理，不能让 ExcelJS 的一基稀疏数组约定把后续值左移。
- 日期、公式和既有 ExcelJS 值对象继续按原能力处理，不用 JSON 序列化补孔，也不把模板填充的严格值校验套到普通行写入。此修复只保证数据位置，不新增公式计算或格式、合并、工作表结构的完整往返保证；保留模板内容仍使用 v2 填充操作。

例如工作簿的 C3、H12 有值，读取结果必须仍通过 `[2][2]`、`[11][7]` 访问；将读取结果引用到普通写入后，它们仍在 C3、H12。普通写入 `[[], ["第二行"], [], []]` 后再读取，仍得到四行。

## 兼容与验证

旧流程和历史不改写；旧版曾压缩空行或左移空首列，修复后下游索引和循环会按照真实行号看到空行。依赖旧缺陷的流程需要显式筛选空行，不提供静默压缩或兼容开关。公共格式和契约副本保持不变，采用治理基线由客户端元数据记录。

验证必须包括真实 xlsx 文件读写：首部/中间/尾部空行、全空表与明确空行、空首列/中间空列、稀疏数组、不等长行、标量及日期/公式等既有对象。真实 Worker 执行“读取 → 引用结果写入 → 再读取”，核对实际单元格地址和产物，不仅比较进程退出码。

界面通过现有 Excel 行列表格及引用选择配置，保存重开后执行，检查分页末端 H12 及稀疏位置。浏览器回归只使用内置复杂表单，保持 1920 CSS 像素桌面宽度；不访问招聘站点或真实 AI。
