# AI 任务规划宿主

2026-09-21。消费 [AI 任务体验](design-ai-task.md) 的描述、补问、完整方案、差异与继续修改路径。完整 186 张画板及 U01–U12 仍为验收范围；本文件定义其中规划提案的真实数据路径，不缩减 MCP、桌面、附件、教学或实际用户验收。

## 规划与流程的关系

采用 [契约 0.9.0](../../contracts/v0.9.0/README.md) 的规划格式 1.0。任务保存描述、显式上下文、补问答案及内容 revision，关联一个固定 flowId。未采纳前可以没有流程；采纳后清单和图读取同一 FlowDefinition。任务不另存一份独立可执行副本，不创建 Run、计划、版本或副作用。

宿主构造 AIPlanningRequest：当前描述、用户已选上下文、答案、当前完整流程以及当前客户端真实支持的能力。普通通用规划提示词归客户端；上下文和模型输出属于不可信数据，不能改变授权、访问未选择的文件、取得凭据或调用原生执行对象。文件路径、浏览器登录态、账号、密钥及全量运行历史不自动加入模型输入。

结果必须是完整 AIPlanningResult，区分 plan/clarify/unsupported。先完整 JSON 解析与 Schema 校验，再验证节点类型/版本、重复身份、引用、嵌套和能力。拒绝空方案、换 flowId、伪造模板来源、非法引用与未支持节点；不得把流式片段或生成失败转换为可执行默认方案。补问问题 ID 不可重复；方案包含 limitations 时如实展示。模型给出的能力名称不是新增授权。

### 2026-10-08 步骤输出语义说明

真实 DeepSeek 首次生成曾把文本数据步骤的输出误写成 `steps.set-text.value`，方案通过结构/作用域检查，但执行时不存在该属性并停止。通用规划说明现明确：`value` 直接返回解析后的值，步骤配置字段不是输出包装；文本引用整个 `steps.<id>`，对象字段须以实际输出结构为据；`assert` 成功只返回 `{verified:true}`。同时说明条件与循环的聚合输出及内部作用域，不更改既有执行语义、Schema、IPC 或契约版本。

这些说明改善模型生成，不是完整静态输出类型证明。现有校验和运行时缺失引用拒绝继续生效，不自动修补、降级或重试模型方案。此次真实同任务修改与相同原始需求首次生成均得到正确引用并完成本地两步执行；复杂动态输出、分支/循环、所有模型和完整 U04–U09 仍需独立验收，见[实施记录](design-implementation.md)。

## 本机任务接口 v1

以下为 Renderer/Host 白名单 IPC，不作为平台 API：

| 方法 | 请求/作用 |
| --- | --- |
| `task.create` | 可选 flowId；关联存在的已保存流程，或保留一个新流程 ID，创建内容 revision 1 |
| `task.list` | 返回本机任务概览；没有任务时为空，不用示例填充 |
| `task.detail` | id；返回任务、当前关联流程、最新提案、当前生成状态与宿主计算的差异 |
| `task.save` | id、revision、description、context、answers；严格比对 revision 后保存，递增内容 revision；修改取消该任务的在途生成 |
| `task.generate` | id、revision、provider、model、reviewed:true；显式确认当前上下文和供应商后启动一个生成请求，立即返回任务状态，详情轮询获取结果 |
| `task.cancel` | id；取消本次生成，保留描述和已采纳流程，不创建运行、不自动重试 |
| `task.adopt` | id、revision、proposalId；再次校验内容 revision 及基线流程/绑定摘要，原子保存流程和采纳记录 |
| `task.reject` | id、revision、proposalId；放弃提案，保留原流程 |
| `task.undo` | id、revision；撤销最近一次 AI 采纳，须当前流程/绑定仍与采纳后摘要一致，否则拒绝覆盖手动编辑 |

文本上下文最大 20 项，每项文本最多 50,000 字符，总文本最多 200,000 字符；描述最多 20,000，补问答案最多 30 项且单项 3,000 字符；请求仍受 2 MiB IPC 限制。未知字段拒绝。[本机附件协议 v1](task-attachments.md) 定义系统选择、加密副本和独立图片输入，所有已选资料共同计入预算。应用来源仍需独立协议，不能以可填写路径获得任意文件读取。

宿主构造后的规划上下文与基线流程合计限制 2 MiB，完整模型提案限制 1 MiB；超限保留原草稿并提示缩小本次修改范围，不静默截断 JSON。供应商适配器以 `resultJson` 字符串信封承载完整结果，解析后执行规划 Schema 及语义校验，避免把不完整片段交给执行层。

## 并发与持久化

使用既有加密 documents，增加 `ai-task` 类，不修改 SQLite 结构。任务记录生成 requestId、内容 revision 和基线摘要；提案 ID 由宿主产生。摘要包含当前流程与本机绑定，供本机冲突核对，不发送绑定中的路径或凭据值给模型。

模型调用通过现有 AIProvider 明确选择 provider/model；不静默切换。开始调用、等待凭据、收到结果、采纳前均核对当前身份与 revision。重复生成不并行覆盖；取消、修改、关闭、休眠或重开后的迟到结果不能恢复已取消的请求。退出/休眠主动 abort；重开把未完成生成标为已取消，不继续请求。失败保留原描述和已采纳流程，错误脱敏，不持久化 Key。

提案只存待审结果。宿主从完整旧/新流程按稳定节点身份计算新增/删除/修改/移动和字段原值/新值，包含参数、能力和资源需求变化；不信任模型自述的差异。采纳与撤销在一个 Store 事务中更新流程和任务，写入失败保持原版；已执行版本、计划和运行快照从不更改。采纳保留既有资源绑定，不根据模型文本添加路径、凭据或动作授权。资源尚未绑定时由运行前检查阻止执行。

2026-09-22 网页对象选择沿用规划格式 1.0，采用独立的[本机来源接口与生命周期](task-web-target.md)。元数据由宿主从受控网页取得，普通上下文不能冒充已选目标，采纳后执行继续复核。

## 验证边界

2026-09-22 [理解页输出选择](task-output-selection.md)通过系统目录选择器独立取得输出位置。采纳仅合并宿主保存的 `task_output` 目录绑定，模型不能提供本机路径；文件名与同名规则进入规划、版本和执行复核。

已采纳流程的下一步使用 [试运行前检查](run-review.md)，确认绑定固定版本并由宿主创建唯一 Run；规划与采纳本身不承担运行授权。

失败网页目标的修复使用 [目标修复接口](task-target-repair.md)，由原生拾取提供来源、宿主限制目标差异；普通任务生成不能伪造该修复依据。

清单、图与长流程中的 [AI 单步修改](ai-step-edit.md) 使用本机 scope 扩展，宿主限制实际修改范围，原任务描述和完整流程保持关联；单步采纳不自动执行。

必须覆盖：补问/方案/不支持的正反例，取消和迟到结果，失败保留草稿，重复生成，凭据等待期间修改，手动编辑/绑定变化冲突，修改采纳/拒绝/撤销，存储失败回滚，重开不重试；新 Run 数在规划操作中必须始终不变。真实模型、选择上下文、Figma 页面、同一流程清单/图、来源返回和真实执行另行验收；mock provider 通过不能写成 DeepSeek 实接完成。

### 2026-10-08 完整方案的生成预算与失败原因

完整流程方案包含嵌套分支、循环、引用和完整 Schema，采用宿主内置的规划预算：最多 16,384 个输出 token、单次请求最多 120 秒。通用 AI 请求仍为 4,096 / 45 秒；预算不由 Renderer 或模型输出指定，不增加 IPC 字段，不改变所选供应商、模型或思考模式，也不自动重试。较长预算可能增加生成等待及实际 token 用量，取消仍沿用原 AbortSignal。

只有供应商声明结果完整才解析和校验提案。长度/上下文限制、内容过滤和推理资源中断分别给出固定中文说明，其他不完整回复保留通用错误；不把供应商正文、凭据或未完成方案写入错误提示。DeepSeek 的 finish_reason 定义及 max_tokens 约束以 [官方 API 文档](https://api-docs.deepseek.com/api/create-chat-completion/) 为依据；长度原因不能细分为输出上限还是上下文上限。现场首次分支方案只保存了“AI 返回未完成结果”，不能倒推其具体 finish_reason。实现及人工结果另记设计实施记录，不能据预算增加宣布复杂规划已验收。

### 2026-10-08 采纳后摘要（本机任务详情 v1 扩展）

为画板100的采纳后说明，任务详情可增加可选 `adoption` 对象；它是本机只读投影，不进入公共FlowDefinition、规划输入或导出包。字段为 `version:1`、`created`（采纳前没有流程）、`stepCount`（发生差异的不同步骤数）、`steps`（最多前三个发生差异的步骤，按宿主差异顺序，含 `id`、`name`、去重的 `kinds` 数组）、`flowFields`（发生变化的流程顶层字段）。`kinds` 只取 `added`、`removed`、`changed`、`moved`；`flowFields` 沿用差异定义中的name、description、parameters、requiredCapabilities、sourceTemplate。步骤列表可能被摘要截短，stepCount始终是完整数量，界面明确省略数量，不把前三项当作全部差异。

宿主仅在当前流程存在且整份流程/绑定摘要与已保存undo.afterHash一致时返回；从undo.before及当前流程计算，不信任模型summary、不返回旧绑定或额外文件内容。不新增SQLite字段或历史记录，不保留模型回复副本；已有加密采纳/撤销数据直接生成同一投影，重开不需要迁移。撤销后或手动编辑使摘要不再匹配时省略，等待中或新提案优先展示对应提案，不能用旧摘要冒充新生成。

Renderer复用方案页既有FlowArk说明卡。单步骤修改显示当前对应步骤的名称与可读配置；多步骤或删除按差异数量、动作和名称说明，并标注顶层变化。只能在无待审提案、当前详情revision一致且没有未保存输入时显示采纳摘要；初次采纳与修改采纳文案区分。采纳摘要不是运行成功证明，查看/重开/撤销不创建Run。

这是当前开发客户端本机接口的可选返回字段扩展，消费者更新类型和渲染，不新增请求方法或执行权限；公共契约仍为0.16.0。缺少摘要时使用当前方案通用说明，不新增旧版本迁移路径。规范完成不代表已实现，实际实现与真实宿主核对见实施记录。


### 2026-10-08 拒绝提案后的保留状态（本机详情扩展）

`task.reject` 保留原有流程及最近采纳的撤销数据，并在已有加密ai-task文档内保存本次拒绝标记：任务revision、当前flowHash、当前requestId。标记不包含提案正文、输入副本或凭据，不新增SQLite表/列，不迁移旧记录。旧任务没有标记时不能推断曾经拒绝。后续新请求以requestId隔离，修改以revision隔离，手动修改流程/绑定以flowHash隔离。

任务详情增加可选 `proposalRejected:true`：仅当拒绝标记的revision、requestId、flowHash均匹配当前任务与流程、无提案且状态为draft时返回。标记留在宿主，不投影到任务列表或公共FlowDefinition。保存新要求、开始新请求、采纳、撤销或流程/绑定变化后不展示先前拒绝结果；不新增请求方法、模型调用或Run。Renderer在当前详情、无未保存修改的方案页优先显示“本次提案未采纳，当前保留已有草稿”，不能用更早的采纳摘要回答本次被拒绝的要求；撤销入口仍针对最近一次已采纳版本。

修改页同时显示当前任务修订号，与右侧已保存流程来源一致；修订号不是新的Run或历史运行版本。公共契约保持0.16.0，消费者采用本机可选返回字段。规范完成和真实拒绝/重开证据分别记录。
