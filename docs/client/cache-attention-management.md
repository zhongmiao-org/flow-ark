## 缓存边界与使用流程

本地设置 → 缓存与调试文件 → 扫描 → 核对分类、用途、实际路径、文件数量和占用 → 清除所选 → 在准确逐文件清单上确认。取消预览不删除文件。已结束且有登记的调试临时文件、日志、性能采样、测试副本和未引用编译残留才可选择。正式实例、流程、Skill、凭据、登录态、业务目录、外发账本、正式备份、用户导出和按运行产物不纳入此入口。

扫描可见调试目录、系统临时目录、已知工作目录输出和本实例编译目录。/tmp 与 /private/tmp 按真实路径合并。系统临时根目录的通用授权不构成所有子文件的业务归属证据，具体文件与业务子目录引用仍受保护。旧文件不能仅凭 flowark 文件名前缀判定安全；未经确认的项目显示“待确认”，先打开位置核对来源及用途，再显式登记。含备份或导出的未登记目录保守保护。受保护引用、链接根目录、特殊文件、其他用户文件和无法复核活动占用的项目不提供清理。

执行前再次核对整个项目的路径、文件身份、内容清单、引用和活动占用，逐文件 unlink、逐目录 rmdir，不遍历链接目标、不使用可变目录的递归删除。路径或内容变化跳过；权限失败保留剩余文件并提供打开位置，不尝试提权。清理结果持久保存，调用结果未知时读取已有结果，不重新删除；重开后上次 pending 标为中断，不自动继续。已删除文件的分配占用与磁盘可用空间变化分别展示，避免将其他应用或系统的磁盘变化当成清理成功数量。

后续可保留证据统一在“~/FlowArk/调试文件”，设置只选择用户主目录下的本机专用位置，不写入文稿、桌面或 iCloud 目录；旧位置只读扫描，不自动搬移。本轮按用户要求将新建的调试资料由文稿实际迁到 ~/FlowArk/调试文件，正式业务目录不移动。调试位置配置本身不是缓存。应用会话诊断与崩溃目录、开发启动器均登记目录身份、用途、分类、进程和结束状态；保留证据等待显式清理，成功任务的纯临时目录及时回收。使用 `scripts/debug-launch.mjs` 收集应用日志；既有桌面验证启动器继续串行、检查遗留锁与桌面主进程，不关闭用户实例以抢占测试。

编译文件按全部保存文档、固定快照和本次会话中的准备引用保护；清理期间阻止新运行准入，避免正在准备的脚本被删。扫描只在用户点击时进行，不加入启动或轮询热路径。保护引用的解密结果按本进程写入代数和 SQLite 外部写入版本复用，但每次操作重新解析真实路径，不能以旧符号路径放行。清理后的旧扫描项不可再次选择，需重新扫描。

## 待办边界与使用流程

待处理/已处理列表增加复选框、选择计数、全选当前筛选结果与批量删除。跨页范围明确显示，每页 30 条，切换状态、类型或搜索清空选择。删除仅写可选 deletedAt 标记，记录与原 dedupeKey 保留；普通 Bootstrap 列表和未读统计移除软删除项。回收站提供单条及批量恢复，保留原 read、answered、time 等字段，不提供自动永久清空。

全部已读由服务端固定当前工作区所有未读目标，覆盖搜索和分页之外记录；预览之后新到提醒不进入集合。批量移入、恢复也固定明确 ID 集合，提交事务中逐条复核。服务端从真实等待请求表判断是否仍在等待回答，删除和已读均跳过并报告数量；已处理/超时后可删除。失效请求恢复不会进入真实等待表。已读、删除或恢复都不批准请求、不取消运行，不修改原运行、外发意图和去重记录。同一 dedupeKey 在回收站仍命中旧记录，不重新生成。
