# 本机计划显式更新

2026-09-20。补齐架构要求的“计划固定引用原版本，直至用户显式更新”。0.1.23 界面只有创建与启停，0.1.24 增加更新入口；实际源码、包与安装验证分别见[验收记录](acceptance.md)。

## 界面与行为

每个计划提供内联编辑，修改间隔分钟数和时区。间隔保持整数 1～525600 分钟；时区使用当前 Intl 支持的有效标识，例如 Asia/Shanghai，展示按该时区格式化的下次执行时间。P1 仍是间隔计划，时区不将其变为某地每日固定时刻或 cron。

默认保持原固定版本。用户主动勾选“采用当前已保存的流程版本”后才重新预检并固定已保存的流程、绑定和脚本依赖；界面展示对应流程名称和保存时间。编辑器尚未保存的草稿不被采用，取消编辑不改变计划。

更新保留计划 ID、流程 ID 及启用/暂停状态，不创建 Run。保存后以保存时间加间隔重新计算 nextAt；暂停计划只显示暂停状态，不把 nextAt 当成已安排执行。更新只影响今后的触发，已经排队或活动的 Run 保留原不可变快照。更新周期时不自动读取新草稿或替换脚本依赖。

保存期间禁用重复操作；计划被另一操作暂停/启用/更新时，原编辑请求拒绝覆盖。采用新版本期间若已保存草稿变化，也拒绝旧请求并要求重新核对。拒绝、预检失败或无效时区不改写计划，不启用暂停计划，不运行流程。

## 本地接口与兼容

新增 Renderer 白名单 `schedule.update`，字段严格校验：

- `id`：现有计划 ID；`revision`：编辑打开时的计划 revision，旧记录缺失时显式传 null。
- `intervalMinutes`：整数 1～525600；`timezone`：非空有效时区标识，最多 100 字符。
- `adoptLatest`：布尔值，必须明确给出。false 保留原 versionId；true 还必须提供 `flowUpdatedAt`，与已保存流程记录的 updatedAt 一致。

宿主在异步预检前后检查计划 revision；还比较读取时的计划内容，防止实际 tick 改变 nextAt 后被旧异步更新覆盖。采用新版本时校验 flowUpdatedAt，并在预检后确认完整流程记录未改变。通过后同步保存版本与计划，生成新 revision，返回更新后的 Schedule。计时器并发触发的旧版本 Run 仍保留；未完成准入由既有 revision 复验拒绝。

`schedule.save` 明确仅创建新计划，不再接受此前未被界面使用的可选 id；现有创建调用不变，更新统一走带 revision 的新方法。`schedule.toggle` 保持已有语义，启停不改变固定版本。以上仅为同包发布的本地 IPC，不改变公共契约 0.7.0、计划持久化结构或数据库版本。旧缺 revision 的计划可读取和首次更新，成功后写入 revision；旧 Run 和固定版本不迁移、不重写。

## 验收

- 真实宿主验证保留旧版本与主动采用新版本、暂停状态不变、活动/排队快照不变、无效输入和预检失败无改写；延迟预检期间的启停、另一更新、真实调度与草稿变更不能被覆盖。
- 界面验证创建、编辑、取消、错误提示、明确选择新版本、暂停后更新、保存重开、时区时间展示与窄窗口/右侧网页布局。
- 内置本地表单实际执行旧版本和更新版本，核对虚构输入及 1920 CSS 像素。真实分钟计时沿用已有回归，不以修改测试时钟冒充实际计时证据。
- 新安装包、安装路径及治理/客户端 PR 分别记录；不推进招聘、真实 AI、外部浏览器或在线调度。
