# 本机计划显式更新

2026-09-20。补齐架构要求的“计划固定引用原版本，直至用户显式更新”。0.1.23 界面只有创建与启停，0.1.24 增加更新入口；实际源码、包与安装验证分别见[验收记录](acceptance.md)。

## 界面与行为

每个计划提供内联编辑，修改间隔分钟数和时区。间隔保持整数 1～525600 分钟；时区使用当前 Intl 支持的有效标识，例如 Asia/Shanghai，展示按该时区格式化的下次执行时间。P1 仍是间隔计划，时区不将其变为某地每日固定时刻或 cron。

默认保持原固定版本。用户主动勾选“采用当前已保存的流程版本”后才重新预检并固定已保存的流程、绑定和脚本依赖；界面展示对应流程名称和保存时间。编辑器尚未保存的草稿不被采用，取消编辑不改变计划。

更新保留计划 ID、流程 ID 及启用/暂停状态，不创建 Run。保存后以保存时间加间隔重新计算 nextAt；暂停计划只显示暂停状态，不把 nextAt 当成已安排执行。更新只影响今后的触发，已经排队或活动的 Run 保留原不可变快照。更新周期时不自动读取新草稿或替换脚本依赖。

保存期间禁用重复操作；计划被另一操作暂停/启用/更新时，原编辑请求拒绝覆盖。采用新版本期间若已保存草稿变化，也拒绝旧请求并要求重新核对。拒绝、预检失败或无效时区不改写计划，不启用暂停计划，不运行流程。

## 本地接口与兼容

新增 Renderer 白名单 `schedule.update`，字段严格校验：

- `id`：现有计划 ID；`revision`：编辑打开时的计划 revision，旧记录缺失时显式传 null。
- `intervalMinutes`：整数 1～525600；`timezone`：非空有效时区标识，最多 100 字符。
- `adoptLatest`：布尔值，必须明确给出。false 保留原 versionId；true 还必须提供 `flowUpdatedAt`，与已保存流程记录的 updatedAt 一致。

宿主在异步预检前后检查计划 revision；还比较读取时的计划内容，防止实际 tick 改变 nextAt 后被旧异步更新覆盖。采用新版本时校验 flowUpdatedAt，并在预检后确认完整流程记录未改变。通过后同步保存版本与计划，生成新 revision，返回更新后的 Schedule。计时器并发触发的旧版本 Run 仍保留；未完成准入由既有 revision 复验拒绝。

`schedule.save` 明确仅创建新计划，不再接受此前未被界面使用的可选 id；现有创建调用不变，更新统一走带 revision 的新方法。`schedule.toggle` 保持已有语义，启停不改变固定版本。以上仅为同包发布的本地 IPC，不改变公共契约 0.7.0、计划持久化结构或数据库版本。旧缺 revision 的计划可读取和首次更新，成功后写入 revision；旧 Run 和固定版本不迁移、不重写。

## 验收

- 真实宿主验证保留旧版本与主动采用新版本、暂停状态不变、活动/排队快照不变、无效输入和预检失败无改写；延迟预检期间的启停、另一更新、真实调度与草稿变更不能被覆盖。
- 界面验证创建、编辑、取消、错误提示、明确选择新版本、暂停后更新、保存重开、时区时间展示与窄窗口/右侧网页布局。
- 内置本地表单实际执行旧版本和更新版本，核对虚构输入及 1920 CSS 像素。真实分钟计时沿用已有回归，不以修改测试时钟冒充实际计时证据。
- 新安装包、安装路径及治理/客户端 PR 分别记录；不推进招聘、真实 AI、外部浏览器或在线调度。

## 2026-09-22 Figma 计划工作台与记录读取 v1

本节替代上方内联编辑布局，消费 Figma 本机计划 `1:3673`、创建计划 `2:3431`、计划状态 `2:4526` 与统一离开保护。1440 页面采用 672/456 双栏、24 间隔、最小高 676；左栏是真实计划卡片，右栏展示所选计划编辑或明确创建表单，紧凑窗口纵排。状态目录只定义实际状态的展示，不成为虚构状态切换菜单。

打开编辑默认保留原固定版本，不勾选采用新版本；展示原版本的真实保存时间与版本标识，不能拿当前流程保存时间冒充原快照时间。创建默认 60 分钟、系统时区，明确选择已保存流程/入口、勾选固定内容后才创建并启用，首次执行在间隔之后。选择新流程需重新确认固定内容。全局创建使用选择时的 `flowUpdatedAt`，若真实保存内容在异步预检前后变化，拒绝创建。模板入口来源创建继续遵循 [实例编辑规范](template-instance-editing.md) 的严格修订校验。

编辑/创建、切换计划、取消、侧栏、重新学习与应用内返回共用三选离开保护；无更改直接离开，有更改保存成功后到原目标，失败/冲突保留输入，忙碌期间不能重复提交或替换离开目标。查看计划记录与活动运行属于子任务，保留同一计划草稿、滚动和焦点；从运行详情去其他模块仍经过原计划草稿守卫。明确放弃并重新编辑才采用新计划及流程基线。启停不隐式保存编辑草稿，若改变当前计划需先通过其离开保护。

新增只读本地 IPC `schedule.inspect`：严格对象 `{ id, cursor? }`，id 为非空至多 100 字符；cursor 为严格 `{ scheduleId, ceiling, before }`，scheduleId 必须与 id 一致，ceiling 为非负安全整数，before 为正安全整数。首次以实际 `schedule-log` 最高位置为 ceiling，按插入位置倒序扫描，每页最多 20 条当前计划记录，回复 `nextCursor` 或 null。后续页只读该 ceiling 内记录，新的记录仅在明确刷新/重开记录时出现；其他计划的记录不会混入。

回复包含当前 `plan`、`version`（仅 id/name/savedAt，缺失则 null）、`records`、`nextCursor` 和当前 `activeRun`（仅该计划非终态运行的 id/name/state，缺失则 null）。记录只含位置、归类 kind（occupied/missed/failed）、脱敏 reason、真实 time/from/to；应用重开、系统恢复或时钟间隙归类 missed，不能凭单条日志推算错过次数。缺失时间显示未报告，不编造时间。固定版本正文、脚本、绑定、密钥和文件内容不返回。读取无写入、不触发运行、不改变计时；计划不存在明确报错，不按名称替换。活动运行按钮只打开回复中的真实 Run，并再次核对运行 id 与 scheduleId。记录回复及后续游标也必须属于当前计划。记录与运行详情的读取失败独立于计划编辑反馈；刷新记录清除旧详情错误，记录读取失败保留上次内容并暂时禁用活动运行入口。只读等待中可返回计划，离开后忽略迟到回复，不重开记录或跳入运行详情；不取消实际运行。

`schedule.save` 新增可选 `flowUpdatedAt`（ISO datetime）。提供时在预检前校验保存时间并捕获整个流程记录摘要，预检后再次核对摘要；拒绝时不产生版本或计划。此字段与 `templateSource` 可并用，各自都必须匹配。不改变已有 schedule.update/toggle 的语义、持久化结构、公开流程契约、SDK 或 ZIP 版本。

验收需覆盖两栏/紧凑布局、三选离开/失败/忙碌/焦点、切换计划与来源恢复、固定版本和当前保存版本的区分、只读记录跨页隔离/刷新/缺失来源、真实占用与错过记录、当前活动运行返回以及预检期间真实竞争保存。分钟计时与内置网页执行沿用真实计时回归，不能以注入日志或改时钟代替。

## 2026-10-12 中文字段校验与错误定位

计划创建/编辑与模板入口创建共同使用 shared/schedules 的 scheduleTiming 校验。间隔不是整数1–525600或时区无效时，Ant输入显示中文原因与aria-describedby关联；表单关闭浏览器默认提示，提交保持原输入、不写入计划。首次和重复保存聚焦第一个错误字段；修正间隔后仍无效的时区成为定位目标。只有本地字段校验错误使用字段定位，来源失效及其他失败仍显示总错误。保存离开失败留在三选弹窗，继续编辑后恢复字段。

本轮只改变Renderer交互，不修改计划契约、宿主、计时或固定版本语义。页面内存验证、原生修复前证据与仍缺失的修复后真实调度分开记录于[验收](acceptance.md)。
