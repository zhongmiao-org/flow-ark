资源选择器增加「复用已保存 Skill」。用户通过系统文件选择器明确选择 `flowark-skills/<key>/<versionId>/manifest.json`，不扫描目录。完整三文件经现有普通文件、有界、无符号链接、目录身份与摘要读取器验证；标题、确认时间、版本、父版本、摘要、全文、结构化资料与来源展示给本人。摘要证明文件一致性，不是作者身份签名，须本人明确核对来源与内容。

本地 UI IPC（不提供给模板 Worker，不改变 Skill v1 文件或公共 SDK）：

- `skill.restore.preview` 严格请求 `{path}`，路径来自本人选择；只读取上述固定布局的确认清单和同版本三文件。成功返回 `{token, workspace, version, alreadyRegistered, headPreserved}`，`version` 沿用 `SkillVersion`，含完整内容。随机 token 绑定准确工作区身份、版本、当时本机 head，10 分钟有效，最多保留 20 项；不写文件或数据库。
- `skill.restore.confirm` 严格请求 `{token, requestId, reviewed:true}`。按工作区与 key 串行，重读完整原文件并比较工作区身份、全部内容及原 head；变更或过期要求重新核对。事务只登记原版本和显式复用凭据，不改原文件、确认时间、版本 ID、摘要及父版本。已有当前 head 保留；没有 head 时将本人选择版本设为首次 head。已有同版本不重复登记，冲突停止。请求记录以 token 摘要关联 requestId，重复确认先核对原结果，不能重复登记或改变其他绑定。
- `skill.restore.cancel` 严格请求 `{token}`，撤销活动预览；取消、失败或迟到返回保持原资源绑定。确认成功后只更新当前表单，仍需保存资源才生效，不自动运行。

外部复用登记单独记录来源为本人选择的确认文件，不伪造原生成流程或 Run。历史证据仍保留原内容，只表明外部文件中的原始引用，不能冒充新客户端拥有这些历史。只登记所选版本，不扫描导入所有同目录历史；后续明确选择其他版本可再逐项复用。用户已有版本优先；无可核验版本才进入个人蒸馏模板及本人 API Key 访谈，费用由用户承担。

验证至少包括：空白列表正常选择及本人核对、同版本重复复用、原文件与确认时间不变、取消、无效或摘要不符文件拒绝、过期/文件变化保留绑定、已有 head 不替换、未保存不运行和无 AI/外发调用。当前设计与契约先行，不记为已实现或首次使用通过。
