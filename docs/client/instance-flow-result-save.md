## 实际缺陷与既有契约

“我的流程 → 原实例每日入口 → 完整脚本编辑器 → 检查语法 → 保存并返回”已通过语法检查，却报“结果绑定目标已变化，请重新读取后保存；原绑定保留”。Runtime.saveFlowResults对任何已绑定前次结果的模板实例都直接拒绝，未区分修改脚本与修改来源。saveFlow本身已经限制实例绑定和入口参数必须逐字保持，模板保存也明确保留实例内流程修改，因此这是现有能力接线遗漏。

复用已发布0.48.0的flow.save、实例结果选择/CAS与固定来源机制，不新增节点、IPC或数据库协议。没有新增页面、按钮、确认流或文案，沿用既有Figma的流程/脚本保存与实例资源页；修复既有“保存”行为，不改变设计交互。结果来源的选择或解除仍只能在实例资源页完成，作者来源租约路径保持。

## 修复约束

- 原实例流程保存必须携带准确updatedAt，整个bindings（含模板身份、资源、配置、授权与结果引用）与保存前一致，且不携带结果选择许可。入口参数和来源表达式继续走原禁止变更守卫。
- 从原记录推导本实例结果核对目标，按当前实例修订、完整来源副本与声明重新准备核对；不得把模板入口伪装为作者副本，也不清除绑定规避检查。
- 异步核对后，在同一Store事务内再次检查原流程指纹、实例当前性和来源证明，再保存流程草稿。并发修改、来源撤回、目标或Schema变化仍拒绝，旧绑定保持。
- 仅更新当前流程草稿；原Run、固定脚本、状态、操作账本、额度、账号来源和计划不写入或重建。不扩大资源/权限，不复制实例，不把unknown改成功。
