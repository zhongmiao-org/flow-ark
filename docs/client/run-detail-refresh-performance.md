# 真实运行详情刷新开销

## 2026-11-02 只读对象复制开销

安装版真实连续沟通期间取得 30.14 秒宿主调用栈：18.52 秒为空闲；`Store.get → scriptRequest` 的结构复制自耗时 431 毫秒，`flowCatalog → bootstrap` 为 376 毫秒，另有 Worker 读取路径 163 毫秒。这些局部耗时不能解释全部 CPU 峰值。已排除“每次浏览器读取都会编译 Schema”的推断：相应校验位于运行前检查，不是每次 SDK 读取路径。

本轮客户端优化仅增加宿主内部的递归冻结只读视图：模板 SDK 读取当前运行快照、首页序列化流程目录时复用不可修改的 JSON 对象，避免先复制整份对象、随后又经 IPC 复制一次。普通 `get` 和 `flowCatalog` 仍返回独立可变副本；只读视图不能用于编辑、写入授权或代替实时实例、资源及权限复核。

运行快照视图每次仍查询并逐字比较完整当前密文；目录保持原事务、外部连接变更检查和缓存容量限制。修改、删除、回滚、外部替换、缓存淘汰或重开均不得采用旧对象；冻结必须覆盖嵌套对象和列表。只读接口不修改数据库、快照、模板 ZIP、公开 SDK 或授权规则，不增加界面状态，因此沿用现有 Figma。

先执行类型、构建、格式及治理检查，不新增或运行单元测试。使用隔离数据的手工核对覆盖副本可变性、深层冻结、当前密文变化、事务回滚和目录失效；在普通 UI 核对编辑、保存、重开与运行推进。安装前等待活动业务安全结束，保留原工作区、全部外发历史与客户端已有未提交改动。当前为先行约束与待验证优化，不将调用栈、代码或本地检查当作 CPU 修复、业务上限或最终 ZIP 交付。

2026-10-23，继续北京 BOSS 真实打招呼时，观察到运行详情页 Renderer 约 58% CPU、宿主约 65%；切到开始任务后宿主降至约 6%。这只是现场对照，不能将全部耗时归因于刷新。代码确认详情每 1.5 秒读取完整事件、完整结果和已核验容量，终态后仍持续；详情自身也在终态后每秒重绘。

不增加页面、控件或交互状态，不改变现有 Figma 结构；只调整已有数据刷新生命周期。按当前阶段执行类型、格式、构建和打包，不新增或运行单元测试。安装前等待活动批次结束，使用原数据目录重开，继续通过客户端真实运行验证。当前当天完整介绍回执 9 条，1 项聊天未就绪保留未知；网站 150 次弹框和 2–3 小时效率目标均未通过。
