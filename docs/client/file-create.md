# 新建文本文件

2026-09-22。对应 Figma [第一次实操 23:2106](https://www.figma.com/design/sVciNUZHG9yx81gCpYzjH9?node-id=23-2106) 中“保存为文本文件 · 新建文件，不覆盖”。本规范为通用文件能力，不在执行核心引入教学或网站业务分支；教学进度与真实运行的连接另行实现和验收。

## 节点与校验

同名自动加序号另由 [file v4](file-create-numbered.md) 定义；本文 file v3 保持同名停止，不把两种策略混为一谈。

契约 [0.11.0](../../contracts/v0.11.0/README.md) 新增 `file` v3，`operation: create`。`binding` 为本机逻辑输出目录，`name` 是目录内相对文件名或既有值引用，`content` 是文本或既有值引用。流程和模板入口必须声明 `file-create-v1`。不支持的消费者拒绝执行，不以 write 降级处理。

解析后的文件名必须为非空安全相对路径，不含绝对路径、反斜杠、冒号、空路径段、`.`、`..` 或控制字符。允许已存在的子目录，不隐式新建目录。目录与符号链接仍遵守已有授权范围。内容仅接受字符串，空字符串有效，不把对象、数字、布尔或 null 隐式序列化；编码为 UTF-8，上限 10 MiB，按编码后的字节计算。静态字面量及可解析参数先校验，步骤引用在实际执行前再次校验。

## 提交与失败

先在目标目录以独占方式写入本次临时文件，再以原子的不覆盖操作提交目标名称；不能以“检查不存在后 rename”代替。已有普通文件、目录、有效或悬空符号链接都不能被替换。两个任务并发创建同名文件最多一个成功，失败的任务保留明确错误，不自动改名或重放。

临时写入或提交失败只清理本次临时文件，已有内容保持不变。成功提交后才登记产物并保存现有规则要求的不可变副本。如果产物登记失败，已经创建的外部文件保留，不自动删除或宣称整个运行成功；再次运行必须重新检查同名冲突。Run、计划与草稿隔离规则不变，无 SQLite 或旧流程迁移。

## 配置与验收

沿用现有文件属性表单、目录绑定和值引用，新增“新建文本文件（不覆盖）”选项，显示文本限制；原写入选项明确可能覆盖。运行前检查与 AI 方案资源影响都显示只新建、同名停止，不把它写成可能覆盖。AI 输出完整流程仍需通过节点、能力和引用检查，规划本身不能创建文件。

验证包括文本精确字节和空文本、动态引用、非法内容与多字节上限、越界路径、普通文件／目录／有效及悬空链接、并发同名竞争、临时文件清理、失败不登记产物、登记失败不删除已提交输出，以及真实 Worker 与不可变 Run／产物副本。界面保存重开、切换操作及撤销还需实际验证。上述规范完成不代表首次教学完成。
