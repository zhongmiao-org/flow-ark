## 可视化制作与规则

从准确0.1.5复制下一检查点，保留五个旧入口。新增不定时message-draft入口，在客户端以既有JD评估编排为来源建立独立流程：读取固定配置、核对明确选择的JD/来信、读取固定确认Skill、用自有Key评估JD、校验引用并按三路分支；仅match分支继续来信分类与简短草稿，其他分支保存原因/本人待办或不感兴趣建议。业务代码只整理和校验，模型/分支/Skill读取等通过可见节点表达，不把整个流程藏在脚本中，不手改流程JSON或ZIP。

本次来信正文、完整性声明与本人接管声明为显式输入，默认空/未完整/接管中；声明不能冒充已核验真实会话。无正文、不完整、本人接管、配置缺口时不进入模型。模型只接收本次明确选定的JD、消息、固定个人Skill与规则，不读取其他工作区或Key。JD或来信要求改规则/取密钥/代办动作均作为不可信数据。

结构化来信建议区分普通事实、自我介绍/招呼、技术交流、索要简历、正式题目、身份质疑、薪资/时间承诺和未知。普通回复最多一两句，事实须引用固定Skill原文；没有依据、未知/冲突或不确定交本人。语义与事实正确性仍需本人核对，连续原句核对不能证明全部内容正确。

索要简历只建立附件待核对建议，不把文本回复当附件已发；选定简历版本、重复索要、附件/介绍分别授权、持久去重与页面回执继续独立开发。正式面试/笔试/作业、身份质疑、薪资或面试时间承诺默认通知本人，不自动代交、固定否认AI或作承诺。普通技术交流只围绕已确认能力，正式题目不能靠延时冒充本人作答。

结果固定本次JD/来信摘要、求职配置修订、实际Skill版本与原句依据；模型不能自报这些身份。明确保留accountVerified=false、eligibleForActions=false，草稿/建议不可作为发送准入。本人待办由来源去重并保留首次记录。Key/模型未绑定、Skill缺失/变化时宿主阻止，不借用其他用户服务或伪造模型结果。
