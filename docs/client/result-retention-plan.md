## G1必须固定的保存语义

采用本次Run内内容寻址的无损完整值复用方向，不能跨Run或跨工作区借用引用。候选以规范化JSON子树和有界字节叶保存相同内容；数组顺序、对象键/值、中文、转义、长文本和原完整摘要均须可复原。当前`digest`使用排序键的规范JSON，而`TypedResultMeta.bytes`是完整值的UTF-8 JSON大小；G1须明确两者口径，不能把摘要字节和原完整值字节混淆。

1. 每条原逻辑结果仍独立计数，保留精确Run/节点实例/type/完整值摘要；复用不合并不同节点的身份、来源、事实确认或动作回执。
2. 实际保留预算计入本Run全部唯一内容、组成引用、根记录和索引；已保存与未消费预留共同占用。不能只算叶正文、把回执中的完整副本搬到另一命名空间后不计，或把数据库大小当此预算。共享块按Run唯一身份只计一次。
3. 新预算政策须版本化，固定在新Run快照；现有1000项限制保持。8MiB的旧“逐条完整值累计”与拟议“唯一内容及结构保留”属于不同语义，不能静默更换旧Run规则，也不能用界面设计数值证明新规则足够。最终常量、编码阈值、最大深度/扇出/节点数、字节上界、重建和摘要关系由正式机器契约固定。
4. 内容、引用、根和元数据索引同事务保存。先校验完整业务结果，再取得精确准入；事务失败不得登记半条结果、悬空根或可执行许可。复用命中仍须校验原内容、字节、类型和拥有者，不按哈希相同直接相信记录。
5. 读取按准确Run与条目索引定位，经有界重建核对完整摘要/大小，再执行原类型、固定来源、当前权限和终态规则。循环、缺块、错拥有者、摘要/索引不符或重建超限整次拒绝；不返回已读前缀给模型或后续动作，不自行重建旧状态。
6. 当前原值结果、写入回执及会话/来源归档属于不同事实记录。不能只优化`typed-run-result`就把其他完整副本漏出保留预算；G1须逐类列出纳入范围及独立已有预算，拒绝“引用指向无预算副本”的绕过。跨类复用不得削弱不可变回执、隐私归属或保留期限。
