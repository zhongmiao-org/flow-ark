# 桌面选区流程与候选采纳 v1

2026-09-23。承接修改条件检查，把已核对的候选保存为同一任务的流程草稿，进入已有清单/流程图、步骤详情与运行检查。对应应用方案、修改对照和统一方案页面；完整确认执行及结果仍以 U12 为目标。

## 公共步骤

契约 0.14.0 增加 `{type:"desktop",version:1,operation:"replace-selection",target,text}`。target 为逻辑标识，text 只能是已确认的非空纯文本常量；客户端限制 20000 UTF-16 单元。必须声明 desktop-selection-v1。执行语义为同一窗口同一原选区的单次替换及按原起点/新文本长度回读；不支持动态文本、窗口查找表达式、键盘或剪贴板回退。不得循环重放同一次选区授权。

## 本地采纳

`desktop.plan.adopt` 在生成/检查身份字段之外要求 `adopted:true`，Renderer 不提交正文。宿主仅使用仍有效且来自同一任务修订的最新候选，重新进行修改条件检查，两项能力均 available 方可采纳。采纳只保存方案，**不授予修改权限或创建 Run**。检查期间候选、任务、来源或草稿变化时拒绝。

首个增量只接受尚无流程、其他提案、网页/工具/输出绑定的当前任务，避免覆盖已有流程或混入其他执行对象。任务中的普通资料保留；保存后任务修订递增，清除临时候选。新流程只包含一个 replace-selection 步骤，目标 selected-text，参数为空；候选文字与源生成标识由宿主取得。保存流程和任务修订在同一数据库事务完成，既有加密存储继续生效。

FlowRecord 的本地 desktopTarget 保存 version、taskId、生成 requestId、observationId/windowId/previewId、expiresAt 及 sourceHash/replacementHash；不放入可导出 Flow。它只证明采纳时的来源，不延长原观察期限，也不是稳定原生绑定或执行授权。离开页面释放窗口后，草稿仍保留，但运行前必须取得有效窗口执行绑定。本文不定义跨重启原生引用恢复。

## 界面与执行边界

改动对照页条件均可用后提供“保存方案，继续核对”，明确保存不会修改文档。保存中禁用重复提交，失败保留对照与错误说明；成功进入现有任务方案清单及流程图。可读步骤显示替换文字、逻辑目标、回读语义和当前未开放的执行状态。保存后不自动运行、不静默重新生成文字。

首次消费者可只支持草稿采纳与查看，须在任何执行入口的共同 preflight 拒绝尚未接入的桌面执行；不能因为 Schema 接受节点而生成成功 Run。后续执行增量需定义确认、原生会话移交、Run 内授权消耗及写前持久记录/写后回读，沿用统一 Run 与不可变快照。真实文档修改、用户验收及 186 画板完成状态分别记录。

## 验证和发布

治理 PR 合并及不可变契约 tag 发布后，客户端固定采用 Schema/摘要并生成类型，不依赖父目录运行。此阶段不新增、不运行单元测试；类型、构建、格式及人工界面核对不替代真实原生写入验收。
