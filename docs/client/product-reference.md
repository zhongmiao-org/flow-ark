## 0.1.12 的实际差距

基于客户端 `7b3989e07ab8691807b0d8275bc3272b7407e806` 的代码和隔离安装版检查：

- 已有语义流程图、网页元素拾取、浏览器动作表单、保存重开及逐步调试。浏览器节点已能展示“填写 测试姓名”等名称，不应把这些当成尚未实现。
- 节点库只列节点大类。添加具体网页动作需要“浏览器—添加到主流程—操作下拉框”三步，没有按动作搜索。普通使用者仍要理解内部分类。
- 添加操作面向主流程末尾、所选条件分支末尾或循环体末尾；已有上移、下移、删除，但缺少明确的前后插入、复制和撤销入口。调整长流程费力。
- 浏览器常用配置已有表单，其他节点仍较依赖原始 JSON；变量没有统一的可读选择入口。定位信息应继续放在高级编辑中。
- 展开右侧网页后，画布宽度从约 656 缩到 334 像素，但保留旧平移，280 像素宽节点超出画布。手动 Fit View 可以恢复。在 1040×700 窗口，固定侧栏与画布最小宽度还会让主区域横向溢出。该问题已在独立临时数据的 0.1.12 安装版复现，尚未修复。

## 下一步实现与验收顺序

1. **编排与网页同时可用。** 修复打开、收起网页和调整窗口后的画布可见性及横向溢出。保持节点、当前配置和网页会话；尺寸变化不产生 Run 或页面刷新。验收普通与最小窗口，检查真实节点边界和实际网页显示，不以进程存在代替可用。
2. **直接选择具体动作。** 先提供打开网页、填写、点击、读取、等待、下拉选择、勾选和上传等可搜索入口。它们生成既有节点协议，不增加第二套执行语义；保留条件菱形、数据平行四边形等用户要求的流程图形状。
3. **低成本修改流程。** 让添加位置明确，逐步补前后插入、复制、移动与撤销。条件和循环内操作必须保持所属分支、引用作用域和持久化语义，不能用任意连线隐式制造回路。
4. **可读配置与调试结果。** 将常用参数、目标、前序输出引用做成表单；高级 JSON 仍可用。编辑草稿与不可变运行快照区分，继续和单步会实际执行网页动作，失败信息应能定位到具体步骤。

上述为待实现方向，不是本次新增功能清单。每项按实际变更范围独立验证和交付；不为了外观全面换图形库或复制另一产品的品牌界面。

编辑体验统一用本地复杂表单验收：从空白流程通过界面添加动作、拾取 input/radio/checkbox/select、填写虚构数据、绑定测试上传文件、保存重开、逐步执行、核对字段和提交回执；故意失效的定位应明确停止。只依靠导入预先写好的长流程跑通，不足以证明搭建体验通过。

当前继续暂停 BOSS/智联测试与 Codex 实接。自动录制、AI 生成整个流程、桌面/手机自动化、可复用子流程和在线模板商店均不纳入本次；已有路线图安排的能力沿用原阶段，其余需后续明确范围。后续若调整范围，先更新对应架构与契约。所有设计和验收 Markdown 仅在治理仓库维护。
