# 独立正文与管理字段的输入域候选

2026-10-21，未发布。接续[联合预算](joint-budget.md)，只修正准备输入时外壳额外收紧正文的问题，不修改0.51.0快照、数据库布局、安装版或公开模板，不取得来源证明、预留或动作许可。

## 固定捕获语法

管理结构与下列完整正文各自校验，不把整个复合对象重新当作一个单值序列化。路径使用JSON Pointer转义，数组下标是实际位置；固定语法由宿主实现，不开放给模板自定义绕过字段。

| 入口/域名                                 | 独立正文位置                                                                                                                                                             |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| captureProducerSchemas / producer-schemas | 根对象每个直接自有成员，每份完整Schema各一域                                                                                                                             |
| captureJointPlan / joint-plan             | completion.flow、completion.parameters；completion.producerSchemas每份Schema；pending每项及proposed内results每项output的value/schema、copies每项stages每项的value/schema |
| captureProposal / ledger-proposal         | values；copies每项value                                                                                                                                                  |
| captureActualCopies / actual-copies       | 每行value，根必须是最多8192项的普通稠密数组                                                                                                                              |

这四个函数只捕获固定数据域，不替代完整入口的字段、类型或业务关系验证。捕获后的数据仍须交给相应编译器/目录核对器，不能把任意额外字段或缺失字段当作合法输入。完整flow仍有自己的固定P1格式和8MiB/64层限制，Schema仍有自己的有限语法；不把它们的内部任意字段进一步拆开来放宽原格式。

每份正文独立沿用规范JSON的8MiB、262144次值访问、64层和128MiB累计子值序列化工作限制，取得完整规范副本和完整摘要。管理字段在正文位置仅放一个固定的sha256标记，再以同样四个限制核对管理结构；正文的内部层数不加到管理路径上。普通记录、原生稠密数组、自有可枚举数据属性和无循环限制保持，拒绝访问器、Proxy、符号、隐藏字段和特殊原型；原值中的普通自有特殊键不能被原型赋值吞掉。

除每域限制外，一次捕获固定累计正文规范字节最多128MiB、值访问4194304次、工作512MiB。这是候选输入准备总量，不是提高单值或保存额度，也不代表真实内存峰值/CPU承诺。正文先有界遍历自有数据成员、拒绝深层Proxy与访问器，避免计量和复制间可执行代理改变输入；每份正文计量后、克隆前先检查累计限额；管理字段的标点、键、标量和摘要标记按路径深度增量计入字节与工作，在继续保留后续分支前拒绝超限，末尾再完整复核。单次规范化、Schema代码生成/正则、捕获和校验仍须在未来消费者中受宿主期限及取消监督；此参考没有实现该运行环境。

返回value是深度冻结的完整自有副本，fingerprint仅绑定内容。令M为按固定路径把独立正文换成字符串`sha256:`加完整64位摘要后的管理结构，摘要输入字节严格为：UTF-8的`flowark-input-domains-v1`、NUL、上述准确域名、NUL、M的规范JSON。前缀不再包成JSON对象，避免重新引入一层；不是原复合JSON的摘要，不能沿用旧缓存。原文字、Schema、流程或管理字段任一变化都会改变对应指纹。输出不返回M作为私人资料预览，也不允许以摘要替代保存完整正文。

## 读写与联合预算一致采用

`scoped-ledger.mjs`是独立未发布的读写参考，存储布局沿用run-owned-results-v1，但不能据此宣称旧运行政策已支持新输入语义：

- verifyScopedCopies先核对自有目录/拥有者，逐行匹配完整实际正文的family、id、规范sha256/bytes，拒绝重复、缺少、额外或变化；成功返回同一份冻结完整副本及容量，不再对包含正文的整行调用单值canonical。输入仍须由宿主从同一稳定视图取得，函数本身不认证Store来源。
- proposeScoped先固定目录/拥有者，按固定域捕获完整变更；结果元数据、根/索引对应、原修订、逐副本CAS、排序、幂等及最终8MiB联合保留检查保持。正文不与values/其他副本合成一个单值域；结果仍仅是提案，原子事务与实际副本持久化必须由后续宿主完成。
- compileJointBudget使用相同捕获/实际副本核对和独立正文copyShape限制；planSha256来自joint-plan指纹。actualCopiesSha256仍是全部正文核对成功后准确已排序charge清单的规范摘要，保持其原定义。
- compileCompletionBoundary的producerSchemasSha256改为producer-schemas指纹，整份flowSha256仍是完整flow规范摘要。单份Schema证书及完整值摘要保持原定义。现有证书格式未新增字段，这个含义变化只发生在未发布候选，未来正式契约须一起固定。

固定输出校验的Schema引用图最长路径单独限制为256条边，Schema自身JSON及实际数据深度仍为64、结构定义最多4096。引用边与properties容器层次不是数据层数，不能误用64条Schema图边把实际可用数据缩至约一半。缓存仍保留完整后继高度，递归拒绝；这不是增加数据或保留额度。

未来正式版本须一起采用域语法、指纹、读写、联合预算与全部入口；不能只换预算却继续使用旧包装验证器，否则外发前证明与动作后保存不一致。旧0.51.0快照及消费者保持，发布前仍须完成受保护段、可信生产者/SDK来源、全部写入口与原子持有消费释放、失败/取消/unknown回执和运行完成观察。动态循环来源由后续[完整流程分析](flow-plan.md)接续，1000项硬限保持；不能把输入域修正当作完整G1完成。
