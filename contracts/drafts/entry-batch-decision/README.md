# 入口批次决策核心草案

2026-10-21，独立未发布草案，依据[连续有限批次](../../../docs/client/finite-run-continuation.md)的先行Figma和边界。当前只定义可移植结果字段声明、规范化决策和有限运行设置，以及不访问系统的字段关系参考；不定义任何已可调用的连续运行IPC，不更改已封存0.49.0，不被客户端运行时采用。

作者在本入口完整结果Schema中选择三个必需字符串字段。决策字段的枚举必须恰为`continue / complete / review`，UI分别展示“继续下一批 / 目标已完成 / 需要查看”；进度字段1–256个Unicode标量，说明字段1–1000个Unicode标量。三个路径独立、最多16层，逐层只能经过显式object/properties/required；数组、可选、复合或引用Schema不能猜测，普通选择器显示不支持并要求重选。标题供显示，不代替稳定路径。结果整体仍由宿主按原固定Schema完整校验。

`BatchDeclaration`拟放在作者入口与公开包入口的可选声明中，并要求独立能力`entry-batches-v1`。声明不存在时保持单次路径；存在但关系不符时拒绝连续模式，不能沿用旧字段或猜测布尔值。正式版本还须同步作者/包完整性校验、普通字段选择/删除引用保护和原始ZIP独立复导；当前没有向任何现行格式添加字段。

`reference.mjs`只检查有限声明/Schema关系并从已完成完整Schema校验的JSON原值提取决策，不验证Run身份、完成事实、收尾、授权、秘密过滤或未来运行资格。不能把它的返回当作启动许可，不能把脱敏投影、旧末步、任意模型文本或未校验值交入此路径。进度和说明可能含私有内容，宿主最终秘密集合处理前不得对外显示或写普通日志。

每批完整结果只能给出继续、完成、需要查看三种意图。单次模式下`continue`不自动开始下一Run；连续模式也必须经过原生会话的结果/来源/进度/收尾与授权复核。进度不变、没有结果、运行失败/未知或本地限制到达时停止，不变成`complete`。BOSS真实站点终点仍由模板规则和网站证据决定。

`BatchLimits`草案采用明确有限设置：1–1000批、1分钟–24小时总时长、1秒–5分钟批间等待。没有Schema默认值，开始前必须准确预览并明确提交；先行Figma的50批/8小时/5秒仅是界面示意。生产计时必须结合本进程单调时钟及停止/代次复核，不能因墙钟回拨延长运行，退出/休眠/重开不自动续跑。
