# 契约 0.22.0：可视化模板作者

2026-10-15。在0.21.0上增加独立作者定义、修订草稿、编排副本、公开提示词映射和本机导出回执。`p1.schema.json`、`template-authoring.ts`及包校验为规范源，`SHA256SUMS`覆盖机器文件。包格式仍2.0、SDK仍1.0，Node/Value及执行语义不变；访谈、求职事实和站点规程仍属于模板。发布以真实`contracts-v0.22.0`为准，定义及画稿不代表客户端已实现。

## 作者草稿与范围

`TemplateAuthorDefinition`只包含公开定义：包身份/名称/版本/作者/来源/最低客户端、共享配置与状态Schema、最多50个入口、100份提示词、100项逻辑资源/动作、README、附加公开资产和依赖声明。入口固定完整FlowDefinition、输入/结果Schema、是否定时、额外能力、资源/动作身份与提示词绑定。入口中可以复用现有条件、循环、资料/AI/会话/Skill等节点，不引入业务节点或大脚本替代制作工具。

允许先保存零入口草稿；导出必须至少一个入口。新草稿生成新的本地公开包身份，源包复制也默认新身份和1.0.0，不把已安装包版本变成可变内容。作者若明确填写身份/版本，必须遵守同标识同版本内容一致；之前导出或本机已安装的同标识同版本不同摘要阻止导出，提示修改版本或身份，不自动升版。作者/来源是声明，不冒充签名认证。

定义不含实例、目录绑定、Key、Profile、动作授权、实际参数/配置值、业务状态、历史、个人资料或Skill确认记录。入口parameters只允许中性结构：空文本、0、false、null及其对象/数组；sourceTemplate不继承。导入来源参数只用于建立字段结构，用户值不进入作者定义；公开默认值由作者在Schema中显式维护，需核对后才分发。普通字面量/代码/README/提示词/资产仍可能含手工输入的敏感内容，必须有可读文件预览与最终公开核对，不能把“移除绑定”当作自动脱敏保证。Skill固定个人内容等既有导出阻断继续有效。

完整定义限制2MiB UTF-8 JSON、深度40及50000个JSON值/成员；每入口1000节点、深度16，全部入口合计1000条提示词绑定。提示词/README各60000字符，文本必须可严格UTF-8往返；不采用截断内容。附加公开文件保存在assets列表，可位于包允许的assets/prompts/scripts/schemas/flows目录，最多100项、每项编码文本最多1Mi字符；base64须为规范编码。复制来源时保留未由入口/作者工具管理的公开文件，静态scripts文件仍须.js并完整列入清单；与生成文件同路径时明确拒绝，不覆盖来源文件。拒绝路径越界、冲突、可执行二进制、node_modules和保留作者映射文件。包仍执行20MiB归档、100MiB展开及既有文件/声明预算；编译结果超限明确失败。

配置和入口输入继续采用受限可渲染Schema，支持对象/数组/标量/选项/约束；结果和状态Schema可使用现有本地JSON Schema，不允许远程引用或自定义$id。可视化字段编辑为主路径；高级Schema模式不能成为完成常见字段的必经路径。结构/引用有误时保留当前输入并定位字段，不生成半可用包。

`TemplateAuthorDraft`在本机加密存储，id只标识私有草稿；revision正整数单调递增。保存用预期revision的CAS，冲突返回可读原因及重新对照入口，不覆盖较新草稿。编辑失败、关闭或导航有三选离开保护和焦点恢复；读取最新版本时保留未保存输入供明确合并。保存、复制、预览及导出不调用模型、不执行流程、不安装包、不改变现有实例/计划/Run。使用者的运行仍按自己的资源/权限独立检查。

## 入口编排副本

`TemplateAuthorCheckout`记录草稿/入口、创建时修订、独立流程身份及基线摘要。作者明确打开副本，复用现有客户端编排器；仅复制定义，不继承绑定、参数值或授权。副本作为普通本机流程，可由作者配置自己的资源、显式预检和调试；调试输出不是公开定义，不能隐式带回。

副本保存不自动改写制作草稿。带回前宿主生成固定预览，绑定当前作者revision、入口、完整副本定义/摘要及预期采用内容；用户核对后使用稳定操作身份明确采用。实际带回时再次核对草稿和副本；任一变化使旧预览失效，不能误用新来源或覆盖别人修改。相同操作重复回到原采用结果，不能多次推进修订。节点/输入类型变化可建议新的字段结构，不能静默丢弃作者已编辑的公开Schema。

绑定提示词的副本展示完整公共正文。若副本正文与原公共提示词不一致，或目标节点被删/换类型，带回阻断并列出具体目标；作者选择修改公共提示词，或明确解除相关绑定后采用副本的手工内容。不用自动重绑/清空/覆盖解决冲突。副本中从未绑定的独立字面量保持独立，未保存编辑保留。

## 公开提示词及可移植映射

`TemplateAuthorPrompt`独立维护id、公开名称和正文。`TemplateAuthorPromptBinding`只能指向同入口唯一AI或conversation节点的instructions；目标存在、类型和promptId需核对。作者定义中绑定字段固定为`@author:prompt/<promptId>`，不能同时保留另一份候选正文；该标记只是作者内部编辑约定，不能直接作为运行规程。未绑定标记无效。

导出时将绑定目标替换为公开提示词完整正文，产生正常现有FlowDefinition；同时保存`prompts/<id>.md`和`assets/template-author.json`。`TemplateAuthorPackageMetadata`只含版本1、公开提示词id/名称/路径及入口/节点/字段绑定，不含本机草稿身份、操作、路径、实例值或确认记录。提示词资产与生成的步骤正文均进入包清单和摘要；同一公开提示词只在制作源中编辑，所有绑定入口一起编译。

`validateAuthorMetadata`对存在的映射严格检查：资源和入口/节点确实存在，路径与键匹配且不重复，目标只限instructions，严格UTF-8原文逐字等于生成步骤正文。损坏/未知版本/缺文件/不一致都使包校验失败，不静默去掉映射后当成功。没有映射的普通包继续按原格式验证，复制制作时保留步骤的独立字面量，不猜测哪个文件是提示词来源。该映射只帮助编辑，运行依赖已经编入步骤的正文，不改变SDK或供应商接口。

从已安装包复制制作必须选择准确身份/版本/摘要，先校验完整包；有映射时验证后恢复提示词绑定，普通包保留独立正文，其他已声明资产和依赖保留或因预算明确拒绝，不静默丢文件。复制不读取使用实例。通过普通流程编辑器单独叉出入口再导出时，必须去掉旧作者映射，避免它与已修改步骤不一致；原公开提示词文件作为普通资产可保留，不冒称仍绑定。原模板直接导出不改定义与身份。作者工作区自身编译则重新生成全部准确映射。

## 编译、资源与最终核对

作者显式选择每入口额外资源、动作和能力，编译器结合节点推导最低要求并取并集；目录读写提升须在预览显示，同名不同类型拒绝，不静默更换逻辑身份。不能通过删除手动声明来取消节点实际需要的资源/能力/写入动作。脚本与动态行为须作者补充声明，不能声称自动分析任意代码；静态脚本依赖沿用现有开发打包限制，不自动安装。

动作声明默认deny。可视化资源声明不含具体路径/Provider配置/Key/Skill版本绑定，作者也不能在制作页授予使用者权限。导出逐项列出入口、Schema、提示词、脚本、公共资产、推导要求、版本及准确包摘要。先保存有效草稿，宿主生成5分钟有效预览并固定完整字节/归档摘要；任何作者修订变化使旧预览失效。核对不是新的执行授权。

最终导出必须来自本机UI明确操作，绑定短期预览和稳定requestId；Worker、脚本或模型不能直接调用作者导出。Main只负责可信文件选择与转发，Renderer不得传任意目标路径或接收完整ZIP/受保护凭据。用户选择位置后，宿主在写前再次核对准确草稿、预览和目标目录身份；只能独占新建所选ZIP，已有文件/链接/目录拒绝，不能静默覆盖或采用路径后来替换的对象。写完同步并回读准确字节/摘要后，记录成功回执。目录保护不宣称是同用户恶意竞争进程的安全沙箱。

## 导出回执和恢复

`TemplateAuthorExportReceipt`记录固定作者修订、公开包身份/摘要、预期归档摘要/大小、稳定操作身份及choosing/writing/written/cancelled/failed/unknown状态。本机目标路径仅在回执存储/UI使用，不能进入公开作者映射或ZIP。文件与本机登记不是单次原子事务。

在选择位置之前持久化choosing，重复同一请求只接续/返回原操作，不弹多个保存窗口。用户取消得到cancelled且无写出；进程重开时无写入目标的choosing转cancelled，不自动重开对话框。选定可信路径后，先持久化writing和准确路径/目录身份，再独占写入。写入后回执丢失、宿主中断或超时转unknown；关闭页面不构成磁盘写入已取消。重开只恢复展示，不自动重写、改路径或换请求身份。

“核对原导出结果”只读核对该操作准确目标、文件身份、预期大小/归档摘要与固定包内容。完整一致时补登记同一written回执；缺失或不完整明确failed并保留现场，不自动补写、删除或覆盖。文件齐全但较新草稿存在仍可登记当时固定导出，不改写当前草稿；回执清楚显示旧修订。再次导出使用新操作、新核对和新文件；同身份同版本的成功/结果未知内容身份不得被不同内容占用。撤销未开始请求必须有串行屏障/撤销记录，不能让迟到请求随后写出。

本机导出回执成功只代表已选择的ZIP经读回一致；后续导入格式校验、安装、新实例、另工作区绑定和实际运行各有独立验收。不得因编译/回执成功宣称完整蒸馏、真实Key或BOSS业务通过。

## 采用、兼容与验证

新增12个语言无关定义，30个正反格式资料、5个作者示例与规范校验模块。Schema形状、引用一致性和包摘要资料只证明相应格式规则，不是CAS/磁盘恢复/UI或业务验收。现有包2.0/SDK1.0及执行节点不变，新增可选的保留作者映射文件；支持本契约的客户端须严格核对存在的映射。不得修改既有快照或为旧开发版做迁移/明文降级。

治理PR合并并发布真实tag后，客户端固定复制机器文件并记录采用提交，新增作者工具、字段树、提示词/资源编辑、编排副本与CAS、编译/预览/导出及原生异常核对。可复用现有加密documents/事务，不要求新增SQLite表；实现证据另记于[模板制作工作区](../../docs/client/template-author-workspace.md)。随后在客户端可视化制作并导出个人蒸馏及BOSS模板，独立模板仓库接收公共资产；本契约不内置业务Schema/提示词，也不改变原186板与Agent完整流程目标。

当前UI/UE阶段不新增或运行单元测试，使用格式/引用核对、类型/构建、真实文件/Runtime和原生界面人工取证；未执行项如实保留。
