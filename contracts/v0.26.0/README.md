# P1 契约 0.26.0：模板提醒的宿主来源

2026-10-16，接续0.25.0。实际BOSS预检已登记提醒，却无法从详情直达产生提醒的Run；现有界面只从模板detail.runId/runIds找关联，不能把模板自报内容当作宿主来源。本批先定义语言无关的持久记录和来源，待客户端采用后再验收真实跳转；无BOSS字段或业务判断。

## 记录与信任边界

TemplateAttentionOrigin为严格对象：version固定1，runId、instanceId、entryId均为1–100字符的`[a-zA-Z0-9_-]`标识；不允许额外字段。新建template类提醒由宿主从当前已核验Run及固定模板引用产生origin，模板请求、输入、详情或模型不能指定/覆盖。节点实例未纳入本版，不根据用户文本补猜步骤来源。

TemplateAttentionRecord保留id/kind=template/title/detail/dedupeKey/read/time及可选origin。origin可选仅表示既有记录未保存来源；新建记录必须带有效宿主来源。字段错误的origin不能被当成合法“缺失”。detail仍为任意JSON，显式null、数组、字符串、数字、布尔和对象均原样保留；省略时使用空对象。业务详情与origin分开，detail中的runId/runIds/origin等同名内容仍是模板数据，不能变成来源链接，也不因展示关联而被隐藏。

SDK仍为`attention({key,title,detail?})`，方法/请求形状、包2.0、SDK1.0、入口能力attention及去重键不变。不需要新节点或模板升级。来源字段是本机宿主持久记录的扩展，不向可移植流程或模板包夹带具体Run、实例或本机绑定。

## 去重与生命周期

同实例内同key重复登记返回首次记录，不创建新提醒，不改变首次origin、time、标题、详情或已读状态。另一Run重用该key也不把来源改成当前Run；另一个实例拥有独立去重范围。已存在且没有origin的提醒保持原状，不以新调用猜测其原Run。并发写入仍由既有本机宿主管理，提交边界与存储故障按既有Store规则处理。

宿主在RPC前后核对脚本owner和取消状态；取消后未登记则不得新增，已持久化的提醒保留，外层取消/崩溃不把它当作外部动作失败或自动重放理由。查看、返回、标为已读和恢复展示均不创建Run、不调用模型、不授予外发权限。通知失败仍保留应用内记录。

## 展示与缺失

template类提醒只将通过本契约验证的origin.runId用作来源/关联运行；不采用detail.runId/runIds作为补链。有效来源显示宿主保存的Run身份，打开现有运行详情，再按原导航返回该提醒；缺少或损坏来源则说明无法关联，仍可阅读原始详情并人工核对运行记录。原Run不在当前摘要时显式读取详情；Run缺失时显示原身份和失败，不换成其他Run或创建新运行。

非template类提醒既有human/unknown/contact等来源语义不由本批改写。原业务内容不能因存在来源就被误判为人工输入请求或动作授权。完整本机运行/提醒内容仍由既有受保护存储和脱敏规则管理，来源身份不表示模板或原始内容已签名认证。

## 发布、采用与验证

当前为G1，客户端仍采用0.25.0，真实tag发布后固定采用本批机器资料。SQLite表和user_version不变，新增记录增加字段；不迁移、不回填、不删除既有记录，也不开发旧客户端升级/降级兼容路径。历史契约快照及已导出的公开模板保持。

结构正反例见[规范数据](template-attention.cases.json)，宿主来源判定见[无IO模块](template-attention.ts)，记录示例见[JSON](example.template-attention.json)。这些只验证数据格式，不证明宿主身份、去重、取消或导航通过。消费者须人工核对真实SDK/Store的首条/同键跨Run/跨实例、原始类型与伪造字段、取消/失败、持久重开及来源缺失，并从客户端可视化模板实际运行取得新提醒和往返证据；不能通过伪造数据库记录声称原生来源正确。
