# 0.21.0 · 本机 Skill 草稿与确认版本

2026-10-15。新增通用skill v1节点、skill-v1能力、确认版本/清单/来源/草稿格式和只读skill逻辑资源。流程1.0、包2.0和SDK1.0不变；旧端遇到未知节点、能力或资源必须在执行前拒绝，不能声称兼容。此前快照保持不可变。实际发布以真实tag为准，客户端/模板随后分别采用；本规范不等于已实现或已完成个人蒸馏。

## 节点、资源与输出

skill v1含id、operation=propose|read、binding固定逻辑资源名，可选name/timeoutMs沿用节点语义。

- propose使用用户明确绑定的readwrite目录。key、title、markdown、data、evidence、base均为Value，必须明确给出；base为null或准确SkillVersionRef。解析引用后，key须符合安全键格式；其余内容满足SkillDraft及预算。节点只保存加密待确认草稿和待办，随即返回SkillProposeOutput，不写工作区文件、不调用模型，不占槽等用户。pending时ref=null，只有本机确认成功时confirmed携带ref；失败/冲突/unknown的草稿仍只能作为pending查看。
- read使用独立kind=skill、access=read的本机资源，不能用任意目录/文件伪装。绑定固定工作区与SkillVersionRef；不支持latest或隐式跟随当前版本。只读取本机已核对登记且文件完整的确认版本，输出SkillVersion；草稿、半成品和仅自称“已确认”的外部文件均不可采用。

普通流程在资源配置中明确选择目录或确认Skill；模板当前入口同时声明skill、skill-v1及实际使用的逻辑资源。propose目录须readwrite，read资源只允许read。模板不获取额外文件、Key或浏览器权限。确认Skill、允许本次模型输入和允许外发分别管理；读出内容不自动调用或发送给模型。Skill内容及来源按资料处理，不能改变宿主授权、读取Key、自动执行指令或安装依赖。

## 文件与摘要

确认版本保存于所选目录下固定布局：`flowark-skills/<key>/<versionId>/SKILL.md`、`data.json`、`manifest.json`。key为1–64字符小写字母起始的字母/数字/连字符；versionId由宿主随机生成，为sv_加32位小写十六进制。不得由模型提供目录、版本标识或任意输出文件名。

- SKILL.md为用户核对的markdown精确UTF-8字节，不自动改写换行或正文。模板负责具体Skill规程、frontmatter、个人事实和表达；通用宿主不定义求职字段，不宣称任意正文满足特定Agent的可执行Skill格式，也不执行其中的代码。
- data.json按本规范canonical序列化`{data,evidence}`，data根类型为对象。结构化个人事实/偏好等业务字段由模板声明，不进入公共协议。evidence最多100项，含document来源与选定单元、conversation身份/修订/连续游标/正文摘要，或manual说明。来源只提供追溯声明，不单独证明事实正确、资料完整或用户已经确认。
- manifest.json满足SkillManifest，含本次operationId、key/versionId、title、parent、confirmedAt和准确两份文件的字节数/SHA256；不含Key、本机绝对路径或其他文件。parent为null或同key的先前确认引用。
- SkillVersionRef含key、versionId和sha256；sha256为canonical(manifest)的UTF-8 SHA256。canonical沿用本版本package-format.ts：对象键按ECMAScript默认字符串排序递归排列、数组保持顺序，然后JSON.stringify，无额外空白或换行。manifest不包含自己的摘要，避免循环。读取同时验证清单摘要和两文件原始字节摘要，不能只信文件名或状态字段。

markdown最多60000个JS UTF-16码元且非空白；data/evidence/清单和整个草稿或返回值序列化合计不超过1MiB，JSON最大深度32、最多10000个值/对象成员。每份读取有界1MiB，版本只读取固定三文件，不扫描相邻简历或仓库。额外文件不自动加载，固定路径中有链接、非普通文件、权限错误、越界、身份/大小/mtime/ctime变化或预算超限均失败，不采用截断数据。

用户明确选择的工作区是普通可读文件目录，应用内草稿/运行历史仍加密。绑定、真实目录身份及本机索引仅留本机。新工作区的外部内容须用户明确核对并登记；不能因为manifest带确认时间就自动获得本机确认状态。移动后重新选择目录并核对原引用，不静默搜索其他位置或改用新版本。

## 草稿、编辑与确认

SkillProposalSnapshot定义UI/宿主共同理解的草稿和状态，revision单调递增。来源身份固定到流程/节点、目录与key；sourceFingerprint由原始解析输入的canonical摘要确定。相同来源和输入的重复运行读取同一草稿/确认结果，不重写用户编辑；不同输入创建独立草稿，不能替换仍待处理的草稿。数据/正文的后续用户编辑不回写原始输入指纹。模型再次整理必须显式采用当前草稿或版本的选定内容，不自动清除手工修改。

编辑采用预期revision的CAS；保存失败/冲突保留当前输入，离开保护提供保存成功后离开、继续编辑、放弃未保存编辑。已确认草稿不可原地编辑；基于确认版本产生新草稿，保留旧内容、父引用和来源。比较时可读到完整旧版及草稿；差异摘要不替代正文/数据核对。确认基线为该工作区/key的当前已登记版本，首次为null；若别处已确认新版本或基线文件变化，转conflict并保留草稿，须显式重新核对与合并。

最终确认必须来自本机UI的明确人工操作；流程、脚本、模型、普通Run确认和conversation.confirm均不能直接发布Skill。宿主生成短期核对凭据，绑定草稿revision、内容摘要、工作区身份与基线；任何相关修改使旧凭据失效。确认请求使用稳定requestId，重复同一请求仅返回原操作，不分配第二个版本；同一requestId不能改内容或目标。

状态为draft、publishing、confirmed、conflict、failed、unknown、discarded。publishing/unknown/confirmed必须记录publication的requestId/versionId/draftSha256；confirmed额外记录准确confirmed引用，其他状态不携带可采用confirmed引用。failed/conflict/unknown记录可读错误，不把路径或秘密拼入错误。放弃草稿不删除原版本。

## 写入、未知结果与恢复

确认前先持久化本次操作、完整草稿/目标/基线，再按工作区/key串行处理。每个操作分配全新版本目录，独占创建目录与文件，不覆盖任何现有文件。先完整写出并同步SKILL.md/data.json，再以完整manifest作为最后的完成标记；不能把未写完的manifest暴露成完成标记。核对原始字节、清单、目录身份和基线仍一致后，才原子登记本机确认版本及新的head、更新草稿状态。

整个版本跨文件与本机数据库不声称单次原子事务；磁盘写入成功而本机登记未完成、异常退出、确认超时或回执丢失均保留操作身份并显示unknown。unknown不自动重试、改用新目录、删除文件或重放外部动作。重开后只恢复展示和标记待核对，不自行再次写出或采纳半成品。

“核对保存结果”显式检查原操作的准确目录、完整文件、摘要、草稿与基线；全部一致且无较新确认冲突时可补登记同一版本，不写第二份。只发现部分文件时保留草稿和现场，提示未确认；普通失败后的再次确认需新的操作身份及新目录。正在发布时关闭页面不意味着磁盘写入已经取消；后台状态与待核对入口可恢复。文件清理是独立显式维护动作，首版不提供删除确认版本的入口，不能据此宣称已经验证引用计数删除功能。

工作区所有祖先/目标须按既有目录边界检查、拒绝链接，并在关键步骤复验身份，异常结果不登记。不能把这些检查称为对同用户其他进程持续替换目录的安全沙箱保证；实现须对所承诺的实际边界人工取证。

## 固定引用与生命周期

流程本机绑定保存工作区及准确确认引用；新确认版本不修改既有绑定、计划或活动Run。运行准入核对当前入口的确认记录和实际文件，将已确认内容及摘要复制进加密不可变Run快照；读取步骤再次复验所选版本仍可用，返回该快照，不改用磁盘上的新内容。该步骤之后文件或规则变化的外发复验仍由独立提交机制处理，本契约不声称已消除跨端竞争发送。

文件缺失、外部修改、未登记或摘要不匹配时阻止受影响的新读取，保留既有历史快照。外部修改只可经明确读取/对照成为新草稿，再确认新版本，不覆盖或重新标记原版本。基于旧Run重跑仍须当前资源核对，不能通过快照绕过失效保护。首版不提供直接删除确认版本；将来增加删除须另定义绑定/计划/活动快照引用保护与真实验收。

## 公开分发与采用

公开ZIP只带流程、逻辑skill资源、公开规程及声明依赖；不能携带个人版本、正文/结构化数据/来源、确认记录、草稿、历史、目录绑定、Key或本机路径。read节点只有逻辑binding。propose正文/data/evidence/base使用参数或前序引用；导出保留准确引用，固定非中性个人内容须阻止导出并定位字段，不能悄悄夹带或生成不可用半包。key/title仍需作者在导出预览核对公开性。参数中性化遵循既有规则，使用者重新填写材料和选择本机确认版本；导入不自动确认、运行或授予动作权限。

新增SkillManifest/VersionRef/Version/Draft/Evidence/ProposalSnapshot/ProposeOutput及节点/资源枚举，见p1.schema.json。正反格式资料与示例仅核对结构，不能替代摘要计算、人工确认、CAS、文件身份、恢复、版本引用或可视化公开复用验证。无SQLite表结构变更需求：客户端可复用加密documents存储各记录与事务；实际实现、持久化和跨重启证据仍须单列。不开发旧端兼容、隐式清库或升降级迁移。

治理PR合并并发布contracts-v0.21.0后，客户端固定采用快照、更新类型与静态校验，独立实现通用节点/资源/宿主/人工UI；随后模板采用。完整设计和验收范围见[Skill工作区记录](../../docs/client/skill-workspace.md)。当前UI/UE阶段不新增/运行单元测试，保留类型/构建/格式及真实文件/并发/异常/原生人工核对，不能用绿色格式资料宣布个人蒸馏或BOSS闭环完成。
