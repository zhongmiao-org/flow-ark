# 契约 0.16.0

2026-10-08，增加模板人工核对展示结构 `TemplateHumanReview` v1 与能力 `human-review-v1`，对应 Figma 人工确认与输入画板的「目标」和拟执行内容。流程格式1.0、SDK1.0、模板包2.0及已有节点语义不变。开发快照标识 `contracts-v0.16.0`；实际发布以远程不可变 tag 为准，尚未发布产品，契约不代表客户端或模板已实现验收。

## 数据与能力

`review` 是 JSON 对象，必填 `version:1`、`target`、`content`，不接收额外属性。`target` 为1–4096个字符且至少含一个非空白字符，表示模板明确提供的可读操作对象。`content` 为0–100000个字符的完整拟执行文本，允许空字符串表示空内容。均为普通文本，不解释 HTML、Markdown、URL 或文件路径，不执行或打开。超过限制或格式无效应拒绝请求，不静默截断确认内容。

SDK `human({title, description?, schema?, review?})` 可携带此结构；`effect.prepare({action,key,description?,review?})` 在原授权为 confirm 时将同一结构交给人工请求。使用 review 的入口必须声明 `human-review-v1`，直接 human 调用仍需 human 能力，effect.prepare 仍需 effect 能力。能力检查发生在请求处理前，不认识该能力的客户端应按既有入口准入机制阻止执行，不能丢掉 review 后继续。未提供 review 的普通人工输入请求仍使用说明文本，不从说明中猜测结构；这不是旧客户端兼容层。

## 所有权与边界

模板从当前运行已选定的对象和本次实际参数构建展示内容，宿主在创建待办时校验并固定保存，Renderer 按字段展示。「目标」是模板提供的核对文本，不是新的资源绑定、可信定位证明或授权。模板必须在实际操作前复验目标与参数；用户回应只解决本次请求，不扩大实例默认权限。auto 授权不因附带 review 变成人工确认，deny、去重、unknown 不重放与取消规则不变。

不在 review 中放凭据、Token 或登录态，不从客户端自动补入本机路径/文件内容。待办沿用本机受保护存储及既有脱敏边界，不新增数据库表或修改已保存的 Run/计划。旧记录缺少 review 就按实际保存内容显示，不推测或回填。

## 采用顺序

治理 PR 合并并发布不可变开发快照后，客户端固定复制 Schema、摘要与生成类型，增加能力声明、宿主校验和界面展示；模板仓库仅在明确采用后才能使用该能力，本次不代表任一业务模板已更新。示例见 [example.human-review.json](example.human-review.json)，SDK说明见 [模板 SDK](../../docs/templates/sdk.md)。单元测试按当前186画板 UI优先约定后置；契约格式与摘要检查、类型构建和人工界面证据分别记录。
