# P1契约0.33.0：完整会话来源的不可变清单与分页

2026-10-17，接续0.32.0。按[完整来源与五状态Figma](../../docs/client/conversation-full-source.md)，定义独立于聊天窗口和所选checkpoint的完整来源：原已确认普通会话只保留一次，随后每一个实际终态请求按序纳入，包括失败/取消的本人输入和助手片段、实际重试、资料上下文、来源摘要及未知用量。总历史不设12/24或固定题数上限；清单和每个读取对象有资源预算。本批是G1来源核心，真实发布tag、消费者和业务分别取证。

流程1.0、包2.0、SDK1.0、已有节点/SkillEvidence及SQLite表不变。本版新增六个数据定义和`conversation-archive-v1`能力名，不新增招聘节点，也未定义可直接运行的整理节点、流程来源资源绑定或AI覆盖回执。这些消费者/编排边界仍须接续定义与实现。尚不支持能力的客户端必须拒绝未知必需能力，不能仅增加支持枚举便标为已实现。

**完整来源可读不等于模型已整理，更不等于事实确认或外发授权。** 本版引用不得冒充SkillEvidence或旧conversation-checkpoint；尚未补齐实际处理覆盖时，不能据来源清单创建“完整蒸馏已完成”的声明。用户没有更多补充即可进入待核对草稿整理，未知项不强迫补访谈；真正处理全部来源、草稿编辑和最终确认保存仍按主线继续。

## 捕获范围与本机归属

ConversationArchiveCapture固定sessionId/title、捕获时head修订、资料contextRevision及准确context引用、原普通会话Evidence（或null）、v2终态historyCount/historyHash。范围来自宿主的真实受保护head/原确认记录；不接受Renderer或脚本提供的“完整对话正文”。捕获要求没有活动请求、未发送输入或待核对资料提议；最后一次请求可以失败/取消，仍保留本人信息，不能把它排除后称完整。

原会话仅接受真实已确认普通v1来源；内部试聊不自动成为事实来源。v1原有50次/100消息等有限格式原样保留，本版不迁移、扩写或重新生成它的消息身份。完整来源中以一个origin记录保留整个原快照（包括上下文、请求、原始完整/部分消息和未知用量），而不是只取过滤后的transcript。用户消息可缺少旧可选requestId，通过唯一turnId对应；助手以requestId/turnId核对。无唯一对应、孤立消息或原来源摘要变化时停止，不能靠文本相似度猜测/去重。

随后纳入history ordinal=1到固定historyCount的所有真实不可变条目，不使用默认聊天选择或checkpoint的transcript拼接。origin请求与v2请求分别计数，失败和重试也是独立真实请求；同一用户轮次在显式重试中可复用用户消息身份，但不得把两次模型请求合为一次费用或覆盖记录。旧所选checkpoint、原会话及其Run保持不变。

本机scope、资料访问与选择权限仍归宿主。相同key、标题或摘要不授权跨实例读取；另一个流程/实例采用来源必须由本人通过UI明确选择固定引用，且具备自身所需AI/资源能力。模型不能枚举所有会话、选择私人来源或扩大读取授权。本版不把本机来源写入公开ZIP；作者不得烘焙私人正文、固定用户ID、路径或Key来补齐模板。

## 清单、记录与上下文

ConversationArchiveManifest只保存固定capture、创建时间、原请求/v2请求/资料上下文/实际记录计数、complete/failed/cancelled计数、根/尾摘要及自身摘要，不携带全部记录数组。requestCount=originRequestCount+historyCount，终态计数之和=requestCount；recordCount=origin记录数（0或1）+contextCount+historyCount。计数用安全整数，预留后继游标所需空间，耗尽时停止而非回绕。至少有一个实际请求和当前资料上下文。

记录全局ordinal从1连续增长，类型只有origin/context/history。存在origin时必须位于第1条；接着保存当前context的完整ConversationContext，再按原始history顺序读取请求。每个历史条目引用的其他context在首次使用前紧邻保存一次，后续只按原ID/摘要引用；不混入未采用的资料。当前context即使还未用于历史请求也保留，用于明确当前资料与过去实际输入的区别。资料或历史原始记录缺失/摘要不同不能继续发布清单。

rootHash=canonical(`{version:1,archiveId,capture}`)的UTF-8 SHA-256。每个记录保留archiveId/ordinal/previousHash/payload，sha256覆盖除自身sha256外全部字段；第1条previousHash为rootHash。context与history正文继续验证原0.32.0的自身摘要，origin继续验证真实普通来源Evidence；不能重算外层摘要掩盖原记录变化。清单sha256覆盖除自身sha256外全部字段。原生JSON身份、角色、顺序和null用量不改写；助手部分正文明确保持部分状态。

ConversationArchiveScan是顺序参考验证器。生产宿主为每个archive提供独立持久上下文引用/请求去重索引；只保留计数、摘要和最近一个原历史条目，不在head或内存集合中收集所有正文。索引写入与对应记录/进度同事务。append失败应回滚该步并丢弃当次验证器，不继续使用部分修改的验证状态。原请求唯一性、重试关联、当前context和全部实际请求终点均通过后才能生成/登记最终清单。

## 有界分页与实际读取

ConversationArchiveRef为version/archiveId/sessionId/清单sha256。身份必须与本机已登记清单精确一致。首游标为该引用、nextOrdinal=1、previousHash=rootHash；每页按ordinal升序返回一个非空连续段，最多20条且2MiB。单个context/history/旧快照正文仍最多1MiB；记录封装最多1MiB+4KiB，给已有有效正文的身份和摘要留出空间。最大深度48/值60000，严格UTF-8有限JSON；非法Unicode、不连续数组、保留键、超限或不可表示整数都拒绝，不截断正文来凑预算。页面可因任一预算提前结束，不能静默跳过大记录。

next游标为末条ordinal+1及其真实sha256；到清单固定末条时next=null，并核对tailHash。禁止空页、越界或在末尾另造下一页。page.sha256覆盖除自身sha256外全部字段，绑定实际范围和下一个游标。旧游标不会因为会话追加而移动；它永远属于准确的不可变清单。

宿主收到非首游标，必须按archive/ordinal从自己的固定索引取得真实前序记录核对，不能仅相信调用者提供的hash或page自洽。参考`validateConversationArchiveCursor/Page`的previousRecord须为本机该行，或客户端刚验证的前一页末条。客户端按返回next接续，从首游标验证到真实终点；来源不符、重复、乱序、缺页或断链时保留已读范围并停止。一个格式正确的孤立页、总计数或尾摘要都不能单独证明全量已读取。

## 确认、当前性、取消与恢复

来源操作只在本机读取/固定用户已选会话；准备、分页、确认和重新打开均不调用模型。UI清楚展示原请求/持续请求/未完成记录的范围，以及“固定来源不等于整理完成”。来源准备与确认使用准确的会话/修订/范围摘要、宿主一次核对凭据和持久请求身份；相同身份/相同内容返回原结果，身份复用不同内容拒绝。过期/并发变化保留输入，不能静默改成更新的来源。

完整复制不能占用一个无限IPC响应或构建无限数组。宿主以有界批次复制、逐记录摘要、独立暂存索引和持久进度执行；只在全部原记录/资料与固定终点一致后原子登记清单和幂等回执。中途失败、取消或崩溃保留原资料/已固定来源与可核对进度，没有最终清单就不能返回可供消费的完整来源引用。重开先查原请求/实际登记结果；需要继续本机复制时由用户显式继续，不自动重放任何模型请求或覆盖旧文件。磁盘/存储错误停止新工作，不能报告来源已保存。

会话可以继续追加，旧清单与页仍只读可查。当前性核对比较实际historyCount/hash、origin身份、context引用和contextRevision，且当前没有活动请求、未发送输入或资料提议。仅因保存确认/刷新使head修订增长，不会在内容完全相同时使来源过期；资料修订、消息追加、更正或待处理输入则要求新来源。旧来源不被删除或偷偷补入新内容；引用保护、旧Skill/Run与明确采用规则保持。

后续处理必须固定来源与实际批次范围、用户自己的Provider/model/Key及预算，建立真实模型收据、顺序覆盖与结果关联，保留手工改动/冲突/未知、取消及结果未知恢复。这些处理和可视化编排接口不是本版数据格式已实现的能力。当前G3生成首版Skill仍需消费者和此部分闭环，不以大脚本或一次性私人JSON适配宣布完成。

## 机器资料与采用

- `p1.schema.json`新增六个Archive定义，原定义不变；其余机器资料从0.32.0完整继承。
- `conversation-archive.ts`为摘要、顺序、请求来源/重试、分页、当前性参考规则；宿主仍负责真实归属、授权、事务、持久索引和并发。
- `example.conversation-archive.json`为虚构原14次+持续8次的22次来源；`example.conversation-archive-long.json`为40次两页来源，均无真实个人内容。
- `conversation-archive.cases.json`与`conversation-archive.semantic.json`为格式正反例及关联语义资料，包含131次、不完整输入、乱序/缺页/重复、原来源/上下文/摘要变化及非法Unicode。验证资料不等于客户端运行或真实业务通过；按当前阶段不新增、不运行应用单元测试。
- 发布后消费者固定真实tag/治理SHA/完整机器资料摘要，独立生成类型；不运行时读取父目录、不改已发布0.32.0快照。实际安装、UI全程制作/公开复导、本人Key整理和Skill保存分别取证。
