# P1 契约 0.3.0：工作簿模板与文件归档

发布标识 `contracts-v0.3.0`。继承 [0.2.0](../v0.2.0/README.md) 的实例配置和 [0.1.0](../v0.1.0/README.md) 的执行语义。流程格式仍为 1.0，既有节点 v1 含义不变。

新增两个显式 v2 节点，旧客户端因未知节点版本拒绝，不按 v1 猜测执行：

- `excel`, `version=2`, `operation=fill`：`binding` 为本地目录绑定；`templateName` 为模板 xlsx 的相对名称；`name` 为另存的 xlsx 相对名称；`sheet` 为精确工作表名称（空字符串表示第一张）；`cells` 为 A1 地址到 JSON 单元格值的映射。name/templateName/cells 可使用通用引用。模板和输出必须不同，禁止覆盖原模板；保留工作簿其他单元格、样式和工作表，不承诺宏或高级公式计算。支持空值、字符串、有限数字、布尔值，以及 `{formula, result?}` 公式值。单次最多 10000 个目标单元格，Excel 行列边界内，模板文件最多 50 MiB。
- `file`, `version=2`, `operation=archive`：`binding` 为本地目录绑定；`name` 为输出 zip 名称；`files` 为输入相对文件名称数组，可通过通用引用获得。只归档明确选择的普通文件，不递归扫描目录、不包含输出自身、不允许重复条目或 `..`/绝对路径；符号链接解析后仍必须位于绑定目录。最多 200 项、输入合计 100 MiB。

写入在同目录临时文件完整生成后原子替换输出；失败清理临时文件，不将半成品登记为成功产物。输出返回 ArtifactRef，由宿主登记。产物后来被用户移动或删除时保留历史索引并提示不可用，不把历史 Run 改写成新的执行失败。

生成：`python3 contracts/build_contracts.py --version 0.3.0`。历史 0.1.0/0.2.0 仍可原样再现；本次无 SQLite 表结构变化。旧流程继续使用 v1，用户显式选择新操作才生成 v2，不自动改写旧快照或计划。
